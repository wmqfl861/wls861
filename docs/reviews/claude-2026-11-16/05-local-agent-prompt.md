# 05 给本地 agent 的提示词

用法：owner 把下面整段原样发给本地 agent。发出即表示 owner 确认其中的授权。要改某一项，直接在“一、授权”里改掉那一行再发。

---

```text
你是 wls861 项目的本地开发 agent。本次任务：按 2026-11-16 的审核文档恢复真实运行、完成 G2 出口，
同时修沙箱的启动参数；之后按新的总计划一个阶段接一个阶段做到项目结束。

2. 恢复真实调用。11-13 计划里“出现文件效果 UNKNOWN 就停”的规则由 D-32 取代：

   - 可以使用 max 以外的思考等级（D-35）。
   - 额度按 D-34：按调用次数和输入 token 分阶段计，到 v1.0 合计 3,000 次、6,000 万输入 token。

四、规则

沿用不变的：
- 每个 PR 直接基于 main，不堆叠；测试行数不超过产品行数的 2 倍；
  同时在制的 PR 不超过 3 个；PR 开出 48 小时内必须有结论；合并即删分支。
- PR 说明一页以内，四段：改了什么、为什么、怎么验证、没做什么。
- 测试只用 FakeModel、本机合成端点和自建的临时夹具，任何测试都不调用真实模型。真实运行不进 CI。
- 不提交构建产物、数据库文件、私有证据、压缩包或长日志。
- 不为了让测试通过而放宽生产路径的权限、隔离或安全断言。
- 如实报告：没有运行的写“未执行”，未知的写“未知”，失败的运行原样保留。
- 每次任务结束同步交接摘要并推送（owner 11-16 的要求）。

这次变化的：
- 停止之后做什么，按 D-32 的表。只有一种情况停下全部真实调用并问 owner：
  UNKNOWN 涉及数据目录之外的不可逆副作用。
- 单个请求的默认上限：80 次调用、200 万输入 token、8 万输出 token、墙钟 40 分钟；单次调用期限 180 秒。
  有理由时可以调到两倍，理由写进报告；超过两倍先问。
- 降低开销先出数据再选题（D-37）：每一项合并前给出离线重算的前后字节数，
  合并后重跑给出真实 token 的前后对比；没有改善就回退。G2-7 最多 3 个 PR。
- 性能方面的结论以托管 CI 同一作业的耗时为依据，本机的单次测量不作为依据。
  本机 sanitizer 超时不立项，托管 CI 复现才处理（D-11、D-39）。
- 文档写法（D-41）：长期状态只在 STATUS 写一处，PR 说明的“没做什么”只写和这个 PR 有关的边界；
  current-handoff.md 保持 60 行以内，先写现在能做什么、卡在哪、下一步；
  报告第一段先给结论。
- 不再继续拆 Store，除非某次改动的增量构建超过 3 分钟（D-44）。

五、遇到要决定的事

- 审核文档有建议的：照建议做，不用问。
- 没有现成建议的：你自己定。选可撤销的、改动小的、与审核方向一致的做法；
  在 PR 说明里写一行“决定：……；理由：……”；日报里汇总；不停下来等。
- 只有下面几类事停下来问 owner：
  (1) 需要 owner 本人提供的东西：密钥、充值、主机上的 sudo 操作；
  (2) 阶段额度或合计额度触顶（D-34）；
  (3) 第一节第 5 条列出的几件事；
  (4) UNKNOWN 涉及数据目录之外的不可逆副作用；
  (5) 审核目录都没有覆盖的全新产品方向。
  停下来时用 10 行以内写清：要决定什么、有哪几个选项、你建议哪个、不决定的话你先做什么。
  然后继续做不受影响的工作。

- 之后每个阶段出口发一条：报告的链接；出口标准逐条的结果；标签。
- v1.0 验收报告出来后停下来等 owner 回复。
```
