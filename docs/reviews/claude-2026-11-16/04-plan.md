## 2. 工作规则

沿用不变：

- 每个 PR 直接基于 main，不堆叠；`src/`+`include/` 的非移动改动不超过 800 行；测试行数不超过产品行数的 2 倍；在制不超过 3 个；48 小时内有结论；说明一页以内四段。
- 合并权限：PR 自己的必需检查全绿、行数合规、不改数据库版本、不含真实调用，就自行合并。main 完整矩阵失败 24 小时内修复或回退；连续两次同因失败先修。
- 合并即删分支。
- 测试不调用真实模型；真实运行不进 CI。
- 遇到要决定的事按 11-13 `02-decisions.md` §7：有建议的照做，没有的自己定并记录，五类事才问 owner。

本轮新增：

- 停止规则按 D-32。
- 真实调用按 D-34 的额度，日报里报次数和 token。
- 改了 `tests/*.cpp` 的 PR 合并前跑一次 `asan-affected`（D-40）。
- 文档写法按 D-41。
- 每个阶段开始前，用 10 行以内写出这个阶段的 PR 切分和顺序。可以调整本文的切分，理由写明。
- 每个阶段出口：一页报告、STATUS、CHANGELOG、版本号、带注释的标签（D-43）、§1 的状态列。

### R0 导出重放

1. 只读查看原请求目录，记录有没有 `output-intent.json`、`output-root.json`、`output/`、`.wls-run-receipt-*` 和其他临时文件。
2. 把整个原请求目录完整复制到证据目录，对副本生成 SHA-256 清单。
3. `output/` 已存在但没有 `output-root.json`：`output/` 是空目录就 `rmdir`，不是空目录就跳到第 6 步按“不成功”处理。
4. 用当前 main 构建的 `wls`，以原来的命令和原来的配置路径重跑。确认行里应当有 `"completed":true`。先不提供密钥试一次；程序因为缺少密钥在启动时拒绝的话，再带密钥运行。
5. 通过的标准：摘要的 `stop_reason` 是 `completed_replay`；`output_path` 非空；调用数仍是 29；`python3 scripts/check_g2_outputs.py <output_path> three` 退出码为 0。
6. 写进报告。通过：“原请求的导出已由重放完成，UNKNOWN 关闭”。不通过：原样贴出报错，标为“已封存”，原目录和副本保留到 2026-12-16。两种结果都不挡后面的步骤。
