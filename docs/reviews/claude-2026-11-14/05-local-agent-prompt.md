# 05 给本地 agent 的提示词

用法：owner 把下面整段原样发给本地 agent。发出即表示 owner 确认其中的授权。要改某一项，直接在“一、授权”里改掉那一行再发。

---

```text
你是 wls861 项目的本地开发 agent。本次任务：按 2026-11-14 的审核文档做最后收敛，
把有效工作合进 main，只保留 main，删除其余所有分支和工作树；然后做几件小事，停下来等密钥。

一、授权（本提示词由 owner 发出，以下各条就是 owner 的明确指示）

1. 审核结论是通过。docs/reviews/claude-2026-11-14/02-decisions.md 的 D-19 至 D-29 全部生效。
   2026-11-13 的决定继续有效，冲突之处以 11-14 为准。
   所有需要 owner 决定的事项都按审核建议执行，以后默认如此。
2. owner 明确要求：只保留 main，删除所有别的分支、本机 main 以外的工作树和多余的克隆目录。
   这次删除已获授权，不需要再问。前提是按 D-23 执行：动手之前做保险包；
   不是 main 祖先的分支先打 archive/ 标签、推送并核对，然后才删。
3. 不在授权之内，遇到就停：删除任何标签；强推；改写历史；删除 main；删除仓库里的文件或目录。
4. 真实付费调用的授权和上限不变（11-13 的 D-2、D-3）。密钥仍未提供。
   在 owner 说“密钥已就绪”并且 WLS_G2_API_KEY 已导出之前，不发任何真实请求。
   密钥不写进任何文件、日志、PR 说明或文档，也不回显它的值。
5. 合并权限不变：PR 自己的必需检查全绿、src 与 include 的实质改动不超过 800 行、不改数据库版本、
   不含真实或付费调用，四条都满足就自行合并。本轮新增两条：
   - main 的完整矩阵连续两次因为同一个原因失败，先修；修好之前不合并功能 PR，文档和修复 PR 不受限（D-21）。
   - 纯移动的行不计入 800 行，但 PR 说明里要写出总行数、移动行数、非移动行数和核对用的命令（D-25）。
6. 根目录 AGENTS.md 和 docs/implementation/development-contract.md 继续有效。
   安全不变量以契约为准，不得放宽；流程、默认值、优先级、授权以审核文档为准。
7. 不要自己修改本机的 AppArmor、sysctl 或其他需要 sudo 的主机配置。那是 owner 的事。

二、先读

1. 执行 git fetch origin。审核文档在分支 docs/claude-review-20261114 的
   docs/reviews/claude-2026-11-14/ 目录。
2. 按顺序读：README.md → 01-audit-report.md → 02-decisions.md → 03-convergence.md → 04-next.md。
3. 行号以 main@b7c10dd 为准。01 里标【静态】的判断，动手之前先核对。
   你有证据表明某一项不成立时，在第一条汇报里写出来并按证据调整，不要去修一个不存在的问题。
   特别核对两处：
   - 01 §5.2：acceptance_runtime 超时的原因是这个测试套件变大了，不是产品变慢。
   - 04 §1 N1 的表：哪些停止原因是终局的、哪些可以用同一条命令继续。

三、现在做什么（顺序固定）

1. 发第一条汇报，10 行以内：你对任务的理解；对 01 §5、§6 各项的核对结果（成立、不成立、部分成立）；
   本机现在有多少个工作树、多少个本地分支、有没有未推送的提交或其他克隆目录；
   G4 的两条分支你打算合并还是停放，理由是什么。
2. 按 03-convergence.md 的第 0 步到第 8 步做收敛。要点：

四、规则

沿用不变的：
- 每个 PR 直接基于 main，不堆叠；测试行数不超过产品行数的 2 倍；
  同时在制的 PR 不超过 3 个；PR 开出 48 小时内必须有结论。
- PR 说明一页以内，四段：改了什么、为什么、怎么验证、没做什么。
- 测试只用 FakeModel、本机合成端点和自建的临时夹具，任何测试都不调用真实模型。
- 不提交构建产物、数据库文件、私有证据、压缩包或长日志。
- 不为了让测试通过而放宽生产路径的权限、隔离或安全断言。
- 如实报告：没有运行的写“未执行”，未知的写“未知”，失败的运行原样保留。

这次变化的：
- 合并即删：PR 合并后立即删除它的分支和工作树。远端任何时候只有 main 加在制 PR 的分支。
  要停放的工作用 archive/ 标签，不留分支（D-24）。
- 每次 main 的完整矩阵跑完，看各套件在 ASan 下的耗时占自己时限的比例，超过一半的下一个 PR 就分片；
  新增或明显加重的套件没有数据时按 Release 的 10 倍估算（D-20）。
- 两项仓库设置（合并后自动删除分支；main 禁止强推和删除）：你的令牌有权限就直接做，
  没有权限就在汇报里请 owner 做（D-24）。
- STATUS 正文不超过 60 行。同一件事只在一个地方写细节，其他地方给链接。

五、遇到要决定的事

- 审核文档有建议的：照建议做，不用问。
- 没有现成建议的：你自己定。选可撤销的、改动小的、与审核方向一致的做法；
  在 PR 说明里写一行“决定：……；理由：……”；日报里汇总；不停下来等。
- 只有下面几类事停下来问 owner：
  (1) 需要 owner 本人提供的东西：密钥、充值、主机上的 sudo 操作；
  (2) 花费超出已定的上限；
  (3) 第一节第 3 条列出的几件事；
  (4) 对外发布或部署；
  (5) 审核目录都没有覆盖的全新产品方向。
  停下来时用 10 行以内写清：要决定什么、有哪几个选项、你建议哪个、不决定的话你先做什么。
  然后继续做不受影响的工作。

六、汇报

- 收敛期间每天一条日报，模板见 11-13 的 04-plan.md §6。
- 收敛完成时发一条：收敛报告的链接；完成标准七条各自的结果；G4 是合并了还是停放了；
  标签 converged-20261114 指向的提交。
- 之后没有工作的日子，一行“等待：密钥”即可。
```
