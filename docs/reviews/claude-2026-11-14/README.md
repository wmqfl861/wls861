## 结论

1. **通过，可以做最后收敛。** 上一轮清单的“真实模型就绪”部分（G2-P）11 个 PR 全部按验收条件落地，预演门禁的八个剧本在最新 main 的完整矩阵里通过。过程守规矩：每个 PR 直接基于 main、行数在预算内、失败如实保留、真实调用仍是 0。
2. **收敛的前两步是收尾，不需要再审一轮。** 一是 main 的完整矩阵不稳：一个测试套件自己变大了一倍，在 ASan 下贴着时限，#79 之后完成的 13 次运行失败了 10 次。原因是测试体量，不是产品变慢，把套件拆开即可。二是 G4 有两条在途分支不在 main 里，变基后合并，合并不了就打标签停放。
3. **其余分支没有要抢救的东西。** 50 个已经是 main 的祖先，直接删；另外 44 个是历史分支或内容已在 main，一律先打 `archive/` 标签再删。删完远端只剩 main，被删的提交都能从标签找回。
4. **“通过”不等于产品已经验证。** 这个项目到现在没有调用过一次真实模型。收敛之后只做三件小事，然后停下来等密钥，不再往上盖新功能。

## 委托与边界

owner 在 2026-11-14 的指示是：需要 owner 决定的事都按审核建议做，以后默认如此；项目通过审核就做最后收敛，只保留 main，删除所有别的 tree。

- “别的 tree”按 main 以外的分支、本机 main 以外的工作树和多余的克隆目录理解。仓库里的目录和文件一个也不删。
- 删除只在“被删的提交都还能找回来”的前提下执行：先做保险包，不是 main 祖先的分支先打标签。
- 没有替 owner 定的事：删除标签。想连标签也不留，说一声“标签也删”。
