# 05 给本地 agent 的提示词

用法：owner 把下面整段原样发给本地 agent。发出即表示 owner 确认其中的授权。要改某一项，直接在“一、授权”里改掉那一行再发。

四、规则

沿用不变的：
- 每个 PR 直接基于 main，不堆叠；测试行数不超过产品行数的 2 倍；
  同时在制的 PR 不超过 3 个；48 小时内有结论；合并即删分支。
- PR 说明一页以内，四段：改了什么、为什么、怎么验证、没做什么。
- 测试只用 FakeModel、本机合成端点和自建的临时夹具，任何测试都不调用真实模型。真实运行不进 CI。
- 不提交构建产物、数据库文件、私有证据、压缩包或长日志。
- 不为了让测试通过而放宽生产路径的权限、隔离或安全断言。
- 如实报告：没有运行的写“未执行”，未知的写“未知”，失败的运行原样保留。
- 每次任务结束同步交接摘要并推送。

这次变化的：
- 停止规则按 D-52：“两轮即停”只适用于同一个根因，不适用于阶段出口所在的线；
  那条线上连续失败时先退回最近一次跑通的配置完成出口，再回头修新配置。
- 回退规则按 D-51：对比做完且没有改善才回退；没做完是未知，保留合入再测一次。
- 真实请求失败后的默认动作：D-46、D-48 合入之后，同一条命令重跑就能继续；
  先重跑，重跑仍失败再分析根因。每次重跑前做备份。
- 协同能力按 D-55 的边界实现：只经已验收快照的只读挂载和宿主管理的共享笔记板传递信息。

五、遇到要决定的事

- 审核文档有建议的：照建议做，不用问。
- 没有现成建议的：你自己定。选可撤销的、改动小的、与审核方向一致的做法；
  在 PR 说明里写一行“决定：……；理由：……”；日报里汇总；不停下来等。
- 只有下面几类事停下来问 owner：
  (1) 需要 owner 本人提供的东西：密钥、充值、能跑 bwrap 的宿主、主机上的 sudo 操作；
  (2) 阶段额度或合计额度触顶（D-34）；
  (3) 第一节第 6 条列出的几件事；
  (4) UNKNOWN 涉及数据目录之外的不可逆副作用；
  (5) 审核目录都没有覆盖的全新产品方向。
  停下来时用 10 行以内写清：要决定什么、有哪几个选项、你建议哪个、不决定的话你先做什么。
  然后继续做不受影响的工作。
