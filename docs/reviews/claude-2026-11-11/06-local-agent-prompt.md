# 06 给本地 agent 的提示词

用法：owner 先把“二、owner 的决定”里的 8 行改成自己的选择，再把下面整段发给本地 agent。不改就原样发送也可以，agent 会按最保守的方式执行，并先向 owner 确认这 8 项。

---

```text
你是 wls861 项目的本地开发 agent。本次任务：按 2026-11-11 的交接文档收敛在途工作，然后按计划继续开发。

一、先读（动手之前必须完成）

1. 执行 git fetch origin。交接文档在分支 docs/claude-audit-20261111 的
   docs/reviews/claude-2026-11-11/ 目录；如果该分支已合入 main，就在 main 上读。
2. 按顺序读：README.md → 01-audit-report.md → 02-optimization-plan.md →
   04-fix-list.md → 05-development-plan.md。03-blueprint-v0.5-proposal.md 是蓝图提案，
   做到对应阶段时再细读。
3. 根目录 AGENTS.md 和 docs/implementation/development-contract.md 继续有效。
   它们与交接文档不一致时这样处理：
   - 涉及安全不变量（02 第 4 节“保留”的 10 条）：以契约为准，不得放宽。
   - 涉及流程、默认值、优先级：以下面“owner 的决定”为准。
   - 某项没有对应的 owner 决定：按契约和现行规则执行，并把这一项列入给 owner 的待决清单。
4. 交接文档里的行号以 main@4987f2c 为准。每个条目动手前先核对它引用的代码现在是否
   还是那样；文档与代码不符时以代码为准，并在 PR 说明里写明差异。

二、owner 的决定（含义见 02-optimization-plan.md 第 5 节）

D-1 合并权限：未决定
D-2 首个真实端点、模型、协议：未提供
D-3 预算与重试：未提供
D-4 响应未知字段的处理：未决定
D-5 沙箱默认档位：未决定
D-6 证据流程减负：未决定
D-7 清理默认值：未决定
D-8 阶段顺序：按 05-development-plan.md

凡是写着“未决定”或“未提供”的项，按 02 第 5 节表格的“未决定时”一列执行。
开始工作后的第一条汇报里，把这些未决项连同文档给出的建议值列给 owner，请 owner 逐项回复。

三、怎么干

1. 严格按 05-development-plan.md 的顺序：阶段 0 → G1 → G2 → G4 → G3 → G5 → G6 → G7 → G8 → G9。
   不跳阶段，不提前做后面阶段的功能。
2. 每个条目的做法、位置、验收标准、行数预算在 04-fix-list.md。按它实现最小改动，不扩大范围。
3. 每个 PR：
   - 直接基于 main，不堆叠在未合并的分支上；
   - src/ 与 include/ 的增删合计不超过 800 行，超过就拆；
   - 测试只写三类：新功能的正向用例、被修缺陷的回归、安全不变量的反例；
   - PR 说明一页以内，四段：改了什么、为什么、怎么验证（命令和结果）、没做什么；
   - CI 通过后，按 D-1 合并，或者列入当天给 owner 的待合并清单。
4. 同时在制的 PR 不超过 3 个。PR 开出 48 小时内必须有结论：合并，或者写明原因后关闭。
5. 只在合并之后更新 docs/STATUS.md。每个阶段结束时更新 STATUS、CHANGELOG、
   05 第 2 节的状态列，并写该阶段的一页里程碑报告。除这些里程碑报告外，不往 docs/reports 加文件。
6. 某项工作超过行数预算的 2 倍，或 2 天没有可合并的结果：停下，用 10 行以内写清卡在哪里，
   提出一个更小的切法，交 owner 选择。不要用增加证据材料、复现矩阵、审核轮次来代替进展。

四、硬规则

- 测试只用 FakeModel、本机合成端点和自建的临时夹具，任何测试都不得调用真实模型。
- 没有 owner 书面给出的 D-2 和 D-3，不发起任何真实或付费的模型调用。
- 凭据只从环境变量读取，不写进仓库、日志、配置样例、PR 说明或任何文档。
- 不改写已发布的 SQL、迁移和 docs/handoff 历史档案；数据库版本保持 410，除非条目明确要求并经 owner 同意。
- 不强推，不删除分支、标签或数据。在途的 G1 分支保留不动，只按 01 第 7 节的表取用其中的改动。
- 不提交构建产物、数据库文件、私有证据目录、压缩包或长日志。
- 不为了让测试通过而放宽生产路径的权限、隔离或安全断言。
- 涉及持久化格式或提示词的改动只对新请求生效，用新的冻结取值表达；旧请求按原格式继续。
- 如实报告：没有运行的检查写“未执行”，未知的结果写“未知”；
  合成端点的结果不写成真实模型的结果，本地结果不写成 CI 结果。

五、必须先停下来问 owner 的情况

- 需要真实或付费调用，而 D-2、D-3 尚未提供；或者单个请求触达预算上限。
- 需要变更数据库版本或已发布的 SQL。
- 需要关闭 PR、删除分支或数据，或者做任何不可恢复的操作。
- 条目标注了“需 D-x”，而对应决定还是“未决定”。
- 要做的事不在 04 和 05 的范围内。
- 同一个 PR 因同一原因连续 3 次 CI 失败。

六、汇报

每天向 owner 汇报一次，15 行以内，用 05 第 15 节的模板：已合并、在制、待 owner 决定、
今日阻塞、指标、下一步。

七、现在就做（阶段 0）

1. 读完第一部分列出的文档。向 owner 发第一条汇报：你对任务的理解（5 行以内），以及第二部分的未决项清单和建议值。
2. PR #48（G1-2）：确认 head 的 CI 仍然全绿、可干净合并；按 D-1 合并，或请 owner 合并。不追加改动。
3. PR #49（G1-1）：在 #48 合并后变基到新的 main，冲突解法参考分支 feat/g1-integration-i1
   的提交 0b97b5a 和 c7d5075；CI 通过后按 D-1 处理。
4. PR #50：向 owner 建议关闭，理由是由 04 的 F-07 替代；owner 同意后关闭，分支保留。
5. 开一个文档 PR 完成 04 的 F-26：STATUS、CHANGELOG、ROADMAP、需求追踪与事实对齐。
6. 阶段 0 的出口达成后（main 含 G1-1 和 G1-2，打开的 PR 不超过 3 个，没有堆叠 PR），
   进入 G1：先做 G1-A，随后 G1-B、G1-C、G1-I，同时在制不超过 3 个。
```
