**G2-0 要记录的内容**（5 行以内，写进报告草稿）：端点是否接受了全部工具定义；应答的顶层和用量里出现了哪些未登记的字段；输出项里有没有未登记的字段；应答里的型号名；失败发生在哪一步、原因是什么。

**每次失败之后**：把配置复制到一个新目录再跑，这样得到一个新的请求号。失败的请求目录原样保留。P4a 合并之前，失败过的请求不能续跑。

**G2-6 报告的内容**：

| 项目 | 说明 |
| --- | --- |
| 每个请求 | 最终状态、耗时、估算费用 |
| 调用 | 按角色的次数；纠正次数，按原因分；重试次数 |
| token | 按角色的输入、缓存读取、输出；Worker 第 3 次调用起的缓存读取占比 |
| 请求体 | 按角色的分段字节数：工具定义、系统文本、契约、历史、本次状态 |
| 成果核对 | 附录 A 的预期结果逐项对照 |
| 失败与未知 | 原样列出，不删不改 |
| 结论 | U1、U2 是否达成；没达成的写明原因和下一步 |

**停止条件**：单个请求触达预算上限；G2 累计触达 10 美元；出现文件效果 UNKNOWN；同一个问题修了两轮仍然不过。出现任一情况就停下来写清楚，不自行加预算。

**出口**：U1、U2 达成，或者报告明确写出没达成的原因。出口时做三件事：冻结 D-10 列出的六个格式取值；按 D-13 把蓝图迁入 `docs/spec/v0.5/`，写入 `02-decisions.md` §6 的五条修订和 G2 带来的修订；版本升 0.13.0。
