# ADR-083：冻结管理视图、原记录回读与预约前容量诊断

状态：采纳。实现 `0.9.0-r3.3b`；接续 `56185a48303deb1c72b2ec53d896e8c0b32055f0`；
目标蓝图 v0.4.1，限定节点 R1.4。

## 问题与决定

Worker 的 R1.3 窗口没有改变 Dispatcher/TeamLead 的完整问题列表。管理流程累计完成的问题
仍占原查询和上下文容量；仅扩大查询或模型输入常量会把同一故障推迟，同时难以说明省略了什么。
新策略只在新请求中显式冻结，不改旧请求的配置字节、哈希或完整历史解释。

`system.context.management_history` 选择 `window-v1`，并要求 `request_format: structured-v2`。
近期管理尝试为 1..4，完整轮次内联上限为 32768..65536 字节，二者乘积不超过 131072；
完整管理输入上限为 131072..1048576 字节。缺失策略时保持旧行为；当前外部配置改变不会改变已准入请求。

当前原始要求和全部 AMEND、有效约束、任务/计划/说明、绑定、预算、待办、等待、全部 OPEN 问题，
以及本次管理动作捕获的完整目标和必要提交文件原字节保持完整。PREPARED/RUNNING/CANCEL_REQUESTED/
UNKNOWN 操作和未结算或缺失反馈的模型尝试独立保留。Store 410 的 live 用量以独立五维投影判断；
原结算不改写，缺失 cache 用量、争议和已知超预留均保留可见事实。已知超预留作为管理告警保留，
不改成“用量未知”，也不扩大或收缩清理权限。

窗口只从动态管理视图省略已完成历史，数据库原记录不删除。三个目录分别索引问题、提交和当前
管理身份的尝试：固定作用域、插入高水位、条数和原始成员哈希链。目录明确标记
`snapshot_kind=insertion_membership_only`；它固定插入成员，不声称冻结这些记录之后的状态。
单次读取用 SQLite 读事务取得一致的目录、当前事实和近期成员；事务结束后再复核当前绑定和政策。

## 回读与权限

新增 `management_history_page` 和 `management_history_read` 两个模型只读控制。模型不能指定或
替换请求、角色、任务、团队、主体或执行代次。Dispatcher 的问题/提交限定本请求，TeamLead 限定
本请求/任务/团队；尝试历史另限定当前管理角色及主体。引用的原 hash 包含读取作用域，不能跨角色套用。

分页每次 1..4 项。原记录读回固定 ID、原版本、SHA-256，按每片 1..4096 字节返回规范化 JSON 的
base64；模型必须拼接后验证完整 section SHA。状态已经变化的旧引用明确失败，不把当前行补写成旧目标。
缺失原反馈不生成替代记录，也不读取当前工作区冒充历史提交。

调用仍走正常模型预约、结算、不可变反馈和预算。最近 60 秒的两类已结算查询（含失败）按
request/role/principal/task/team 从持久账本计数，重开不重置冻结控制频率。精确响应重放返回原反馈，
不再读取、不再收费。当前紧急禁用在预约和回读前后复核；任一必要回读能力撤销时，不再生成需要它的窗口。
控制读取不授予回答、计划修订、候选通过或业务工具权限；最终管理命令继续检查原捕获目标和事务 CAS。
经验收尾调用仍仅声明 `report_experience`，没有增加历史控制能力。

## 容量与非目标

上下文先完整编译和测量，再创建 attempt。超过冻结上限时报告总量、稳定前缀、历史消息和当前契约各段
字节、目录省略范围及 `reservation_created=false`，指明需处理的未决事实或显式拆分/重规划；不截断约束。
当前事实集合仍有 64 项保护上限，超过时指明集合并在预约前拒绝。目录扫描只载入元数据，内存有界；
扫描时间随当前作用域历史长度增长，本节点没有加入大数据库分页索引优化或无限历史承诺。

本节点是确定性的管理视图，不是 LLM 语义压缩、活动请求自动迁移、实际供应商质量验证或守护进程。
实现接口见 [R1.4 合同](../implementation/R1-management-window.md)，实际执行范围见
[节点报告](../reports/r1-management-window-validation.md) 和最终提交的五节点联合报告。
