# ADR-069：冻结 Worker 历史窗口与原证据回读（R1.3）

状态：采纳。基线为 `0dbf478892a381aed6fee99d6e1243363b005297`；目标蓝图 v0.4.1。

## 决定

仅新请求可以在 `system.context` 显式选择 `request_format: structured-v2` 并配置
`worker_history: {mode: window-v1, recent_attempts: 4, inline_bytes: 32768}`。
缺失该对象保持原完整历史语义；不改旧快照、哈希或历史记录。近期尝试1..8，单轮内联
32768..65536字节，二者乘积不得超过196608；未知字段/模式/与v1组合在准入时拒绝。

宿主按当前Worker的请求/任务/团队/身份读取最后N条，保留完整轮次及原绑定。过大的单轮
改为明确的ID、原反馈哈希、section长度/哈希和回读参数，不伪造摘要、tool成功或部分调用对。
窗口索引提供总条数、遗漏条数和插入高水位；遗漏的历史可通过R1.1作用域分页定位。
近期成员查询必须限定在同次COUNT/MAX捕获的插入高水位内；独立只读连接与写者并存时，
后提交的调用只进入下一次捕获，不使省略数量为负。不冻结已入选记录的结算状态，未决事实另行完整读取。
完整需求原文、AMEND、当前任务、说明、问题、提交、待办、等待和预算不参加窗口裁剪。
权威任务契约本身不能容纳时，仍在新预约前拒绝并说明需要显式宿主处置；不能私自丢约束。

新增Worker专用 `history_page` / `history_read` 为只读控制能力，由冻结窗口选择授权，
不依赖工作目录和业务文件权限，也不能执行旧工具。当前代次/语义绑定及运行时禁用政策
必须复核。模型每次回读需要正常调用预留、使用记账和完整反馈持久化，精确重放返回原反馈。
每页最多4项，每片最多4096原字节；以持久settled_at和冻结查询频率限制每团队最近60秒的
回读尝试，重开不清零。原宿主只读CLI保留原边界，不变成免费模型调用或远程认证接口。

模型调用预约仍先检查业务就绪；窗口/回读不解除UNKNOWN、WAITING、AMEND、工具禁用或预算。
只读宿主诊断仍沿原独立通道。移除必要回读能力后不能继续生成无法回读的省略窗口。
逻辑请求包含实际窗口描述和冻结策略；策略变化影响前缀依赖/缓存，动态历史不扰稳定前缀。
网络仍未实现，wire哈希保持null。无需修改SQL/vendor，也不引入新依赖。

## 验收与非目标

实际Worker连续16次读取61100字节文件，重开后再16次可继续；数据库保留全部原反馈。
窗口外原字节可经模型回读，修改当前文件不改变旧结果。大结果/缺失/错误反馈有明确引用；
跨任务、篡改指纹、过期绑定、禁用政策和超频拒绝；旧无窗口测试仍明确触顶而非静默裁剪。
超过256次历史仍可从尾部构建；等待和未知门禁保留；完整测试以普通用户运行。

本批是确定性窗口及引用，不是LLM语义压缩。管理角色历史、真实provider transport、自动
活动请求迁移、拒绝验收后继和强沙箱正向部署仍分别验收。实施/成绩见STATUS和实际报告。
