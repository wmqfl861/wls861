# ADR-075：运行时所有权分配恢复与显式放弃

日期：2026-10-26。状态：**设计草案，尚未实现**；目标增量 R2a.2；蓝图 v0.4.1。
当前 0.8.3-r2a.1 只实现 [ADR-074 的业务目录工具](074-bounded-directory-tool.md)。
下述迁移、创建收据、状态和命令均不是当前可执行能力；实施前须完成对应回归。

## 问题与现有边界

当前 `src/cleanup_posix.cpp` 的 `create_owned_workspace()` 直接创建最终 envelope，
然后写 `owner.json`、创建空 `work`、同步并登记 OWNED。若进程在 marker 完整写入前退出，
重试无法证明已有路径属于原意图，因而保留 PREPARED 并拒绝采用。这一拒绝必须保留；
缺少的是可恢复的发布协议和允许用户保留残留后继续的明确出口。

`db/migrations/009_owned_cleanup.sql` 只允许 PREPARED/OWNED/DELETING/REMOVED，
并对 `team_id` 设置永久唯一约束。单独新增“忽略错误”或状态值，不能解决同团队重新分配、
旧命令重放、目录保护、清理目标和冻结容量之间的关系。

原 [S1.6 契约](../implementation/S1-owned-cleanup.md) 的意图、身份、清单、证明和已冻结
清理 manifest 必须原样保留；新设计不授予模型分配/弃置/清理权限，不清除业务 UNKNOWN，
不把弃置当作删除，也不扩展到私有行 purge 或任意宿主目录修复。

## 拟议数据模型与兼容

通过新的事务迁移扩展 owned-workspaces；不得改写已发布 009 或其他 SQL 的字节。
拟增加 ABANDONED 状态和首次保存后不可变的 allocation_receipt。
保留 `UNIQUE(request_id, command_key)`，将团队唯一性改为只约束非 ABANDONED 记录，
使新的命令键和资源 ID 可在明确弃置后分配新目录。原键始终返回原资源，不能复活弃置记录。
OWNED、DELETING、REMOVED 仍占团队唯一槽位；本增量不引入已绑定工作区替换协议。

新 v2 意图在任何 mkdir 前记录随机 sibling staging 叶名、最终叶名、父目录身份、
nonce、资源/请求/团队 ID。创建收据绑定完整 marker 哈希、stage/work 的文件系统代次
（设备、inode、mount ID、birth time）、原父目录和意图。最终身份仍由原 OWNED 字段记录。
旧意图不回填新路径或伪造创建收据；旧完整 marker 加空 work 的既有精确重试保留，
旧部分 marker 则可经显式弃置退出。

有数据的结构迁移仅允许显式 AllRequests init 维护。OneRequest 与 AdmissionOnly
在其他写入前拒绝升级；只读打开不执行升级。迁移测试须覆盖全部旧状态、原 CAS/不可变
触发器、已完成/中断清理、原事件和命令键，不能只用空库证明兼容。

## 拟议创建与发布顺序

1. Store 保存 v2 PREPARED 意图，并为此分配的有限结算步骤预留容量。
2. 在固定父目录 fd 下建立私有 stage，写完整 marker，创建空 work；固定对象身份，
   同步 marker、work、stage 和父目录。所有访问继续要求 openat2/statx 的原强约束。
3. Store 在短事务中保存不可变创建收据；验证当前 Root/资源 CAS 及原意图。
4. 再核原父目录、stage、marker、空 work、资源状态和执行权限，以无覆盖 rename
   发布到最终叶名，随后同步父目录并核对最终对象与原创建收据的精确代次。
5. 以原资源 CAS 登记 OWNED。若物理发布后写库失败，重试只能核验并补记同一资源。

最终发布应使用 `renameat2(RENAME_NOREPLACE)` 的同父目录语义；缺少所需平台保障时拒绝，
不退回可能覆盖目标的 rename。复制相同 marker 或相同文件内容不能代替对象代次匹配。
失败时保留现场；不凭名称删除 stage/final，不把未知路径自动采用成运行时所有物。

## 拟议恢复判定

| 持久收据 | stage/final 实际观察 | 允许的后续 |
| --- | --- | --- |
| 无 | 两个路径都不存在，父身份一致 | 可以开始该意图的创建 |
| 无 | 任一路径存在 | 保留 PREPARED，报告冲突；仅提供显式弃置出口 |
| 有 | 只有 stage 存在且全部代次/marker/空 work 匹配 | 复核后无覆盖发布 |
| 有 | 只有 final 存在且全部代次/marker/空 work 匹配 | 重新同步、核对并登记同一 OWNED |
| 有 | 两者同时存在、任一身份不符或应在对象缺失 | 保留 PREPARED，报告原始观察和冲突 |

恢复必须先读取原意图和收据，再观察路径；不能事后用路径内容构造一份看似原始的收据。
旧 v1 兼容路径单独分支，不将新协议的“无收据”规则倒灌到历史完整意图。

## 拟议 Root 显式弃置

候选命令形状如下，**当前版本没有该子命令**：

```text
abandon-workspace --request REQUEST --resource RESOURCE
                  --expected-state-version VERSION --key KEY --reason REASON
```

只对该请求下尚未绑定的 PREPARED 资源执行元数据转换。要求当前 Root 身份、独占写者租约、
请求限定作用域、资源 CAS、非空理由和精确幂等键。请求已终态、原父目录丢失或团队已退役
不能堵住这条保留残留的控制出口；需专用授权路径，不能套用恢复业务执行所需的 ready 门禁。
已 OWNED/DELETING/REMOVED、已绑定或非目标请求的资源必须拒绝。

ABANDONED 是不可逆的记录状态；保留原意图、已有创建收据、观察、理由和命令结果。
它不删除文件、不产生 absence proof、不写 REMOVED、不宣称 cleanup complete、不清业务 UNKNOWN，
也不放行原资源的旧注册请求。精确重放只返回原弃置结果；不同参数冲突。

## 与路径保护、清理和容量的联动

所有历史资源仍可查询。绑定、业务执行和新清理目标只选择有效资源，避免使用
“按 team 取任一行”误选弃置历史。旧冻结清理 manifest 不得重新枚举、扩展或改写。
ABANDONED 不成为清理目标，其残留在 closeout/doctor 中明确报告为 retained；
其他有效 OWNED 资源仍须满足完整交付、回执、经验、原执行器退出及库存核验门禁。

stage 与 final 两条保留路径都参与业务绑定、交付和嵌套分配的重叠保护，包括 ABANDONED
历史。弃置不是把未知残留变成可利用的业务目录。不得通过新分配别名覆盖或收编原路径。

保存收据、补记登记与弃置属于有界续进/控制结算，不能在物理效果之后才被普通业务 hold
堵住。新分配应先预留需要的结算容量；新事件类型与容量归属不得重分类旧事件事实。
有效资源数和历史记录数分别有界；不能为支持重试而取消总历史限制，也不能在新分配额度
耗尽时关闭已有 PREPARED 的弃置出口。具体历史上限、预留扣费和旧窗口兼容值须在实现前
定稿并写入容量测试，不能只靠数据库约束兜底。

## 实施验收清单

- 在 marker 部分写入、收据前/后、rename 前/后、最终同步后和 OWNED 登记失败处中断，
  重开验证精确恢复或明确拒绝；至少包含真实跨进程 SIGKILL 和 SQLite 写失败场景。
- 外部预建目录、相同 marker 的错误代次、被替换父/stage/final、同时存在两路径、
  原路径消失以及 populated work 均不得误采用或删除。
- 原/新命令精确重放、旧资源 CAS/旧 Root、请求终态、业务 hold、退役团队、已绑定资源、
  兄弟请求行/租约/终态作业隔离，以及弃置后的新键重分配全部覆盖。
- 全部旧状态的非空迁移、旧 v1 完整重试、部分 marker 弃置、冻结清理 manifest 和
  “弃置残留 + 有效 OWNED”并存时的目标集合/报告/路径保护全部覆盖。
- 结算预留、有效资源及历史配额用尽、无法新增业务时仍能弃置、审计字节不可变均覆盖。

遵守普通用户、双 umask、严格编译、ASan/LSan、UBSan、Make 和 Clang 的原验证要求。
doctor 的实际路径与具体阻塞解释随后接入，只读诊断不能顺便接管、创建或弃置资源。
临时目录和故障注入测试不能替代物理掉电、恶意同 UID 对抗或强沙箱部署正向验收。
