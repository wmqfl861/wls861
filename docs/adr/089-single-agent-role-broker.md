# ADR-089：单一逻辑 Agent、全局原生历史与原角色权限代理

- 日期：2026-10-27（America/Los_Angeles）
- 状态：接受，执行结果另记
- 前置：ADR-068、ADR-085、ADR-087

## 决定

新增显式冻结的 `system.context.logical_agent`，模式为
`single-agent-role-broker-v1`。它表示一个串行模型执行者，拥有同一请求的完整、顺序化
原响应与原反馈历史；Dispatcher、TeamLead、Worker 是当前调用的权限代理，仍执行原
上下文捕获、工具声明、身份、CAS、业务门禁、预约、结算与反馈。Root 不作业务决定。
该基线保留相同工作流协议开销，比较的是共享决策历史与角色隔离历史，不是移除工作流
后的任意自由代理，也不提供独立第二模型审核。

只给原多角色调用添加一个 ID 不成立。每次调用实际编码的 structured-v2 输入必须含
全部前序调用的原生 assistant/tool 消息；无法配对的失败记录作为明确的原始观察保留。
当前权限代理只声明当前可执行工具，历史中的工具名称不授予新权限。

## 冻结、持久化和恢复

策略必须显式声明 `max_attempts`（1～128）和 `max_history_bytes`（4096～524288）。
Dispatcher、TeamLead、Worker 必须解析到同一模型及 reasoning；新策略仅支持
structured-v2。旧快照缺少该字段时，原行为和原评测含义保持。

使用原 Store 410 的 attempts、原结算和不可变反馈，不新增或改写 SQL。每个原请求
envelope 的 task contract 记录固定逻辑身份、全局步号、原历史摘要与前链 hash。
逻辑身份由 request ID、冻结配置和策略确定；不是模型参数，也不是跨请求共享身份。
全局顺序来自该请求的原 attempts 插入顺序，包含失败调用，不按成功、角色或任务筛选。
历史事实包含原角色/权限身份、binding、预约摘要、原响应/usage、原结算和反馈；不递归
嵌套以前的 request envelope，不用当前任务或当前工作区替代旧观察。

首次新预约的事务重新读全局高水位、重建整条链，并逐字核对实际输入的原生消息及当前
execution 标记。两个并发捕获相同前链时只有第一个可预约；旧预约的原幂等重放保持。
前序未结算、缺少不可变反馈、损坏或遗漏原链时明确拒绝新预约。未知或失败事实不删除；
崩溃造成的反馈缺口不能用宿主合成成功补齐。正常闭合轮次可跨进程/恢复代次继续，原
历史绑定不改标，新调用使用恢复后的当前权限身份。所有容量失败发生在新增预约之前。

## 运行器与评测

`SingleAgentRuntime` 验证冻结策略后使用原有限 event pump 作调度/权限代理，Fake 和
显式授权 live 共享同一条全局历史路径。网络、凭据、计费核验、调用/期限、错误与取消
均保留原规则。工具与模型决定仍须来自原模型反馈，不由宿主提前创建业务答案。

新增 v3 评测契约，继承 v2 的模型来源和业务判据，并逐步重建每次调用的全局历史、
身份、步号和原生输入。v1/v2 的 `single_agent` 仍是原单 Worker principal/team 定义。
v3 共同条件仅剥离 `context.logical_agent` 这一实验变量，另行精确校验单 Agent 的冻结
策略与多角色条件没有该策略；其他上下文、模型、工具、环境、约束和预算不得被抹平。
v3 另以 `original-instruction-epoch-rebind-v1` 证明跨进程来源：原模型工单的不可变
instructions 内容及其 body hash 必须匹配原 recover 事件中、位于工单和提交之间的
精确 epoch 投影。只容许 dispatcher/execution epoch 改变，语义版本与权限身份均相同。
缺事件、错 bytes、错 epoch 或顺序不符不能连接来源。v1/v2 的完整 binding 相等判据不变。
本地 TLS、Fake 和 provider 分类仍来自原记录。工程通过不建立真实供应商质量或普遍优势。

验证覆盖跨角色及两个任务的真实 wire 历史、部分 AMEND、返工/耗尽、精确交付、跨重启，
以及删/改/调序历史、错配置、只贴 ID、混模型、缺反馈、并发旧前链、越权工具、超容量等
反例。实际执行日志和结果独立记录，本文不预填通过。
