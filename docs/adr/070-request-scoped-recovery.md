# ADR-070：请求限定的写者恢复

状态：采纳。依据：10-23审核 #2、10-24审核 P1-3 的范围后继及 ROADMAP R2。
目标蓝图仍为 v0.4.1；本项不涉及真实模型、并发写者或物理数据清除。

## 问题与选择

原 Takeover 在每次写者打开时恢复全部活动请求，并重领全部经验/清理/事件作业。
即使只取消 A 或提交 C，空闲的 B 也会增加代次、暂停、消耗恢复事件；合法控制同样有此问题。
保留数据库级唯一写者和既有恢复围栏，但增加宿主明确选择的恢复范围：

- `AllRequests`：原默认构造行为，兼容既有嵌入调用及显式 `wls init` 维护。
- `OneRequest(id)`：取得相同独占写锁后，仅恢复 id 的请求/团队、操作、待定调用、事件领取和经验/清理作业。
  当前请求在任何角色可用前完成原恢复事务；不存在的请求拒绝。该连接不能准入新请求，也不能写其他请求。
- `AdmissionOnly`：只允许 `admit` 的新准入及精确去重返回；不恢复旧请求，不能发行执行身份或执行任何其他写接口。
  新请求执行须另外打开 OneRequest 或 AllRequests，先完成恢复再发身份。

CLI 的请求写命令使用 OneRequest，submit 使用 AdmissionOnly；查询保持 ReadOnly。
范围不是模型参数，也不是新的身份认证。保留原 StoreActor、CAS、权限及业务门禁。
未选请求可能仍保留崩溃前 RUNNING/PENDING 事实，但本连接没有其执行权；日后打开该请求时，
必须先把它们围栏为 UNKNOWN/取消 PREPARED。不能依据只读查询中的旧状态直接派发。

## 兼容与失败原子性

不改旧 SQL、原事件、冻结快照或说明正文。选中请求的纯 epoch 恢复仍使用 ADR-064，
不产生新的 TeamLead 决策，不清工具额度、返工、费用、AMEND、WAITING 或 UNKNOWN。
所有作用域检查重复执行于宿主写入口及事件追加；无 actor 的结算/反馈 API 也检查原记录归属。
恢复事务失败时全部回滚；旧写者锁未释放时，即使请求不同也拒绝第二写者。

带已有请求的数据库若需要结构升级，限定写者明确拒绝，要求先用 AllRequests/init 维护；
避免 403→404 事件引导等升级隐式写兄弟请求。空库的 AdmissionOnly 可以初始化；
OneRequest 必须针对已存在的受支持数据库。ReadOnly 不接受写者范围选项。

## 验收

先在原代码实际复现“对 A 的成功取消/新准入改变 B”，再验证：
A 的操作/调用/领取被正确恢复，B 的相关行完全不变；B 后来接管仍隔离旧身份/结果；
终态 A 的经验/清理可恢复而 B 不变；跨范围写入、无效 id、恢复事务故障及第二写者拒绝；
新准入和去重不改变旧请求，准入连接不能执行业务；旧默认全库恢复仍兼容。
普通用户 Release/两种 umask、UBSan、ASan、Make 与原回归一起执行。

## 不做

这不是并行租约、延迟到首次写入的恢复或“空闲请求永不提升代次”。被显式选中的请求仍完整恢复；
终态及旧默认全库模式保持原语义。Dispatcher 否决后的有界返工和模型 AMEND 处置仍为 R2 后继。
