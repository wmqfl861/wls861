# ADR-084 — 新请求冻结 owned 工作区贯通容量

日期：2026-10-27。开发基线：`56185a48303deb1c72b2ec53d896e8c0b32055f0`。
接续 [R3 后继计划第 6 节](../implementation/R3-controlled-live-plan.md#6-owned-工作区贯通容量)，
实施契约见 [owned 工作区贯通容量](../implementation/R3-owned-workspace-capacity.md)，
实际证据见[节点验证报告](../reports/r3-owned-capacity-validation.md)。

## 问题与复现

历史 Workspace 允许 20000 个条目，owned cleanup 只接受最多 4096 项的完整原始库存。
基线普通用户实验先建立 4096 个合规文件，再调用真实 `Workspace.write_atomic` 成功创建第
4097 项；随后库存生成报 `quota`，目录完整保留。它是合法业务输入导致的收尾容量缺口。

仅将 Workspace 改成 4096 仍不贯通：原子替换在 rename 前同时保留旧文件和一个临时文件，
崩溃可能留下第 4097 项或额外 16 MiB。数量与内容字节合规的长路径、控制字符路径，经 JSON
转义后也可能超过 Store 的 8 MiB 库存上限。`run` 可直接写文件，不受文件工具的遍历额度约束。

## 决定

采用显式的新请求策略 `system.cleanup.owned_workspace_capacity`，版本为
`owned-capacity-v1`。不更改历史默认值，不回填旧配置、旧分配或旧库存，不扩大清理硬上限。

| 冻结业务字段 | 可配置范围 | 清理所需边界 |
| --- | --- | --- |
| `max_entries` | 1–4095 | 业务条目加 1 个可能遗留的 stage，最多 4096 |
| `max_total_bytes` | 1–251658240（240 MiB） | 加 16 MiB stage，最多 256 MiB |
| `max_inventory_bytes` | 262144–8388608（256 KiB–8 MiB） | 完整规范 JSON，不分片或截断 |

版本隐含 `file-tools-only`。新策略绑定原 runtime-owned 分配；WorkerTools 将冻结值实际应用到
Workspace，执行策略记录同一容量及范围，工具声明不提供 `run`，直接调用 `run` 也在准备操作
或启动进程之前拒绝。旧请求的 `run`、默认 WorkspaceLimits 和 execution_policy 字段保持原解释。

新分配意图保存原策略，所有权 marker 保存策略 SHA-256；现有 allocation receipt 的意图 hash
和 marker hash 自然绑定这些原字节。库存保存相同策略，Store 在库存事务内验证绑定、条目数、
内容字节及编码大小，Linux 删除入口再次验证。低层调用者给出的较大 CleanupLimits 不能覆盖
原策略；更小的调用上限仍可保守拒绝。所有删除仍仅针对原所有权与持久库存。

业务写入采用保守编码预算：128 KiB 覆盖库存头及全部绝对根身份，每项预算为准确 JSON
转义路径的编码长度加 1024 字节，另保留一个最大 4096-byte 路径的 stage 项。元数据包含固定
字段、有限宽度的整数及 SHA-256，1024 字节大于该表示的上界；新库存生成仍核验实际字节。
目录创建、新文件和替换/patch 均在首次文件效果前核验完整当前树及投影。长父路径还须容纳
原子 stage 名称。一次中断残留被下次遍历计入当前树；不能绕过额度持续堆积新的 stage。

首次库存超出原能力时，清理运行器返回 `RETAINED_CAPACITY_EXCEEDED`，明确本次未提交库存、
未删除，要求保留或由可信宿主另行明确处理。它不会切分旧清单、以新配置重标旧请求、生成
删除证明或跳过原收尾门禁。已经持久化的库存始终按原字节重放。

## 为什么选择保守限制

有界分片需要新增不可扩展的总清单格式、分片身份、原始总量证明和跨重启检查点。
当前阶段先提供可验证的单清单闭合边界，减少新格式和删除权限转换。对 `run` 的独立磁盘配额、
可接续大树库存和分片删除仍需后继设计；本策略不宣称支持任意大树或任意子进程写入。

## 验证与边界

测试使用普通 UID 的真实临时目录、SQLite、原文件工具、FakeModel 工作流及限定到夹具的
进程中断。覆盖业务条目/字节/转义库存预算恰上限、超限无文件效果、原子替换 stage 残留、
原库存与配置不变、v2 分配恢复、原 inode 替换、库存事务失败和删除后重启。实际执行结果
只记入节点报告及整批报告；测试清单不等于已经通过所有编译器、sanitizer 或 CI 门禁。

合作锁与原权限模型不变；任意同 UID 宿主可绕过工具直接写入，超限后仍保守保留。SIGKILL
不是整机掉电实验。工作目录阶段完成仍保留交付包、owner 收据和全部私有数据，仍不代表
全局 cleanup 完成。此节点不新增 SQL，也不改写任何已发布 SQL。
