# ADR-079 — 独立边界复核与修复范围

日期：2026-10-26。审核基线：`72f74d6fd9261fab2fb372370080b93006fc4fdb`。
用户要求独立审核、优化代码与蓝图并直接修复；既有开发和推送授权继续有效。

## 决定

按模块边界重新核对源码和反例，不从历史 CI 通过推导协议互通或产品验收。
本轮由分开的审阅任务交叉检查，但仍属同一模型体系的工程复核，不能充当
S2 的独立第二模型业务验收。实际命令、失败和修复后成绩另写版本化报告。

已复现的问题按最小范围修复：

1. Responses 已支持的两种 delta 允许官方默认的 `obfuscation` 字符串。
   该字段只作为有界传输填充保留和计数，不能混入文本/函数参数；类型、事件范围、
   原始流、完整终态、序列/身份和所有容量门禁保持。未知字段仍拒绝。
2. 普通 CLI 的所有命令/子命令/参数在读取输入或打开 Store 之前验证 UTF-8。
   现有 doctor/replay 的 4096 字节参数限额保持；不把该限额擅自套给历史业务参数。
   错误报告只保留最多 4096 字节消息前缀，截断和原长度显式记录；不能直接表示
   为 UTF-8 的前缀用 hex 保留。异常处理自身必须有固定 JSON 兜底，避免再次抛出。
3. 文件系统读取和清理分别核对“只读打开是否产生副作用”“文件长度是否等于
   实际 EOF”“合法工作区名称是否能进入受控清理”的契约一致性。修复必须保留
   原对象代次、所有权、无符号链接、实际读取预算、不可变清单和删除授权。
   同类类型先检规则须贯通 `pin_file`、`read_runtime_file` 和配置文件加载器，
   不能只修运行文件而保留 doctor 的配置/manifest 或协议输入入口的特殊文件打开副作用。

修复不修改已发布 SQL、vendor 字节或历史证据，不移除旧回归、不放宽生产权限，
不通过延长超时掩盖失败。未证实的问题只登记后续设计，不为审计数量扩大改动。

## 蓝图取舍

R3.3 拆成可独立验收的本地 transport、Store/账本集成、获准真实小任务三个节点。
未知用量的后补核对须新增独立不可变事实，不能改写原结算、释放未知预留或提高旧响应
业务权限。具体依赖、失败反例与完成条件见
[受控真实闭环计划](../implementation/R3-controlled-live-plan.md)。

Worker 窗口不等于管理角色视图已经有界；工作区可创建容量不等于清理器能一次处理。
这两个贯通容量问题分别制定任务卡，不直接提高上限或剪掉当前约束。服务化、私有行
purge 和大范围 Store 重构继续后置；CLI 可以承担首个 S1 小任务验收入口。

官方 SDK 的 `StreamOptions.include_obfuscation` 说明默认 delta 填充：
[OpenAI Python SDK](https://github.com/openai/openai-python/blob/main/src/openai/types/responses/response_create_params.py)
（2026-10-26 检索）。这是协议依据，不是供应商现场验收。
缺陷复现反例须在基线失败并在修复后通过；新增守卫与边界回归分别注明基线行为。
原有身份、版本、UNKNOWN、权限与
请求作用域测试继续执行。没有真实模型调用、付费尝试或生产数据操作。
