# ADR-073：模型产生逐任务 AMEND 处置

日期：2026-10-25。状态：采纳；实现目标 0.8.2-r2.3，蓝图 v0.4.1。
基线为 R2.2 `c975be3e7d30c1208a0a2c19494e2a186c7f77ca`。

## 问题与选择

R2.2 的 AMEND 仍需宿主提供 dispositions 文件。正常 Dispatcher 模型只能提交计划，
不能自行对已分配任务选择 update、keep、cancel。本切片在工作流事件运行器接入两个
有界模型工具，保留已有宿主处置和旧单任务运行器的兼容行为。

- `submit_amendment_plan`：提交模型字段的 plan 与至少一个逐节点 disposition。
  首次当前 AMEND 计划及这些决定原子落盘。现有节点和模板不允许更换，遗漏任务继续暂停。
- `resolve_amendment`：已有当前计划时，只提交至少一个尚未处置节点的决定。
  不重新发布计划，不修改已处置兄弟任务的说明、代次或 applied 版本。

每个决定仅含 `disposition` 和非空 `rationale`。模型可选择宿主捕获的待处置节点子集；
不能注入请求、任务、团队身份、修订、执行代次或 CAS。update/keep 的 TaskBrief 来自新计划；
keep 仍要求新说明及 Worker 确认，不能直接重用旧 applied 状态。

## 捕获与最终授权

宿主在预约模型前捕获当前请求 CAS、原要求/计划/代次、完整原文与任务快照，
并将 AMEND 工作目标持久化在原 ModelRequest。首次计划影响全部既有节点，故在同一
Store 事务内核对全部捕获任务 CAS/团队代次；后补决定核对其捕获的待处置集合。
请求 CAS 不能代替任务 CAS；响应回来后不得用当前任务行重新授权旧判断。

原响应和实际/未知用量先结算，随后核 Schema、原调用、请求范围、当前绑定和捕获目标。
再一次 AMEND、恢复、政策变更或目标任务变化会拒绝旧判断，保留原响应及费用事实。
事务失败不留下部分计划/处置。精确响应重放仅返回原反馈，不重新推进修订。

不重置共享返工计数，不核清 UNKNOWN，不把 cancel 当成副作用撤销；不恢复已退休团队。
现有旧 SQL、冻结快照、原说明、原成果与原历史反馈均保持不可变。

## 调度与验收

仅未提供宿主 dispositions 的工作流 pump 启用模型 AMEND。一次唤醒继续受原管理调用数、
总调用数、预算与上下文边界约束；缺脚本、坏响应、调用耗尽保留待办。
仅完成已被当前计划明确处置的具体 AMEND 项，遗漏项可以在下一次 pump/reopen 后继续。
后补决定不额外增加 plan_revision。请求 A 的恢复和决定不得改写请求 B 的持久行。

回归覆盖模型 update/keep/cancel、部分决定和重开续办、原约束/模板、迟到和任务 CAS、
UNKNOWN、精确重放、预算、兄弟请求及已有宿主路径。完整门禁按 AGENTS 在普通用户下执行，
实际结果写独立版本报告；R2.2 缺失的联合验证报告同步补齐。

本项不宣称真实模型决策质量、强沙箱部署或 S1 全阶段完成。后续为 R2a 的 fs_mkdir、
PREPARED 分配恢复/显式放弃，然后 R3 单协议离线回放；付费实测仍需独立端点/预算配置。
