# ADR-068：供应商无关的结构化模型输入（R1.2）

状态：采纳；实现、证据和默认启用状态分别记录在 STATUS 和本批报告。
基线：`b493752a10d2ad66670d6b201b24b1f489df7931`。不改已发布 SQL、vendor 或历史调用字节。

## 决定

新增 `wls-compiled-context-v2`。编译结果包含独立的工具参数 Schema、具名系统段、
完整任务契约及有序 user/assistant/tool 消息，不要求适配器解析 WLS-CONTEXT/1 字节帧。
原生工具调用与结果以唯一 ID 配对；动态消息不允许 system 角色。历史内容始终是数据，
不因为带有 tool 名称或旧的 accepted 标志而取得执行权限。

配置 `system.context.request_format` 可选 `framed-v1` 或 `structured-v2`。缺字段的旧快照
仍为 framed-v1，不补写、不改 hash、不受当前 YAML 影响。迁移活跃请求不在本批授权范围。
兼容样例仍选 framed-v1；结构化路径通过新请求显式启用，并接通 run-fake/pump-fake 的全部角色。
Store 在新预约时核对格式与冻结配置，精确重放已有预约不受新的默认值干扰。

结构化 prefix_sha256 仅对规范化稳定前缀计算；cache_identity 另含模型、reasoning 和协议版本；
logical_request_sha256 覆盖选择、前缀及动态输入。它们都不是实际 HTTP 请求指纹。
本批无网络发送，wire_sha256 为 null；未来适配器必须保存其实际发送表示，不能复制逻辑哈希。
`prompt()` 在 v2 仅返回逻辑规范 JSON 用于容量/保守字节预留，不是可直接发送给模型的扁平 prompt。

宿主从已保存尝试生成历史：原响应完整、单一工具调用且存在可核对反馈时生成 assistant/tool 对。
逻辑工具 ID 由 attempt ID 与原 call ID 的规范 JSON 哈希导出，原 ID/绑定保留在来源元数据，
避免不同尝试重复同一供应商 ID。错误、迟到、多个调用或反馈缺失作为明确的 user 观察记录，
不能补造成功结果或再次执行工具。所有原始历史仍完整保留在 Store，旧读取 API 行为不变。

## 本批不解决的范围

历史选择仍为旧完整有界读取；不宣称修复 60 KB 多轮触顶或超过256条的 Worker 循环。
R1.3 再接冻结窗口、遗漏索引/原证据回读工具、未决状态保护和跨重开的大结果回归。
不增加真实调用、付费重试、模型权限或弱隔离。结构化语法与哈希验证不替代 Store 身份/版本/CAS。

## 验收

独立字段与往返恢复、历史 ID 重复隔离、配对缺失/重复/交叉拒绝、动态 system 拒绝、
工具/依赖顺序稳定、动态内容不扰前缀而影响整体指纹、选择变化使缓存失效、
重算哈希也不能绕过结构验证、旧格式逐字节兼容、配置冻结与格式错配在预约前拒绝。
实际 CLI 验证管理/Worker及原始工具结果，重开不改旧绑定；付费模型调用数保持0。
