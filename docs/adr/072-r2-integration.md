## 联合不变量

- 每次请求命令只恢复目标；提交新请求或幂等重放不改变任何已有请求。
- 返工捕获、用户上报、回答、重新发说明和新成果验收也必须服从请求范围。
  新管理动作不绕过 OneRequest/AdmissionOnly；精确旧命令重放也不获得外来请求写权限。
- 在范围限定的请求上重开仍隔离旧调用，保存迟到响应和真实用量，不采用旧判断。
  返工累计次数、UNKNOWN、WAITING、AMEND和原任务/说明约束均保持。
- 一个请求的更改不得改变兄弟请求的逐表持久行、预算、说明、原反馈或终态收尾租约。
  兄弟以后自己接管时仍执行完整恢复，不把保持RUNNING的旧记录当作执行许可。
- 继续持有数据库唯一写锁；不提供多写者并行。全库init仍是明确的维护操作。

整个现有回归必须在普通用户下运行，多umask、Release、UBSan、ASan及Make分别记录。
本批不改已发布SQL、vendor和审核原件，不发真实模型调用，不扩大业务权限。

模型AMEND处置仍是下一独立R2切片；PREPARED分配恢复/fs_mkdir和真实协议按原路线图推进。
