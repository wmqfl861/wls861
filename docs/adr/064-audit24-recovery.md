# ADR-064–066：恢复、进程结算与冻结容量

状态：设计采纳；各项实现和验证状态只在 `docs/STATUS.md`。蓝图版本保持 v0.4.1。
依据：用户授权、2026-10-24 审核（含推送补充）、现有 Store/运行器。旧 SQL/vendor 不修改。

## ADR-064：语义不变的说明恢复（P1-3，先实施）

需求、计划、任务和说明修订属于语义版本；Dispatcher/Worker epoch 是执行围栏。
写者恢复照常递增 epoch，取消 PREPARED、将 RUNNING/待定调用置 UNKNOWN，并释放旧 claim。
对仍匹配当前请求/计划/任务/团队的当前说明，宿主只重绑定 epoch，不改正文、语义修订、
已用工具额度、返工计数或原始调用记录。recover 事件保存重绑定前后的元数据及正文哈希；
instructions 行是当前绑定投影，最初 instruction 事件保留来源。事务失败全部回滚。

恢复使 Worker 的 applied_instruction 失效；只能用新身份、当前 CAS 重新 ack。
ack 本身不解除 WAITING、阻塞问题、AMEND 或 UNKNOWN。模型层按语义判断是否真的需要新说明，
包括旧 run-fake 入口。只变 epoch 不应预约 TeamLead，也不能重置每条说明的工具额度。
语义变更、旧命令重放、陈旧 actor、迟到模型/操作结果均维持原门禁。

验收：原 reopen 复现转为断言测试；同说明重 ack 后业务可继续，无新 TeamLead attempt；
原正文/修订/用量不变；旧在途/响应仍被围栏；WAITING 和未处置 AMEND 不被恢复绕过。
不在本项顺便取消全库恢复或改成按请求租约；那是 R2 的独立并发契约。

## ADR-065：已知的失败不等于 UNKNOWN（P1-1，实施前契约）

仅当强隔离证明、network=none、cgroup 全后代退出以及完整前后工作区清单同时成立，
才能把非零退出、信号、超时、输出超限记为 FAILED/TIMED_OUT 等已结算失败。
/work 是唯一可写的持久位置。清单绑定固定根、路径、类型、文件身份、大小及完整 SHA，
差异记录新增/删除/修改；不把“命令失败”解释成“没有副作用”。清单有容量边界，
取不到、超限、不支持的条目、退出未证实、执行器异常、结果无法持久化仍 UNKNOWN。
未产生子进程的拒绝保留 REFUSED；不能把内部弱监督夹具当作强模式正向成绩。

增加 Root/受信宿主专用 reconcile-op，绑定 request/op、预期状态版本、结论及非空证据，
状态变更和事件原子提交，精确同键重放。同请求当前 Root 授权不等于任意 Worker 工具权限；
不注册任意 shell 核对通路，不把核对结果冒充原始退出证明，不覆盖旧原始结果。
取消先成为 UNKNOWN，后续只凭上述观察或明确宿主核对处理；迟到普通结果不自动核清。

验收：零/非零退出、超时、输出超限、取消，及逐项缺证据的反例；存储失败继续阻断；
CLI 错请求/错 CAS/空证据拒绝，精确重放不重复事件，核对前不能新业务。
部署强环境若不可用，分别报告纯分类测试、真实清单/Store/CLI 与未执行的强隔离验收。

## ADR-066：容量是可恢复的准入边界（P1-2，随后实施）

事件（普通/控制）、操作、问题、提交、验收、交付、AMEND 等上限来自 system.limits 的
冻结值。旧快照缺字段时取旧常量的明确等价值，不能读取后来配置或重写旧快照哈希。
新准入以 worker_max_tool_calls_per_order、max_teams_per_request、team_internal_rework_max
推导最低容量（工具生命周期至少按六条事件及管理/恢复余量），显式不足拒绝。
业务与控制分类独立计数；预留已经准入操作/模型尝试的结算空间，不能用控制流量吃掉
业务额度，或让业务占完后控制也无法记录。接近上限告警，到限停止新的准入并持久记录
可恢复阻塞及解除主体/命令。不能在结果已经执行后才随机碰到无结算空间。

恢复/检查点不能清除 UNKNOWN、重置工具/模型/费用/返工额度或隐式批准 AMEND。
事件分段或宿主显式检查点须保留审计、command_id/command_sha256/result 和精确重放。
这不是无限磁盘保证；物理写入失败仍失败关闭。是否添加表/迁移须先记录复杂度与兼容性，
不得为通过复现简单提高常量或删除历史。旧 event_cap 复现和冻结/重开/结算/重放反例
全部纳入 Make/CTest 后，才可将本项标为完成。
