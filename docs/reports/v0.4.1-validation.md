## 1. 当前代码的实质变化

| 变化 | 实际行为与验证 |
| --- | --- |
| Worker 新说明确认成为有界控制动作 | 普通事件额度用尽或存在 UNKNOWN 时仍能确认当前新说明；它不结算 UNKNOWN，也不放行新业务。新命令反复确认已应用说明会被拒绝，精确命令重试仍去重。 |
| 新增 `cancel_operation` | 只处理 Worker 自己团队的操作；Prepared → Cancelled，Running → Unknown。仍检查身份、范围、CAS、代次及状态，重新打开 Journal 后保留结果。 |
| 生产说明变更使当前候选失效 | 成功受理的新说明清除当前候选及批准，保留历史审核与成果版本高水位。旧候选不能靠旧审核再次通过。 |
| 多团队变更围栏 | AMEND 漏处理的第二团队继续阻塞；仅计划变化也不能让旧结果和旧候选生效。确认新说明不冒充未知操作核对。 |
| 审核与交接在饱和时推进 | 普通工作占满其允许容量时，由宿主依次提交审核、交接，预留容量仍可推进。回调不在同一池内同步等待依赖；当前 Scheduler 不负责解除任意依赖环。 |

M1 的 Journal 序列化布局未改变，原有配置冻结、角色权限、恢复与资源状态机制继续保留。`instruct_team` 在生产团队的 Accepted／HandoffPending 状态仍安全拒绝直接修改；不能把本次修复描述为“在所有状态自动重新打开请求”。审核团队有独立的返回 Verifying 路径。详细边界见 [M1 当前实现契约](../implementation/M1-contract.md)。

### 交叉审查落实的契约回归

- AMEND 只能由所属 Root 发起；Dispatcher 处置必须带决定发起时的需求和计划版本。迟到决定不能被盖成新版本，业务终态请求不能重新处置任务。
- 新任务必须先有 TeamLead 说明，再由 Worker 确认。精确说明重试不被自身代次变更拒绝，同命令换内容会冲突。
- 审核票据同时核对生产候选和审核方自己的版本、执行代次；恢复后的迟到回包和重新盖章都拒绝。宿主确定性检查失败不能用模型 pass 或用户豁免替代。
- 记忆使用绑定实际加载 ID、版本、任务及 Agent 实例；跨项目和未知 scope 拒绝。A 版本的成功不会给 B 加分，卡片曝光、无证据与重复来源不抬高评分。
- 记忆修订以基线版本和 CAS 原子提交，冲突不覆盖当前版本。撤权在新的业务派发处重查。
- 每个团队按自己最后发行的任务／说明版本完成经验待办。AMEND 后旧 DONE 报告不能完成新一轮收尾；请求行删除后独立清理待办、回执和持久反馈仍可查询，旧清理租约不能完成新领取任务。

上述 Python 事务使用真实 SQLite 文件与事务，但输入、动作证据、用户豁免和接收回执均为宿主测试夹具。它们不代表真实 Agent 身份认证或业务执行。

最终执行入口：

```sh
make -j2 test PYTHON=/usr/bin/python3
make -j2 ubsan PYTHON=/usr/bin/python3
cmake -S . -B build-cmake -DCMAKE_BUILD_TYPE=Release \
  -DPython3_EXECUTABLE=/usr/bin/python3
cmake --build build-cmake --parallel 2
ctest --test-dir build-cmake --output-on-failure
```

严格编译使用 C++20、主要警告及 `-Werror`。UBSan 使用 `-fsanitize=undefined -fno-sanitize-recover=undefined` 与 `halt_on_error=1:print_stacktrace=1`。CMake Release 在本地实际配置并构建成功，CTest 总耗时约 4.09 秒。普通与 UBSan 门禁中的 35 项 Python 契约分别耗时约 1.75、1.74 秒，均返回成功；这些时长只是本次观察，不是性能指标。

## 4. 文档与实现范围

蓝图和计划已统一为 v0.4.1，保留现有 M1 与未来 S0–S5 的承接。角色、提示词、配置及验收计划同步覆盖显式 AMEND 处置、控制动作、完整版本、审核预留、预算、记忆与恢复约束。三份 YAML 已解析并检查默认值：FakeModel、真实调用关闭、自动付费重试为 0、记忆关闭、真实清理关闭、SQLite FULL。systemd 文件是未来部署样例，未安装或启动服务。

两个独立工作流交叉审查了 C++ 变更和 Schema／SQLite 事务；具体发现已在本批修复并增加有效回归。文档检查还修正了 UNKNOWN 可确认新说明、历史审核保留、同团队与全请求门禁的范围，以及审核预留和等待态释放必须同时满足的表述。

当前 **没有完成** C++ SQLite Store、完整 DAG／RoleRunner、真实模型与业务工具、bubblewrap／cgroup、MCP／Skill 接入、跨 Root 审核服务、MemoryEngine、Git Writer 或生产部署。Python 的记忆 CAS 冲突会抛出错误，持久冲突草稿和人工合并仍由后续 S3 实现；参考清理只删除临时数据库请求行，不处理真实工作区文件。`schema.sql` 是空库初始化契约，不是已有 v0.4 数据库的自动迁移脚本。

原 51 项产品验收保持历史状态。本批结果证明当前内核修复与目标契约的选定边界可执行、可回归；真实系统闭环、模型质量、费用和 OS 隔离需按后续任务卡提供独立证据。
