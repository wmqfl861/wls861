# 记忆系统 v1 规格 v0.4.1（S3 待实现）

目标来自 T13–T20：统一 Skill、规则、经验与事实，按条件逐步回忆，避免反复寻找工具；冲突并存、验证加权、新版本和合并可追溯。本轮采用轻量存储方案，但保留版本、权限、来源、归因和撤销语义。当前 memory.enabled=false，Schema/SQLite 参考事务检查不等于已完成 MemoryEngine。

## 0. 与 v0.3 的对应

| 概念 | v1 实施契约 |
| --- | --- |
| MemoryRecord / Applicability | 带不可变 revision、范围/条件/标签的 Markdown/Git 内容与结构化元数据 |
| Proposal / Approval | draft 候选、expected_base_revision、目标范围及单独审批记录 |
| Evidence / WorkingMemoryBinding | memory_loads 中的 load_id/实例/任务/版本，与 Submission 声明和动作证据分别记录 |
| 权重 / 统计 | 按 memory_id + revision + 来源去重组聚合，带统计政策版本；不是“加载次数=有效次数” |
| 生命周期 | draft/active/archived/blocked；内容修订、发布状态、运行时撤销门禁分别管理 |
| Wiki / 索引 | 内容可浏览，全文索引可从内容/发布元数据重建；反馈与审批不是能从 Markdown 正文凭空重建的数据 |

## 1. 目标与验收

用相似任务对比关闭/开启记忆，报告质量、工具次数、错误、费用、耗时和样本条件；不把第二次因为任务更简单或缓存更热造成的变化归因于记忆。保留“无新增经验”、无可用匹配和无足够证据的合法结果。验收见 04 的 S3 与新增回归。

## 2. 内容、身份与写入

### 2.1 布局

拟使用 memory/rules、facts、experiences、skills 和原样 imports。wlsd 的 MemoryStore 是自动写入入口；Markdown 可作为 Wiki 浏览。Git 提交用于追踪版本，不使未审批内容自动获得权限；Git 删除提交不清除历史副本。

### 2.2 身份和 revision

规则/事实/经验用稳定 ID，Skill 用 skill:name；每次实质内容、脚本或适用条件变化产生新的不可变 revision。记忆 ID 表示连续身份，revision 表示具体可加载内容。加载、评分、批准、撤销和引用不能只存 ID。脚本审批绑定内容 revision/hash，不能批准一次后任意改脚本仍沿用批准。

### 2.3 文件头

memory_frontmatter Schema 包括 id/type/status/scope/title/description/tags/applies_to/source/relation 等。正文写适用场景、方法、依据、限制；观察事实和因果推断分开。outcome=failure 表示失败经验的内容性质，不等于这条警示记忆本身无效。

### 2.4 Skill

SKILL.md 的通用字段按实际选定标准版本验证；自定义 metadata 使用字符串。保存 imports 原包来源/目录哈希，并独立维护获准执行的脚本版本。正文、references、scripts 分别受读取/执行权限约束；脚本已复制到 /work 也不能脱离版本与撤销绑定。

### 2.5 写入与 CAS

new/revise/conflict 经明确项目/功能范围授权的 MemoryStore。修订必须提供 expected_base_revision；事务比较当前 revision，匹配才发布新版本。冲突保留为 draft/并列候选，不能“后写覆盖”。新版本统计从零开始；原版本反馈仍按原 revision 保存，不挪到新版本。

Git 内容写入、SQLite 发布/索引更新以持久提案、内容哈希、提交引用和恢复待办衔接。不能把跨 Git/数据库写入声称为单个原子事务。wls memory reindex 只校验并重建获准内容索引；普通手工编辑不自动批准规则、脚本或扩大作用域。确需人工批准时使用有可信身份的明确命令，留下对象/revision/范围记录。

## 3. 索引与事实来源

内容正文以 Git/文件内容版本为源；发布状态、审批、撤销和反馈以对应的持久记录为源，文档须能解释二者的恢复顺序。memory_meta、memory_error_signatures、memory_fts 为检索入口；memory_loads 与 memory_feedback 保留独立证据身份。

检索先限定 active、授权可见范围、功能/工具/平台/条件，再在合法候选集内做相关度和可信度排序，最后 limit。可以用 SQL JOIN/谓词或受控分页拉取实现，不能先取全局 top 20 再过滤，导致其他项目高分内容挤掉第 21 条有效记忆。未授权标题、片段、数量和匹配存在性也不能泄露。

全文检索可选中文分词；依赖不可用时明确降级，短中文查询需有关键词/标签/ID 回退，不假装任意短词都能被 trigram 命中。规则和精确 ID 查询不依赖全文索引。语义检索和嵌入模型后续评测再定。

## 4. 治理和生命周期

### 4.1 四态

| 状态 | 行为 |
| --- | --- |
| draft | 不参与业务回忆，等待明确验证/审批 |
| active | 仍须满足范围、条件、依赖和未撤销门禁 |
| archived | 不作当前方法默认推荐；历史可审阅，恢复需确认当前条件 |
| blocked | 禁止新激活和相关业务派发；先更新 policy_epoch，再通知活动实例 |

### 4.2 personal 工程默认

拟允许本项目经验/事实在获准任务验收、经验收尾和验证条件满足后自动生效；这不是“请求成功就把任何内容发布”。默认关闭 memory 模块，真实启用时明确自动发布范围和证据政策。

| 变更 | 默认处理 |
| --- | --- |
| project 新经验/事实 | 校验来源、范围、完整证据后按政策 active；证据不足 draft |
| project 修订 | expected_base_revision CAS；新内容重新评价，冲突 draft |
| 无脚本 Skill | 仍校验依赖、内容、范围和适用性，按明确政策发布 |
| 规则、扩大到 function/global、含脚本执行授权 | 单独批准，绑定具体 revision 和范围 |
| 第三方导入 | 原包保留，draft，正文和脚本分别批准 |
| 合并提议 | 新 revision/draft；默认 auto_merge=false |
| 手工修改 | reindex 不授予新权限；明确可信批准才改变规则/脚本/范围状态 |

作用域扩大时不能先以目标范围生效。单用户也不能绕过跨项目/功能边界；默认项目名不意味着全局可见。

### 4.3 摘要

每日摘要记录新发布、待验证/批准、冲突、CAS 失败、新警示、撤销和统计版本，并提供可核验回滚/处理引用。它是本地持久报告；未经发送授权不自动对外发消息。没有新经验可生成空变更摘要，不以数量衡量进化。

### 4.4 命令

后续提供 ls/show/search/digest、approve/reject、revert、archive/restore、block/unblock、import、reindex/doctor。revise 使用 expected_base_revision；approve 指定 revision/范围/脚本；revert 形成新的可追溯修订，不能删除过去评分来假装从未发生。

purge 的普通实现仅从当前可用库移除并阻断后续使用，Git 历史仍可能保留；严格历史清除需另行策略、备份/克隆/远端范围和验证，不把 git rm+commit 命名为完整擦除。

## 5. 逐步回忆

### 5.1 确定性规则

获准且作用域适用的规则必须确定性加载。rules_max_tokens 是启动校验/编排阈值，不是按 token 截断强制规则的许可；超额时拒绝对应执行或显式分组，不悄悄丢规则。运行时可强制的 policy 规则独立进入派发检查，不能只留在提示词。

实例提示前缀可保持稳定；新增/撤销政策通过独立 policy_epoch 立即影响派发。缓存不能延迟撤销，消息通知不能替代门禁。

### 5.2 被动卡片

在任务开始、团队启动、说明/方向变化、准备检查时触发。先过滤授权、active、版本、工具/平台条件，再检索排序和限量（默认 5 张/600 token）。同实例已经出示过的同一 revision 可去重，新 revision 不能因同 ID 被永久屏蔽。

卡片含 ID/revision、来源、适用条件、不可用理由和统计政策下的证据摘要；作为资料追加⑤，不改系统提示。card/recall 是曝光记录，不自动等于实质加载或有效样本。

### 5.3 主动 recall/load

recall 返回合法候选卡片，不泄露被权限过滤掉的数量；load_memory 读取获准的具体 revision/full text 并生成 load_id，记录 request/task/team/agent_instance_id、读取内容和作用域/政策版本。加载时再次检查状态，避免检索后被撤销仍可读取。允许的资源文件逐项限制目录和大小。

scripts 执行先核绑定 revision/hash 与批准，再过普通业务门禁。复制路径不是授权令牌，任意 run 不能绕过撤销。

### 5.4 错误触发

用工具/error_signature 精确匹配经过同样硬过滤的失败经验；最多 3 条。归一化签名用于召回，原始错误证据和条件仍区分。失败经验能否帮忙需单独评价，不能按失败经历本身给记忆扣分。

### 5.5 资料与指令

所有记忆附 ID/revision/来源/状态抬头。项目经验不能因正文自称高优先级获得新权限。注入扫描可用于提示审查，不能声称能检测所有攻击或代替角色/路径/政策检查。

## 6. 使用、反馈和统计

### 6.1 加载绑定

memory_loads 为每次出示/读取登记唯一 load_id、memory_id、revision、agent_instance_id、request/task/team、how 等。card/recall 与完整 load/rule 的语义区分。规则确定性全文加载也须有绑定；“名字进入 pinned 索引”只算索引曝光。

### 6.2 使用与评价

Submission.used_memories 必须带 memory_id/revision/load_id 和具体用法。运行时核对该 load_id 属于此任务/实例、内容版本一致、确有被允许的实质加载；不能拿别的团队或旧 revision 的加载记录证明当前内容已用过。

TeamLead 的 worked/failed/irrelevant 评价要链接具体动作/产物/检查与自足证据。加载、声称使用、实际动作关联、效果判断分别保存；只有满足统计政策的 eligible 证据计分。未加载、只有卡片、未用、未知因果/结果、irrelevant 保留观察但不增加有效/失败分母。请求成功不自动奖励全部加载记忆。

### 6.3 去重和独立性

唯一反馈键为 `(memory_id, revision, source_key)`。source_key 由可信来源分组策略生成；同数据、同工具轨迹或同一试验重放即使换 request_id 也不自动变成独立样本。同一来源冲突评价按明确保守合并政策保留明细，不能重复加分。

request_id 可作最低限度的请求内去重，但不能据此声称统计独立。政策记录来源分组、适用条件/环境桶、冲突聚合与 eligible 规则；跨环境成绩不能无条件提升另一场景。

### 6.4 起步评分

对具体 memory_id/revision/适用条件桶，只统计 eligible 的 worked=s、failed=f。起步启发式为：a=s+1，b=f+1；m=a/(a+b)，sd=sqrt(a*b/((a+b)^2*(a+b+1)))；score=max(0,min(1,m-z*sd))，默认 z=1。

这是一种平滑后保守排序分，不是经过校准的成功概率，也不是 Wilson 下界。记录 score_policy_version、来源分组策略和 s/f/未知样本量；配置改变时重算派生分，原始证据不改。无样本约 0.21、一次有效约 0.43、三次有效约 0.64 是该公式的示例，不构成质量保证。新 revision 从零样本开始；不继承旧版本分数。负面质量与警示有用性分别解释。

### 6.5 警示

方法在可比条件下达到配置失败阈值时标警示，给条件和证据；不删掉有价值的失败经验。明确危险可立刻 block，无需等失败次数。blocked 不是低分仍可被排序推荐的一种情况。

## 7. 经验流水线

Worker note→受控轨迹摘要→TeamLead ExperienceReport→持久经验待办完成→按政策候选/发布→版本化反馈。report 可为 no_new_experience；动作分 new、revise（target + expected_base_revision）、conflict（并列保留）。报告内容与待办状态同事务/可恢复协议提交，不能只发易失事件。

revise 读取的基线过期时生成 draft 冲突，不覆盖现有版本；同名 Skill 更新脚本必须重新绑定批准。经验发布、反馈结算和请求清理之间有持久检查点；预算不足无法提炼时保留待办/摘要并报告，不为了删除空间自动省略经验交接。

## 8. 冲突与合并

先判断条件不同、目标取舍或同条件矛盾，允许方法长期并存。明确新版本生效后才按政策归档旧版本。S5 的“3 次成功/3 次失败”只能触发合并提议，不能自动证明因果或替用户批准；默认 auto_merge=false。合并候选需要可比证据、新的 revision 和重新验证，不能继承旧累计成绩。相似度只用于提示，不用于自动覆盖。

## 9. 第三方导入

限制包路径、大小与资源清单，拒绝逃逸/符号链接越界；按选定标准验证 SKILL.md，保存原包/来源/哈希，进入 draft。扫描脚本、联网、危险命令和指令性文字供审查。正文、脚本、执行环境依赖分别批准；不能“导入成功就自动执行”。公开样例正向导入/加载与恶意反例都要测试。

## 10. 撤销传播

1. 事务把具体 revision 或全 ID 标 blocked，更新发布元数据并递增 runtime_policy.policy_epoch；新派发立即核当前门禁。
2. 找出仍绑定该记忆的活动实例/操作，暂停新的相关业务调用；尚未启动操作取消或失效，进行中副作用按 UNKNOWN/核对处理。
3. 发可恢复通知并清理受控脚本副本。消息只是说明，删除文件也不能证明已读脚本/存活进程已失效。
4. 更新绑定、确认替代规则/方法并核对影响后才恢复；进程/权限无法隔离时明确停用该执行路径。旧缓存前缀不授予继续使用的权限。

参考 SQLite helper 可以证明 policy_epoch 比较失败，不能据此声称真实 shell/已启动子进程的撤销已经实现。

## 11. 请求清理

经验和反馈只有在批准保留范围内才留下。先完成 experience_jobs、固化 self-contained 证据与反馈，再允许删除 request 私有 load/notes/transcripts。cleanup_jobs 与经验待办在请求终态后仍可恢复；不能由删除 requests 级联抹掉唯一待办。

公开/跨项目引用不保留未授权原文。Git 仓库、SQLite 反馈、索引、快照和备份的范围分别登记；索引重建不等于能恢复被删的反馈历史。

## 12. 默认配置

默认 memory.enabled=false；governance=personal、auto_merge=false 只是后续启用起点。卡片 5/600 token、recall 10、错误触发 3、规则阈值 2000、score_z=1、rank_alpha=0.6、警示失败数 2/分数阈值 0.3、合并提议样本 3/3、摘要 21:00。统计政策版本和来源分组策略必须显式记录，作用域/版本过滤先于 limit。

## 13. 指标和边界

分别报告曝光、实际加载、声明使用、证据合格、worked/failed/unknown/irrelevant、CAS 冲突、撤销阻断及统计政策版本。评测开/关记忆、固定 Skill、关键词/语义方案时保持任务/预算/模型可比。S3 的产品验收、C++ Store/MemoryEngine、真实流程撤销和自动发布均未由本轮文档修订或 SQLite 参考测试完成。
