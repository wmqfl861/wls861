状态字段：**S1实施中**。逐能力实际状态和证据只在[STATUS](../../STATUS.md)，不在各卡堆叠增量年表。

- 继承现有 C++20、Make、CMake/CTest、严格编译/UBSan、CI 和 tests；不得用空模块替换内核。
- 按实际需要接入 presets/vcpkg 与 Asio/Beast/OpenSSL、JSON/YAML、SQLite、Schema 库；不是一次把所有未来依赖塞进基础内核。
- 新增 wlsd/wls 目标时保持当前 wls861 演示可回归。配置/文档/打包样例不自动安装服务。
- 验收：现有 `make -j2 test PYTHON=.local/test-venv/bin/python` 与 CMake/CTest 持续通过；Python 依赖按 `requirements-test.txt` 安装，新目标/依赖在实际环境构建，ASan 只有实际运行才记录成绩。

- 实现 request_snapshot/constraint_catalog、plan based_on_requirements_revision、任务完整修订 tuple、amend_dispositions、policy_epoch、experience_jobs、cleanup_jobs。
- Schema/SQL/参考 Python helper 可用于先验证契约，不能当 C++ Store 已完成；Git/SQLite/文件跨存储操作使用恢复待办。
- 验收：DB-DUR、版本/CAS冲突、旧响应不重盖、幂等冲突、删除请求不丢待办、重复迁移、合法样例与反例。
- 渐进整理：先为预约/发送/结算/附加对账定义类型边界，再按行为覆盖提取Store模块。保留事务范围、锁顺序、原事件字节、旧API和已发布SQL；不为行数大重构，不与并发租约同时放开。迁移注册表和资源安装契约在服务化前单独交付。

## S1-06 沙箱和进程

强模式正向仍需具备预先委派资源的实际环境。当前只做每操作资源限制和同目录串行，完整团队配额、历史残留扫描/恢复、真实 `/input` 挂载、TERM 宽限与可恢复资源清理仍待接入。

- bwrap、显式 envp、受控挂载、网络 none；检测实际 AppArmor/user namespace 能力。
- cgroup 委派与每团队资源限制；exec 前入组，取消确认后代实际退出。默认不允许弱隔离；显式降级时展示边界，不能假称等同 cgroup。
- 每个业务意图持久 business_idempotency_key/完整版本；run 与文件写都视具体副作用分类。workspace UNKNOWN 同样不重做。
- 输出有界、分页、超时/取消与最终结果区分；取消 Running→UNKNOWN 等待证据核对。资源清理由白名单待办完成。
- 验收：SBX-01、SEC-01、OPS-01、V3-020–023，含进程组逃逸/强模式拒绝和残留未知不清理成功。

## S1-07 工具注册和控制分支

- 静态注册业务/只读诊断/控制分类，模型不能自报类别。所有接口先核身份、对象、作用域、代次与版本。

- ack 新说明、取消、允许查询/核对不因普通预算/尚未应用/UNKNOWN被锁死；精确旧command可重试，无新说明的新ack拒绝。
- fs读写/patch/mkdir/openat2限制、run/op生命周期、ask/progress/submit/note；任意shell不可作为免门禁核对。memory未启用明确返回不可用。
- 验收：CTL-01、V3-001/019，角色/跨团队/路径逃逸及控制伪装反例。

目录工具按[ADR-074](../../adr/074-bounded-directory-tool.md)独立验收：已有目标/父缺/链接/权限、
投影深度和条目预算、目录同步/身份替换后的UNKNOWN、唯一派发与精确重放、旧冻结授权和CLI全链路。
