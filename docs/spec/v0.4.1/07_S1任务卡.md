# S1 任务卡 v0.4.1：承接 M1 的最小真实闭环

目标仍是“真实任务 → 中途改方向 → 当前版本验收与交付 → 可恢复清理”。现有 M1 已有可运行内核、构建、测试和报告，本轮又加固内核及 v0.4.1 契约；这些成果必须复用。S1 的模型/文件/进程/沙箱/SQLite C++ Store/正式 CLI 尚未因此完成。

用户已经授权本轮修订和 push。任务卡指导增量工作，不要求每张卡再次等待所有者批准，不创建空仓库，不把历史验收表改成通过。

## S1-01 构建和依赖：保留现有项目

- 继承现有 C++20、Make、CMake/CTest、严格编译/UBSan、CI 和 tests；不得用空模块替换内核。
- 按实际需要接入 presets/vcpkg 与 Asio/Beast/OpenSSL、JSON/YAML、SQLite、Schema 库；不是一次把所有未来依赖塞进基础内核。
- 新增 wlsd/wls 目标时保持当前 wls861 演示可回归。配置/文档/打包样例不自动安装服务。
- 验收：现有 `make -j2 test PYTHON=/usr/bin/python3` 与 CMake/CTest 持续通过；新目标/依赖在实际环境构建，ASan 只有实际运行才记录成绩。

## S1-02 类型与存储

- 明确 M1 旧字段到 v0.4.1 长名映射；现有 Journal 不无说明地改格式。实现 ULID/Result、完整记录和模型参数的双层 Schema 校验。
- C++ SQLite Store 默认 WAL/FULL/foreign_keys；事务 CAS、管理精确重试、业务幂等和事件一起提交。NORMAL 需显式配置及不同耐久性说明。
- 实现 request_snapshot/constraint_catalog、plan based_on_requirements_revision、任务完整修订 tuple、amend_dispositions、policy_epoch、experience_jobs、cleanup_jobs。
- Schema/SQL/参考 Python helper 可用于先验证契约，不能当 C++ Store 已完成；Git/SQLite/文件跨存储操作使用恢复待办。
- 验收：DB-DUR、版本/CAS冲突、旧响应不重盖、幂等冲突、删除请求不丢待办、重复迁移、合法样例与反例。

## S1-03 状态、事件、路由与容量

- 复用 M1 请求/角色/版本门禁、UNKNOWN、候选/审核/资源状态与现有反例。
- NEW/AMEND/REPLACE/ANSWER/CANCEL/QUERY 明确；AMEND 建全任务待处置，set_amendment_disposition 显式 update/keep/cancel，keep 也需新说明/ack；遗漏保持暂停。
- Plan 更新既有节点必须同步绑定、失效和重新应用；任务返工版本不冒充请求 revision。
- 事件与状态同事务；持久消费待办，错误/上限不自动确认事件。常态保留审核 Dispatcher/Worker 双容量，等待释放活跃名额、普通不能借用。
- 预算尝试/预留/已花费/未知分开，普通与控制通路分开；控制仍有限额和权限。
- 验收：CHG-OMIT、VER-01、CTL-01、V3-002–009 的实际实现部分，以及满载后审核仍可启动。

## S1-04 配置和请求快照

- 复用逐字段 Root 继承和思考模式；加载 YAML/功能目录并给出处。
- 请求创建冻结模板/Root/覆盖/能力表/提示/环境依赖；新团队和恢复不读新的全局默认；新请求才取新配置。
- 校验审核双名额、隔离模式、真实预算、付费重试策略、确定性能力验收器和记忆关闭状态。
- 验收：CFG-01、V3-016/017；同请求新增团队不漂移、恢复不漂移、显式迁移有新代次/ack。

## S1-05 模型接口、FakeModel、HTTP/SSE

- 定义包含调用 ID、原始版本 tuple、预算预留和配置快照的 ModelRequest/Response；每次尝试分配独立 attempt ID。
- FakeModel 按角色/序号返回文本、工具、延迟、错误、用量缺失；覆盖迟到、断流和重复结果。
- HTTPS/SSE 按所选库版本实现 TLS、超时、代理、分块解析。默认不自动付费重试；429/5xx 本身不构成重试授权。
- 工具输出在完整验证/持久化前不派发；重试不能重复已提交工具。Schema 纠错与压缩计入各自尝试。
- 验收：BUD-TRY、SSE分块/多行/中断、未知费用保留预留、脚本化模型故障和V3-026。

## S1-06 沙箱和进程

- bwrap、显式 envp、受控挂载、网络 none；检测实际 AppArmor/user namespace 能力。
- cgroup 委派与每团队资源限制；exec 前入组，取消确认后代实际退出。默认不允许弱隔离；显式降级时展示边界，不能假称等同 cgroup。
- 每个业务意图持久 business_idempotency_key/完整版本；run 与文件写都视具体副作用分类。workspace UNKNOWN 同样不重做。
- 输出有界、分页、超时/取消与最终结果区分；取消 Running→UNKNOWN 等待证据核对。资源清理由白名单待办完成。
- 验收：SBX-01、SEC-01、OPS-01、V3-020–023，含进程组逃逸/强模式拒绝和残留未知不清理成功。

## S1-07 工具注册和控制分支

- 静态注册业务/只读诊断/控制分类，模型不能自报类别。所有接口先核身份、对象、作用域、代次与版本。
- 业务再核 AMEND处置、request/plan/task/instruction、暂停、UNKNOWN、政策撤销、路径/网络和预算，派发前重复核验。
- ack 新说明、取消、允许查询/核对不因普通预算/尚未应用/UNKNOWN被锁死；精确旧command可重试，无新说明的新ack拒绝。
- fs读写/patch/openat2限制、run/op生命周期、ask/progress/submit/note；任意shell不可作为免门禁核对。memory未启用明确返回不可用。
- 验收：CTL-01、V3-001/019，角色/跨团队/路径逃逸及控制伪装反例。

## S1-08 上下文编排

- 固定工具/角色/功能/环境/规则/项目/契约/消息布局；所有当前原文与已登记约束可追溯。
- Worker追加式，管理快照式；压缩保留未决操作、完整应用绑定、有效ChangeOrder/原文、记忆load引用。
- prefix_sha256 基于实际字节，cache_identity 包括模型/协议/思考等非文本参数；所有模板/规则/Skill/环境依赖版本参与。
- 紧急政策通过门禁立即生效，不为缓存延后。环境卡片有界检查并记录能力/版本。
- 验收：CTX-01、SNAP-01、CACHE-ID、V3-025/026、约束/原文压缩保留，以及模板/规则变更时正确失效。

## S1-09 Worker运行器

- 循环复用状态门禁，初始和新版说明先ack；UNKNOWN期间可ack但不能业务，使用专用核对后才恢复。
- 等待释放运行名额；逐工具检查；持久结果后更新对话；幂等重放不执行第二次副作用。
- submit等待反馈、返工重新应用；停滞/预算/Schema错误有界，默认无付费重试。
- 验收：FakeModel 正常/AMEND漏项/旧说明/UNKNOWN/取消/问题/断流/重复调用；通过日志证实旧业务没有新派发。

## S1-10 管理运行器与验收

- Root技术路由；Dispatcher/TeamLead只处理持久待办；12次上限重排队，不能自动恢复未处理任务。
- 约束摘录校验与 constraint_catalog/constraint_refs 覆盖校验分开；未登记自然语言约束仍需语义审核，HOP不能只跑Schema。
- 正常/模板验收均核当前版本、证据和必需检查，pass不能带未解决blocker/必需fail悄悄放行。
- 接受任务时原子创建 experience_jobs；预算不足/异常时保留待办。说明变化失效候选/审核，保留历史版本高水位。
- 验收：HOP-01、CAP-01、CHG-OMIT、CLN-EXP、Q-01 及版本化返工。

## S1-11 真实交付与可恢复清理

- 包含manifest/原文/成果/证据/限制/经验，原子发布和文件/目录fsync；数据库引用与文件操作可恢复。
- 明确CLI durable_local与API/MCP显式ack；GET只读，旧包/缺回执不删除唯一成果。
- cleanup_jobs/experience_jobs 在业务终态后仍可恢复；经验/反馈结算、UNKNOWN核清、成果持久/回执确认之后才删请求私有数据。
- 每步幂等检查点；删除requests不级联丢cleanup待办；失败保留manifest/error/retry。VACUUM仅空间回收。
- 验收：CLN-01/CRASH/EXP、V3-046/050，模拟各检查点重启；真删操作只在临时测试夹具。
