## 3. 六个独立交付状态

每项状态记录对象（模块/分支/提交）、实际证据、观察时间和责任人，不能跨 SHA 沿用。

| 状态 | 完成的必要条件 | 不能替代它的事实 |
| --- | --- | --- |
| `IMPLEMENTATION_COMPLETE` | 获准范围已有实际代码/契约、必要回归，独立工程复核阻断项已处理 | 规划、接口草图、STATUS 自述 |
| `LOCAL_VALIDATION_COMPLETE` | 该输入快照的适用本地门禁全部结束，退出码、原日志、输入/二进制身份齐全 | 构建成功、部分 Passed、仍运行的后台测试、旧 SHA 的通过 |
| `PUSH_COMPLETE` | 正常推送且远端分支读回完整 SHA 与交付提交相同 | 仅本地 commit、创建 PR、强移远端引用 |
| `REMOTE_CI_COMPLETE` | 该完整 SHA 所有必需 Actions 真正完成并成功，源码快照与提交树一致 | 本地通过、其他 SHA 的 CI、工作流仅已触发 |
| `PR_REVIEW_COMPLETE` | 主协调 Agent 对具体 PR/完整 SHA 明确完成正式审核，采纳/驳回及阻断项处置有记录 | 执行者自评、工程复核无发现、GitHub 自动 mergeable、绿色 CI |
| `MERGED` | 获准合并已实际发生；记录 PR、merge SHA、目标分支及合并后身份/适用 CI | push、PR approval、分支祖先推测、规划中的合并日期 |

## 4. 每个重要模块的证据包

必须逐项提供以下八项，不把同一测试的子例计成多套独立套件：

1. 原始基线、远端分支、工作树与源输入清单；含当前实施版本/Store 和实际环境。
2. 可复现的失败反例及原字节/数据库/外部副作用检查。新设计的负例明确写 `PLANNED`。
   没有确认缺陷的文档任务标不适用，不制造生产修改或伪造红例。
3. 最小修复或实现方案、影响边界和兼容说明；未确认疑点独立记录，不冒充已复现缺陷。
4. 独立代码审核，包含审查者、具体源身份、覆盖/未覆盖路径和阻断项处置。
5. 完整适用回归：普通用户、两种 umask、严格编译、ASan/LSan、UBSan、历史兼容与
   相关集成；平台实现增加各原生平台安全矩阵。文档任务说明检查范围及运行输入未变证明。
6. 正常 Git 提交产生的完整 SHA、提交树与冻结输入核验；无无关文件、凭据或构建产物。
7. 该 SHA 的远端 CI 原结果与源码归档；本地和远端证据分列，不以配置文件存在证明运行。
8. 六状态、PR/目标分支、批准来源和剩余问题；未完成记录保留真实退出/中断和后台进程检查。

Windows 的编译通过只是构建证据。文件重解析、权限、进程树取消、完整退出、网络限制、
清理所有权与双平台一致性分别验收；Linux 的证明不能直接迁移到 Windows。
真实产品验收另按[产品验收](07-product-acceptance.md)，FakeModel、SQLite 和 loopback
TLS 只能证明对应工程契约。没有端点、模型、可信计费、预算和明确授权时，真实调用为零。

## 5. 分支与 PR 规则

先检查数据盘、空间、现有 worktree、未提交改动与正在运行的编译/测试/Agent。
记录 remote/HEAD/main/目标分支并 fetch；对其他分支的未合并提交只记录和分析，
不硬重置、删除或替别人整合。新任务用独立 worktree/分支，运行和临时测试数据库在数据盘。

R2.4 正式 PR：`feat/r2-4-demand-driven-recovery` → `main`，固定审核输入为完整 SHA。
本轮规划分支从 R2.4 的已验证提交派生，便于引用其契约与证据；若另开规划 PR，
先以 R2.4 分支为 base，只展示规划/治理差异，明确依赖 P0。R2.4 合并后由获准的
集成任务决定 retarget/rebase，重新核验实际 diff、最终 SHA 和 CI；本执行者不自动整合。

发布前核对远端 main 和目标分支，若与接手基线有差异，记录提交关系和影响并交协调者
决定兼容整合，禁止覆盖或强推。代码缺陷整改与规划文档分支隔离，先保存确定性红例，
再做最小修改、绿例和完整回归。正式 PR 描述针对最终补丁，至少包含范围、架构、安全
边界、测试/原反例、本地与远端门禁、尚未实现能力及真实供应商/付费范围。

本轮只创建/完善 PR、提交和推送；不点合并、不启用自动合并、不改变分支保护。

## 6. 不可变文件与发布后的回执

- 已发布 SQL 不改写；确需演进时另立迁移卡，定义版本、完整兼容和 populated 数据库验收。
- 历史蓝图、报告、原日志和失败证据不覆盖；修订写新版本并关联旧证据，注明结论时间范围。
- 原始请求、响应、反馈、账目和恢复见证不因评测或规划修订而重写；UNKNOWN 不补零、不改失败。
- 构建产物、临时数据库、真实凭据和环境秘密不入公开仓库。合成凭据只能出现在项目既定
  的独立测试夹具中，不能复制真实 token、私钥或生产数据作为“脱敏”样例。
- 证据归档只纳入审核过的文本命令、日志、清单和复现资料；校验成员路径、类型、摘要和
  凭据模式。读取归档取证不执行其中的代码。大二进制只保留本地身份与受控产物引用。
- 提交内报告不能伪造自己的未来 SHA。发布后回执关联完整 SHA、远端分支、Actions 和
  源码快照，可留在外部交付证据中；若另作报告提交，必须注明其对象是先前已验证 SHA。
