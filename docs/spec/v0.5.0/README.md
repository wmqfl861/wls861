## 版本与起点

本稿以 R2.4 提交 `55dc989e02f7e3e2cd1806e53d47298dd8742376` 为阅读基线。规划开始时远端 `main` 仍为 `a6b8559018a599d7a806b05942857a56d69a00ce`；R2.4 在专用分支上完成实现、本地验证、推送和该 SHA 的远端 CI，正式 [PR #1](https://github.com/wmqfl861/wls861/pull/1) 已建立，**PR_REVIEW_COMPLETE 为 PENDING，MERGED 为 false**。正式审核、合并与后继任务由主协调 Agent 决定，实时证据见 [STATUS](../../STATUS.md)、[R2.4 验证报告](../../reports/r2-4-demand-driven-recovery-validation.md)和[发布治理](09-release-governance.md)。

v0.5.0 待采纳的调整是工作顺序和验收边界：保留 Root → Dispatcher → TeamLead → Worker，保留 S1–S5 主方向；将 Windows 准备前移为贯穿阶段的工作流，将多写者风险设计与真实产品验收分别列卡。未明确修订的权限、原证据、配置冻结、恢复和结算规则继续沿用现行实施契约。历史材料中“待实现”与后来实现不一致时，按对应提交的实施契约和实际报告判定，不反向改写历史。

## 需要协调者决定的事项

1. R2.4 正式 PR 的采纳、合并及本规划的正式生效版本。
2. 并发写者选择：保留一个协调写者，还是设计多连接/多进程的请求所有权；具体租约、时钟与接管规则须先评审。
3. 首个真实端点、精确模型 ID、支持子集、可信计费来源、任务材料、预算及调用授权。
4. Windows 最低版本、CPU 架构、文件系统和工具链支持集合，以及强隔离能力档位。未支持档位保持拒绝。
5. S2 独立审核政策、S3 自动发布范围、S4 MCP/第二适配器的版本与供应商、S5 服务部署和 A2A 协议。

这些问题不阻塞已授权的文档、离线材料与证据准备。涉及真实开销、权限扩张、合并或新生产实现时，按 [09](09-release-governance.md)取得绑定具体方案的决定。
