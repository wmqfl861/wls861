# v0.5.0 五阶段路线

状态：**PLANNED / 待审**。表中新增能力均为 **NOT_IMPLEMENTED / NOT_RUN**；已有工程基础保留对应契约和历史成绩。阶段名称保持 S1–S5，不重编号已完成的 M1 或把 R2.4 分支交付当成 S1 产品验收完成。

## 1. 主线与退出条件

| 阶段 | 目标与承接基础 | 后续交付 | 阶段退出条件 |
| --- | --- | --- | --- |
| S1 最小真实闭环 | 承接 Store、角色工作流、R1 窗口、R2 AMEND/返工/恢复、R3 live/计费/单 Agent 和不可变交付 | 获准真实小任务，可靠恢复/结算，所用工具的安全执行与必要收尾 | 实际端点/模型下完成工具往返、两任务 AMEND、有限返工/耗尽、当前成果与精确回执；原记录/UNKNOWN/预算完整；所用执行路径有正反安全证据 |
| S2 并行与独立审核 | 承接 M1 有界 Scheduler 和 S1 持久事件，不将两者视为已集成 | DAG、跨功能 Root 调用、候选驱动独立审核、公平并发、Dispatcher/Worker 双容量预留、可追溯工作区/worktree | 普通两类容量满载时审核仍可启动，等待释放槽位；DAG 必需节点正确汇合；旧候选/旧 reviewer epoch 拒绝；取消、返工上限和恢复可终止 |
| S3 多层自动记忆 | 承接原经验源、上下文及原历史回读 | 规则/卡片/主动/错误触发/经验流水线，版本化反馈、CAS 修订、发布/撤销、可恢复 Git/SQLite 索引 | 权限和撤销反例通过；版本/使用/反馈可追溯；可比任务的记忆开关对照有质量、费用、耗时与未知样本 |
| S4 互通与组合 | 承接原 Root、模型与 Worker 工具边界 | MCP Client/Server 双向往返、第二模型适配器、获准工具能力组合和 Skill 接入 | 双向 submit/status/amend/answer/get/ack/cancel 保持同等权限/回执；第二适配器实测所选协议子集；外部工具不扩权 |
| S5 服务化与高级能力 | 承接前四阶段的状态、身份、调度与原证据 | A2A、daemon/API、语义检索、跨平台产品化、备份/保留/合并/严格清除等高级治理 | 逐能力独立验收，明确协议版本和部署范围；Linux/Windows 原生矩阵通过，未实现档位明确拒绝；治理不改写原证据 |

S1 可先用 CLI 和受控文件工具完成适用小任务，daemon/API 不成为其前置。需要 `run` 的任务必须先通过相应强隔离验收；只读 doctor、内部监督夹具或文件工具通过不能替代该证据。全局私有行 purge 和严格介质清除继续独立列项，工作目录阶段完成不宣称全局 CLEANED。

## 2. Windows 是跨阶段工作流

Windows 产品必须在 Windows 上原生构建和运行，**不依赖 WSL**。当前仅 Linux 实现；以下均待实施与实测。Linux 原有严格构建、安全守卫和普通用户门禁持续保留。

| 工作流 | 主要阶段映射 | 交付边界 |
| --- | --- | --- |
| P3 构建与抽象设计 | S1 起准备，随 S2 接口演进 | 原生编译/依赖/资源发现；找到必要系统接口边界；不以可编译宣称文件或沙箱安全 |
| P4 文件与进程监督 | S1 安全执行前置，S2 并发共同验证 | Handle 固定对象、ACL/SID、路径别名/Reparse Point、原生锁、创建/取消/退出证据和清理所有权 |
| P5 沙箱安全 | 依赖 P4，跨 S1–S4 的工具接入 | 受限身份/AppContainer 等能力方案、文件与网络限制、后代隔离、秘密与句柄隔离；能力不足拒绝 |
| P6 双平台一致性 | S2–S5 持续回归 | 同一业务语义与证据格式可解释；各平台独立证明隔离；不伪造相同 PID/inode/退出信号 |

完整 Windows 支持作为 S5 产品目标保留；其准备和安全实现无需等到 S5 才开始。两平台目录 `common/linux/windows` 仅为候选责任边界，实际是否移动文件由后续设计与验证决定。

## 3. 近期优先级

按 [08 任务卡](08-task-cards.md)推进：P0 正式审核 R2.4；P1 先设计并发写者风险；P2 准备真实小任务材料和计费条件；P3 建立 Windows 构建与接口边界；P4 完成文件/监督；P5 完成沙箱；P6 完成一致性；P7 按 S2–S5 拆后继卡。

这是审查和依赖顺序，不是所有工作串行等候。P1 设计、P2 离线准备、P3 原生构建调查可在独立文件范围并行；P1 未定案只阻塞依赖该所有权模型的并发写者实现。S3 的模式/用例整理、S4 的协议能力调查可以先准备，不能凭准备完成越过对应实施和外部调用门禁。具体有向依赖和批准点见 [03](03-module-dependencies.md)。

## 4. 共同不变量

所有阶段维持当前请求/任务/Actor/会话/epoch/CAS/Workspace/UNKNOWN/终态守卫。真实调用默认关闭，付费重试默认零；缺失费用不补零。原始 SQL、请求快照、调用/反馈/恢复见证与历史报告保持原样。新增能力必须先给可审阅设计、计划失败反例、兼容边界和验收矩阵，再由获准实现产生代码与证据。

各阶段的质量和费用改进只能由同条件实际样本支撑。结构测试、FakeModel、本地 TLS 和签名夹具仍有各自价值，但不填入真实产品通过栏。阶段验收和下一阶段决定按 [09 发布治理](09-release-governance.md)记录。
