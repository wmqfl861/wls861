# v0.5.0 Windows 原生支持计划

状态：**PLANNED / NOT_IMPLEMENTED / NOT_RUN**，待主协调 Agent 审核。目标是在 Windows 上原生构建、运行和验收，**无需 WSL**；Linux 现有实现、安全限制与回归继续保留。本章列设计候选及必须证明的性质，不声称所列 API 已接入或适用于所有 Windows 版本。

## 1. 当前差距与支持集合

当前 CMake 明确要求 Linux 和 GCC/Clang；`journal_posix`、`workspace_posix`、`sandbox_posix`、`cleanup_posix` 使用 Linux 接口。Store 的写锁与数据库安全打开、配置/资源读取、交付发布和 CLI 也存在平台调用。公开 Workspace/ProcessRunner 接口仍传递 `int` 文件描述符；路径身份含 Linux device/inode。仅替换文件名、添加 `#ifdef`、把 HANDLE 强转成整数或取消 CMake 拒绝条件都不足以建立 Windows 支持。

协调者须确定并记录最低 Windows 版本、x64/其他架构、工具链、SQLite/Boost/OpenSSL/libcurl/LibYAML 构建来源、支持文件系统、普通用户身份与部署模式。建议先对一个明确的本机文件系统和普通用户组合建立证据，再逐项扩展；NTFS、ReFS、FAT、网络共享、云同步目录和容器卷不能凭名称视为等价。当前这些选择均待定，未验证组合为 unsupported。

## 2. 责任边界与兼容

拟区分公共业务语义、Linux 实现和 Windows 实现三个责任边界；`platform/common`、`platform/linux`、`platform/windows` 只是可选布局。先确定对象生命周期与可测试接口，再决定是否移动文件，避免无行为收益的大规模目录重构。

| 公共语义 | Windows 实现需提供的证据 | 兼容要求 |
| --- | --- | --- |
| 请求/Actor/会话/epoch/CAS | 原 Store 事务守卫与当前宿主身份 | 不按平台删掉任何检查；临时会话不改原 actor 指纹 |
| 文件对象与作用域 | 固定 Handle、真实卷/文件身份、权限、无逃逸解析 | 不把 Windows 身份伪造为 POSIX inode；若需持久格式，先定义带版本的平台字段与迁移 |
| 进程结果 | 原创建、隔离、网络、输出、退出和工作区观察 | 不从 Win32 返回码推造 Linux signal；未知仍未知 |
| 交付/清理 | 无覆盖发布、原字节/集合、原所有权/库存和当前领取 | 不以目录存在作为收据，不扩大删除权 |
| 持久化与资源 | 原生文件锁、SQLite VFS、同步/替换、可执行文件定位 | Journal 原字节、已发布 SQL/资源 hash 和旧冻结快照保持 |

平台事实与共同业务结论分开存储：平台适配器证明观察到了什么，公共结算层检查证据是否足够。无法表示的旧格式先拒绝或走经评审的新版本，不能自动转换历史请求和根身份。

## 3. 原生构建与能力检测（P3）

P3 先建立 Windows 原生 CMake 构建与原生测试运行入口，选择 MSVC/clang-cl 等工具链的具体支持范围并保留 Linux GCC/Clang。第三方依赖版本、TLS 后端、异步 DNS、可用 sanitizer 与限制要实际检测；不能因头文件存在认定运行能力。暂不支持的检查记录 NOT_RUN/UNSUPPORTED，Linux ASan/LSan/UBSan 不因 Windows 限制被关闭。

资源发现使用实际可执行文件位置及显式路径，调查 `GetModuleFileNameW` 等原生机制；不引入 cwd/环境变量偷换资源的回退。安装包仍只包含编译认可的 SQL、Schema、公共提示词与 manifest，外部配置和凭据单独提供。原生构建验证移走源码、重定位、错误资源、链接/特殊对象拒绝与历史数据库读取。

能力报告逐项区分 available、unsupported、denied、not_checked，记录 OS/文件系统/令牌和具体机制。检测本身不授予业务执行权；可执行文件哈希、ACL、Job 条件或网络配置的只读观察不能替代实际隔离、取消和退出试验。需要缺失强能力的工具必须明确拒绝，不能自动转到不隔离执行或 WSL。

## 4. 文件、路径和所有权（P4）

### 固定 Handle 与 Reparse Point

模型路径保持受限逻辑 `/work` 相对路径，宿主在私有根 Handle 下解析。`CreateFileW`、`FILE_FLAG_OPEN_REPARSE_POINT` 与 `FILE_FLAG_BACKUP_SEMANTICS` 是需研究的组成机制；只对最终路径加标志并不能证明所有祖先安全。须验证每层 reparse tag、对象类型、卷/文件 ID、硬链接数量、拥有者与 DACL，且最终读写使用同一已固定对象。

`GetFinalPathNameByHandleW` 可用于观察和别名诊断，字符串前缀比较不能单独证明归属。设计必须说明如何防止检查后重命名、父目录替换、挂载点/junction/符号链接切换，以及共享打开模式与删除/替换的竞争。若公共 Win32 路径 API 无法提供所需的固定父对象解析保证，应单列 Handle 相对解析或受限代理方案及其兼容性评审；没有证明前不开放该写入/删除路径。

### 路径别名与文本

负例至少包含驱动器相对路径、UNC、设备/NT 命名空间、`GLOBALROOT`、用户提供的扩展路径前缀、ADS、保留设备名、尾点/尾空格、混合分隔符、大小写别名、8.3 短名、硬链接和 Reparse Point。任何允许的宿主根例外须由明确政策配置，不能由模型字符串选择。

UTF-8 与 UTF-16 转换严格且有界，非法序列拒绝；合法中文/emoji 名称在读、写、提交、库存和清理中保持原身份。不能用区域相关的小写转换或 Unicode 归一化默默改名来获得授权。按文件系统实际比较规则核别名，单独报告路径展示和真实对象身份。

### ACL、SID、锁与临时目录

Windows 权限检查基于有效令牌 SID、拥有者、安全描述符与实际访问权；`chmod`、POSIX mode 或只读属性不等同于私有 DACL。新工作区、控制库、WAL/SHM、锁、授权/账单输入和临时目录需有明确 DACL 和继承规则。检查 `WRITE_DAC`、`WRITE_OWNER`、目录创建/删除子项等权限；不允许普通广泛主体写入或替换关键对象。服务账户或 SYSTEM 的例外范围需独立决策，不默认接受任意管理员拥有的路径。

调查 `LockFileEx`/受限文件共享模式等原生锁与 SQLite 的实际 VFS 锁行为，证明同库重复写者拒绝、同进程多对象/子进程/句柄析构不会提前释放父写者权限。命名 mutex 若采用也须保护命名空间与 ACL，不能仅靠可猜名字当所有权。租约文件、主库、WAL/SHM 的路径别名及对象替换须共同验证。

临时目录用明确安全父目录、不可预测名称和独占创建，创建时设置私有 DACL；不依赖继承的宽松 `%TEMP%` 权限，不接收业务路径作为控制文件。stdout/stderr 管道、暂存文件、所有权收据和交付 stage 都纳入生命周期与容量账目。业务 mkdir 仍不产生 runtime-owned 或清理授权。

### 发布、同步和清理

研究 `FlushFileBuffers`、原生 rename/replace 的无覆盖及耐久边界，明确本机文件系统、共享句柄与杀毒/索引程序占用时的失败结果。不能宣称它们天然等同 `fsync + renameat2` 的全部保证；跨卷发布应拒绝或另立协议，不能静默复制后删除。仅 OS 报告同步成功也不等于物理掉电实测。

创建意图、创建收据、发布与登记仍遵循原恢复次序。清理先完整持久化库存，再逐项验证原 Handle 身份/内容/权限，受当前清理 claim 和 CAS 围栏。文件被替换、额外项、权限不符、共享冲突或无法确认退出时保留资源及证据；不得采用旧目录、删除未知残留或因新平台放大容量。

## 5. 进程创建、监督与取消（P4）

采用 `CreateProcessW` 等原生创建路径时，显式指定受信 `lpApplicationName`、准确 argv 编码、固定 cwd 和从零构造的环境。Windows 命令行 quoting 与不同程序的解析规则须做往返测试；不通过隐式 `cmd.exe`/PowerShell 或 PATH 查找补救失败。已批准可执行文件及 DLL/运行依赖的路径、哈希、写权限和加载搜索规则需固定，不能只哈希主程序后允许搜索宿主可写目录。

设计使用创建挂起、加入已配置的 Job、核验令牌/资源/句柄后才恢复线程的启动屏障。`AssignProcessToJobObject` 失败、宿主已处于限制性 Job、嵌套 Job 不支持或 breakaway 无法禁止时，不释放业务执行。记录“创建了宿主进程”和“业务程序已获准开始”两种事实。

继承句柄使用 `STARTUPINFOEX` / `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` 明确白名单，限定必要的标准流或控制通道；验证并发创建中的继承位竞争。数据库/写锁、凭据、Root/工作区管理 Handle、其他团队管道与 Job 管理 Handle 不进入子进程。令牌与环境不能继承宿主秘密。

Job Objects 可限制进程集合和部分资源、协助统一终止，**不是完整沙箱**。须禁止逃离受控 Job、处理嵌套/后代、主进程提前退出和子进程继续运行；用 Job 通知、查询与持有中的进程 Handle 形成完整观察。单个 PID、退出码、`ACTIVE_PROCESS_ZERO` 通知或 `TerminateJobObject` 返回成功均不能独立替代所有后代退出证明。

取消先持久化控制意图，选择经批准且有界的优雅退出方式，必要时请求终止整个受控 Job；随后等待实际进程 Handle 终止与受控集合清空，保存原退出事实。超时、权限失败、句柄丢失、部分输出或无法追踪的后代仍为 UNKNOWN。取消不证明文件效果回滚，恢复成功不证明进程退出。

原生 Handle 只在当前进程有效，不作为可序列化恢复令牌。跨重启须有原操作、Job/进程创建身份及可验证的对象所有权，防 PID 重用和同名 Job 冒领。不能重新绑定时保留 UNKNOWN，绝不按 PID 猜测杀死无关进程。需要持久监督服务的方案属于单独设计，不在 P4 中暗中引入 daemon。

## 6. 强沙箱与网络（P5）

候选机制包括受限令牌、低完整性、AppContainer/能力 SID、专用受限身份、受控文件 ACL 和网络策略；须按选定 Windows 版本验证组合性质。受限令牌或低完整性单独存在不证明文件保密性，Job 不证明文件/注册表/网络隔离，AppContainer 也不能仅凭创建标志宣布安全。

目标默认 network=none，验证 IPv4/IPv6、DNS、loopback、代理、继承 socket、子进程和被授权 broker 的旁路。若需 WFP、防火墙或宿主代理等机制，明确部署权限、能力来源、作用域和撤销；检测阶段不能自动修改宿主政策。无法在普通业务身份下证明拒绝未授权网络时，禁用需要该安全边界的 `run`。

同时验证宿主 home/凭据/控制库/兄弟工作区、注册表、命名管道/共享内存/COM 等实际暴露面与批准能力集合。保留原 runtime 文件清单、输出/进程/内存/墙钟上限、工作区前后完整观察和结算条件。安全范围以威胁模型与实际试验为准，不声称隔离恶意管理员或任意同进程宿主代码。

## 7. 分级验收与公开状态

| 门槛 | 必须给出的原生证据 | 通过后可声明 |
| --- | --- | --- |
| W-BUILD | Windows 原生编译、链接、安装/资源发现、纯业务/格式回归 | 指定组合可构建；文件/进程能力仍各自待验 |
| W-FS | 普通用户 ACL/SID、Handle 与别名、Reparse Point、锁、CAS、无覆盖发布、临时目录及故障恢复 | 指定文件系统下受控文件路径已验；不等于任意命令隔离 |
| W-PROC | 创建屏障、句柄白名单、Job 后代、输出/取消/超时、退出确认和 PID 重用反例 | 原生监督已验；强沙箱仍需 W-SBX |
| W-SBX | 受限身份、文件/注册表/IPC/网络拒绝、秘密隔离、逃逸反例和真实退出 | 指定能力档位的强执行路径已验 |
| W-CLEAN | 原所有权/库存、旧 claim 拒绝、退出/账目/回执/经验门禁、删除中断与对象替换 | 受控 workspace 阶段可清理；不等于私有 purge 或严格擦除 |
| W-PARITY | 与 Linux 同条件业务、安全拒绝及历史兼容矩阵 | 明确支持集合内的双平台语义一致性 |

P4 的监督测试只能使用私有、固定的测试程序，不得导出生产弱执行入口。每档分别给原命令、OS/账户/文件系统、原日志、返回码、源清单与二进制身份；未运行项保持 NOT_RUN。完整任务卡见 [08](08-task-cards.md)，安全矩阵见 [05](05-security-acceptance.md)。
