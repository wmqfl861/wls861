# v0.5.0 安全不变量与验收

状态：**PLANNED / 待审**。本章新场景全部为 **NOT_RUN**，新增能力为 **NOT_IMPLEMENTED**。表中“已有”指已存在契约/回归入口，具体通过范围须引用对应源码和原报告；不把本章矩阵算作执行结果。

## 1. 所有阶段必须保持的不变量

| 编号 | 不变量 | 必须拒绝或保留的边界 |
| --- | --- | --- |
| SEC-ID | Store 校验请求、角色、主体、团队、当前执行会话、epoch、政策和 CAS | 同 request ID、相同 epoch 数字、模型字段或精确旧命令均不能让旧 Actor 获新权 |
| SEC-VER | requirements/plan/task/instruction/state_version/epoch 各自独立 | 旧捕获响应不盖当前版本；AMEND 漏项暂停；keep 仍经新说明与 ack |
| SEC-CLAIM | 业务副作用和真实发送各取原事务唯一首次权 | 重放 RUNNING/旧 claim 不执行第二次；崩溃缺观察不等于未发送/未执行 |
| SEC-UNKNOWN | 未知工具效果与未知费用分别完整保留 | 取消、恢复、核账、清理或成功返回不把未知改失败/零，不恢复旧业务 |
| SEC-RAW | 请求、响应、反馈、工单、提交、原 usage/null、结算和恢复见证不可变 | 不删失败样本、不回读当前文件补历史、不改见证或旧 SQL 通过测试 |
| SEC-SCOPE | 控制库与宿主信任输入在业务工作区之外，跨请求不串 | 业务路径、兄弟目录、MCP 参数、记忆正文和相似路径不提供宿主权 |
| SEC-PROC | 只有充分的原隔离、网络、退出与前后工作区观察可形成确定结算 | 单 PID 退出、Job 终止返回、Root 核对、doctor 通过均不是完整退出证明 |
| SEC-CLEAN | 原所有权、原库存、当前 claim/CAS、成功回执、经验、账目和原退出共同授权 | 不采用旧目录、不清未知残留、不扩原清单；workspace DONE 不等于全局清除 |
| SEC-TERM | 终态只允许原捕获的受限收尾/核账控制 | 重开、旧会话或新对账不能重新预约普通业务或再次派发工具 |
| SEC-BUDGET | 每次模型尝试独立预留/结算，控制通路有限且单独授权 | Schema 纠错、压缩、审核、重试不免费；null 不等于0；预算满仍保留必要结算 |
| SEC-MEM | 记忆按范围、revision、load_id、source_key 与政策使用 | 撤销即时进入派发门禁；检索先过滤后 limit；新版本不继承旧反馈 |
| SEC-PLATFORM | 平台缺强能力明确拒绝，历史格式维持原解释 | 不启用弱路径、不关权限/TLS/sanitizer、不扩大超时来换“兼容通过” |

## 2. 失败反例的身份

R2.4 的反例和修复结果已保存在[原报告](../../reports/r2-4-demand-driven-recovery-validation.md)，不在本章重标为新的执行。其来源必须分别说明：

- 三个 R2.4 逻辑回归套件的红例使用 pristine `a6b8559018a599d7a806b05942857a56d69a00ce` 头文件、库和 CLI；最终 26 子例是 17 + 6 + 3，不是 26 个套件。
- WorkerTools 的 late-prepare 红例使用 pristine 基线 Store 和原 WorkerTools，加私有 before-prepare 调度观察点；它不是完全未插桩的原二进制。
- settlement-session 红例针对 feature v2，绿例针对加入会话键的候选，后者纳入 v3；它不是 pristine 基线反例。两侧实际使用的库、测试翻译单元及源码身份按原记录判断。
- 早期专项绿例各有其输入快照；最终 `55dc989e02f7e3e2cd1806e53d47298dd8742376` 的完整门禁另据最终输入清单及运行记录核验，不能将早期专项统一换标成最终提交。

既有函数、测试名称和报告不表示下面新增的 Windows、多写者或产品场景已测。

新实现卡必须先保存能检验设计的反例，明确“计划反例”或“已执行反例”。修复既有缺陷时在固定旧源码上复现，并检查返回值之外的数据库行、epoch、原始字节、文件/进程/发送副作用与预算。新平台尚无实现时，应先完成失败测试设计和能力缺失时拒绝的试验；不能编造“旧 Windows 版本失败”。

## 3. 统一验收矩阵

| 维度 | 现有基础入口 | 后续计划必须增加的检查 | 运行环境 |
| --- | --- | --- | --- |
| 请求恢复与身份 | `r24_*`、Store、事件/工作流、清理回归 | 空闲重复打开稳定；必要/显式恢复；旧会话精确重放；恢复与写/claim/清理交错；原见证篡改拒绝 | Linux 普通用户；Windows 原生实施后同矩阵 |
| SQLite/写者 | Store、迁移、容量、Journal | 重复 writer、连接关闭/继承、忙事务/WAL/checkpoint、崩溃、锁文件替换；新租约旧持有者复活、过期/fencing/同请求竞争 | 各原生本机文件系统；多进程夹具，不操作生产库 |
| 多角色/多请求/多团队 | EventRuntime、workflow、AMEND、单 Agent | 真并发下请求/目标/预算不串、等待释放、取消持续可达、双容量常态预留、公平与饥饿指标 | 有界 FakeModel/临时 Store；明确线程与进程拓扑 |
| 文件与路径 | Workspace、owned_capacity、交付 | Windows Handle/ACL/SID、路径别名、Reparse Point、硬链接/ADS、类型先检、实际 EOF、替换竞争和原生锁 | 普通用户私有临时目录；宽松父权限下安全拒绝 |
| 进程与退出 | sandbox/process settlement/WorkerTools | Windows 启动屏障/句柄白名单/Job 子树、终止后等待、后代逃逸、PID 重用；Linux 原强模式继续 | 私有固定程序监督与真实强环境正向分开 |
| 清理与终态 | cleanup、r24_cleanup、allocation、acceptance | 旧领取被拒；未退出/未结算/无原所有权不删除；对象替换/中断续原库存；终态无业务复活 | 临时 owned 树；真实原退出与合成记录分列 |
| 模型协议与账目 | codec/SSE/TLS/live/billing、ledger | 每适配器完整原输入、唯一发送、错误尾部、无凭据泄漏、五维未知、迟到冲突/超预留、原账本守恒 | Fake/loopback 首先；真实端点另需批准 |
| 实验身份与产品 | single_agent、billing E2E、evaluate_r3 v3 | 固定十样本位；真实原生历史/决定来源；无宿主补业务结果；全部失败/未知/未运行保留 | 本地合成工程验收与真实模型验收单列 |
| 记忆与互通 | 原 Schema/参考契约、经验待办 | revision/load/CAS/撤销/过滤前置，MCP 双向和 A2A 认证/范围/回执，外部资料注入不扩权 | 新能力实施后；当前 NOT_RUN |
| 历史兼容与资源 | 旧 Store API、framed-v1/structured-v2、安装/资源、历史评测 | 原 SQL/快照/事件/Journals不变；新平台事实显式版本；坏资源效果前拒绝 | 已支持版本矩阵，未知版本拒绝 |

并发断言以可控屏障、持久记录和实际副作用计数建立顺序，不依赖加长 sleep 掩盖竞争。计时期限仅作为原定义的业务限制或死锁看门狗；不得降低断言、关闭 sanitizer 或扩期限来制造通过。无法构造的系统故障要明确指出夹具范围，不能把合成观察当成真实 OS 事实。

## 4. 必需构建与证据维度

Linux 运行时改动继续执行完整 Release 两种 `umask 0022/0002`、ASan/LSan、UBSan、Clang 严格编译及项目适用 Make/CMake 门禁；普通用户身份必须实际核查。恢复、Store、工作流、进程结算、清理、计费、single-agent、完整计费 E2E、历史兼容与源码快照属于关联核心范围。

Windows 使用原生 runner 和普通非提升令牌，记录实际 ACL/继承权限条件；不得把 POSIX umask 数字机械映射成 DACL 安全性。增加原生构建、fs 安全、取消/退出、清理所有权与双平台一致性。支持的 sanitizer 真正运行；工具链不支持的项目标明原因，并保留 Linux 原检查，不能据编译成功宣称 Windows 运行安全。

本轮为文档规划，生产运行输入未变的证明、文档链接/状态一致性和独立复核是适用验证；不为规划伪造整套新产品运行结果。后续实现的完整门禁依据实际最终源码执行。

每次验证保存源码输入 SHA-256、构建参数、依赖/OS/UID/权限/文件系统、命令、起止时间、退出码、原日志、二进制身份、后台进程收尾、失败与未执行项。并行负载可能影响时间试验，记录真实负载并统一调度，不能仅凭推测把 timeout 归因于环境。中断的测试没有完成记录就不是通过。

## 5. 独立复核与发布

独立复核优先找 Store 绕过、旧身份重放、TOCTOU、错误释放 claim/预算、SQLite/锁生命周期、清理越权与证据换标。检查图谱时先查覆盖；缺失/部分索引以对应源码补证，不能把图谱空结果当无风险。审核者记录输入 SHA、具体覆盖、发现与未验证边界。

六个交付状态、正式 PR、合并与源码快照按 [09 发布治理](09-release-governance.md)核验。所有新能力当前保持 PLANNED / NOT_IMPLEMENTED / NOT_RUN；R2.4 的既有实现和 CI 不能代替这些未来验收。
