## 1. 目标与成功标准

系统以 C++20 实现通用多 Agent 工作流：Root 对外，每个请求有独立 Dispatcher，TeamLead 与 Worker 一对一组成团队。系统应能处理执行中的修改、验证交付、积累经验，并通过显式授权接入模型协议、MCP 和 Skill。

| 编号 | 用户可检验的结果 |
| --- | --- |
| U1 | 一条命令提交任务，真实模型完成，得到交付包、按原名导出的成果和分角色用量明细 |
| U2 | Dispatcher、TeamLead、Worker 使用三个不同模型或思考等级完成同一请求，并报告实际生效的选择 |
| U3 | Worker 能运行 Python、git 等命令完成数据处理或代码任务 |
| U4 | 中途修改要求后，未受影响任务继续，受影响任务按新要求返工 |
| U5 | 同一任务切换到另一种协议时，只改配置即可运行 |
| U6 | 两个请求、同一请求内多个团队可并行，互不串扰，并有与串行的耗时对比 |
| U7 | Worker 调用现成 MCP 服务器并使用结果，加载现成 Skill 完成任务 |
| U8 | 同类任务第二次执行时自动使用既有经验，并能查到实际使用的记忆及版本 |
| U9 | 其他 Agent 经 MCP 提交请求并取回交付 |
| U10 | 交付确认、经验完成、未知副作用核清后清理运行态，保留获准的交付、经验和回执 |

G2 的 U1、U2 采用 D-33 的具体判定：U1 在当前 main 上运行 `three.txt`，须 DELIVERED、`output_path` 非空、成果核对通过、摘要有分角色调用数和 token；U2 使用三个不同且经探针接受的思考等级完成 `three-split.txt`，核对成果并记录各角色实际型号和等级。要求拆成三个团队但模型仍合并为一项时记录为发现，不冒称多团队路径已覆盖，也不单独阻挡 G2 出口。

未提供价格表时，费用明确写“未知（未提供价格表）”；用量明细满足当前 U1 的计量要求。阶段出口允许的未达成说明按计划 R6 执行，不把说明写成 U1/U2 已通过。v1.0 仍要求 Linux 上 U1–U10 全部通过真实模型验收。

## 2. 设计原则

1. 运行时守住 §14 的不变量；其余策略按请求冻结，配置默认值与尚未实现的目标分开说明。
2. 新防护来自实际问题或安全不变量；先取得真实运行证据，再选择优化方向。
3. 宿主负责身份、版本、权限、预算、幂等和恢复；模型负责规划、判断与完成任务。
4. 模型侧契约自包含且最小：参数定义不引用模型看不到的内容；宿主已知字段由宿主补齐；强制规则写入工具说明；校验失败返回字段位置和原因。模型参数引起的失败可纠正，不借纠错绕过宿主权限或副作用守卫。（A1）
5. 请求按稳定内容在前、变化内容在后的顺序组织；原历史、原反馈和原计量事实保持完整。
6. 每个能力以可独立审核和验证的小改动交付；合成测试、协议回放和真实验收分别记录。

## 3. 架构与模块

执行关系为 `RootGateway → 每请求 Dispatcher → 多个（TeamLead → Worker）`。只有 Worker 执行业务工具；其他角色的只读检查、控制和验收仍受各自权限与版本约束。

| 模块 | 目标职责 |
| --- | --- |
| RootGateway | 技术准入、幂等、路由、交付、回执与高层入口 |
| Engine / Store | 请求状态、事件、修订、操作、模型尝试、账本、恢复与结算 |
| ContextCompiler | 完整宿主上下文、模型投影、稳定布局、历史折叠与原件回读 |
| ModelAdapter | 按冻结能力映射协议，保留原请求、响应、用量与身份 |
| ToolRegistry / Sandbox | 工具说明、Schema、授权、文件边界、受控进程与输出 |
| Delivery / Cleanup | 不可变成果、发布意图、回执、原名导出与受控清理 |
| MemoryEngine / Interop | 版本化记忆；MCP 客户端与服务端、Skill、功能互调 |

模块名称和目标能力不表示其后续阶段已经交付。

## 4. 角色与执行模型

角色职责、四套独立修订、AMEND 显式处置、唤醒、问答和恢复沿用 v0.4.1 主规格 §4、§5.2–§5.9 及角色规格。标准流程为 Dispatcher 规划、TeamLead 形成说明、Worker 执行和提交、TeamLead 检查、Dispatcher 验收、经验收尾、Root 交付。

模板计划、检查与经验合并、语义不变时说明沿用属于受控快路径。是否默认启用及各角色默认思考等级由 G3 对照结果决定，不把提案中的“默认开启前两项”提前变成当前运行默认。快路径保留全部授权、版本、候选和验收检查。

请求级并行以每请求独立目录和数据库为目标，全局登记库只保存必要的幂等映射及保留回执。团队级并行以短 Store 事务、锁外模型/工具等待和显式并发上限为目标；Dispatcher 控制事件保持串行。并行按 G6 验收，独立审核团队与 DAG 按 G10-R 推进，双容量语义继续沿用 v0.4.1 §5.10。

| 情况 | 处理原则 |
| --- | --- |
| 模型参数、Schema、工具选择、已结算工具失败可纠正 | 反馈字段位置和原因，保留原尝试；同一目标按冻结纠错上限（默认连续 3 次）继续，不能扩大权限 |
| 符合显式重试策略的连接或完整 HTTP 错误 | 只有新预留和独立记账完成后才能新发一次；当前真实运行自动重试为 0 |
| 副作用 UNKNOWN、权限变化、期限/额度耗尽、存储或不变量错误 | 停止受影响范围的新业务，保留待办和证据；核对、取消和恢复控制通路继续受各自守卫约束 |

D-32 停的是受影响请求或工作线；新请求可在新目录按既有授权继续。UNKNOWN 涉及数据目录之外不可逆副作用时才停止全部真实调用并交 owner 决定。模型调用计费未知、文件效果 UNKNOWN 和交付导出失败分别处理，不互相替代。

## 5. 模型适配

### 5.1 内部请求与协议

ContextCompiler 产出与供应商无关的完整结构化请求；适配器映射工具、系统文本、任务契约、历史、本次状态及模型选择，不替换内容、改写历史或授予业务权限。协议目标包括 Responses、Chat Completions、Anthropic Messages；其他协议有具体需求后再立项。每种适配器附官方资料派生的离线回放与合成端点验证。

思考语义和逐字段继承沿用 v0.4.1 §8.2–§8.3。不支持的等级明确拒绝；能力未知不写成支持。响应型号按冻结别名表核对。地址、凭据引用、能力、上下文和输出上限均来自外部配置，不把本次验收端点或型号固化进产品。

### 5.2 宽容解码与原件

显式选择 `response_metadata_policy: ignore-record-v1` 后，允许的元数据位置及已知 message、function_call、reasoning 项和内容片段内的未知键可忽略语义并记录有界字段路径；原字节和原项保留。未选择策略的旧请求继续原解释。已知字段的类型、身份、状态、工具配对和用量一致性检查继续生效。

未知输出项类型、未知业务事件、截断或矛盾的流不得通过丢弃部分内容而产生可执行工具。SSE 的 created、连续序列、输出增量、done 与 terminal 必须相互一致。与业务身份分离的遥测只能按已定义的窄形状记录，不能改变响应身份、输出、usage 或工具执行许可。具体协议扩展和边界以最终合入的实现契约为准；运行事实按阶段报告记录。

### 5.3 费用、失败与重试（A2）

冻结价格估算且未启用签名收据的请求按 D-9：经验证的完整输入/输出用量按冻结单价估算；缺少完整用量时以该次预留额保守记账，原始缺失维度仍为 null。缓存维度不齐时采用 D-9 的保守上界并给出配置警告。费用预留按 D-9 的请求体字节上界与最大输出计算；不能把尚未校准的 token 估算当作新的价格安全上界。

显式冻结 `cost_policy: observe-only-v1` 的获准新请求不以金额、缺价格表或费用未知阻挡运行；调用数、输入/输出 token、墙钟、独立宿主网络授权和唯一发送权仍生效。费用未知不写成 0 或免费，原始 usage 与保守额度占用分列。旧冻结估算策略、签名收据路径和历史预算不被新政策改写。

当前真实运行按 D-35 保持自动重试 0、单次期限 180 秒，并在探针确认后选择流式。通用重试能力只能由冻结策略显式启用，按 D-9 和既有分类单独预留、记账；部分响应、超时或副作用不明不构成重发许可。

### 5.4 传输

域名解析、TLS、显式地址/代理、单调截止时间、取消和原 wire 身份沿用既有受控传输契约。代理只有显式配置才启用；连接复用在 G6-E 实现和验收。解码完成、离线重放和配置合法都不等于网络授权、真实发送或 Store 接受。

## 6. 上下文、缓存与格式冻结

| 顺序 | 内容 | 更新规则 |
| --- | --- | --- |
| 1 | 角色完整工具目录及说明，固定排序 | 按冻结角色和模板稳定；本轮允许列表另由宿主计算 |
| 2 | 通则、角色提示、功能提示、环境卡稳定部分、规则与 Skill 索引 | 同请求、角色和模板下稳定 |
| 3 | 请求原文、约束、任务与当前说明构成的契约锚 | AMEND 或新说明产生有序更新，不改写旧锚 |
| 4 | 原模型输出、调用、工具反馈和按原边界插入的契约更新 | 原历史只追加；折叠保留原件与索引 |
| 5 | 本轮捕获目标、允许工具、预算、待办、未决事实及记忆卡片 | 逐次变化，末尾发送，不作为旧历史反复追加 |

团队唯一宿主绑定、审计 sidecar、内部 attempt/call 标识和冗余 base64 不为缓存目的进入稳定公共前缀；业务需要的原 provider item/call ID、原生 reasoning、文件路径及未决事实不能作为“元数据”删除。完整宿主契约、来源和原始字节仍留存并参与核验。

历史按冻结策略确定性批量折叠，不调用模型；默认折叠阈值为上下文窗口的 0.6。折叠最旧可完成前缀的一半，保留当前契约、最新需要接续的 reasoning、AMEND、未答问题和未知副作用。原结果通过带原身份校验的 `history_read` 分页回读，不读取当前文件冒充旧结果；仍超限则在新预留前明确停止。

缓存能力以实际端点探针为准。按 D-36，两组不少于 2,000 token 的相同请求在规定间隔内验证；不稳定或不支持时不再为该端点开发缓存特性，布局保持，合成缓存检查只防止退化。缓存占比目标不能代替真实验收，也不单独阻挡阶段出口。

A4 按 D-10 落到 G2 R6（实现版本 0.13.0）出口：冻结范围仅为以下六个取值。出口前允许在既定范围原地调整；出口后不重新解释已持久请求，后续扩展使用新的选择或取值，并保留旧回归。

| 冻结取值 | 语义范围与继承依据 |
| --- | --- |
| `structured-v3` | 完整契约、锚、更新、原历史及末条状态；R1 结构化上下文契约 |
| `lean-v1` | 仅模型编码副本的受控投影；宿主原件、授权和未决事实保持 |
| `fixed-role-v1` | 固定角色目录与逐轮允许子集；新增工具不暗中扩充旧目录 |
| `append-fold-v1` | 持久折叠边界、原轮次和文本分页回读 |
| `guided-v1` | 冻结角色指引及环境投影；旧快照不补入新提示词 |
| `bounded-v1` | 有界运行、捕获目标、纠错/续批、记账与停止控制 |

`framed-v1`、`structured-v2` 及其他旧冻结选择保留原字节、哈希与恢复语义；升级文档不迁移旧请求。实际冻结提交和对应回归证据记录在既有 [G2 运行报告](../../reports/g2-first-real-run.md)，STATUS 和最新交接链接该记录。

## 7. 工具、沙箱与环境

工具注册必须含名称、说明、带字段说明的参数 Schema、副作用类别、幂等属性、时限与业务/诊断/控制分类。模型无法用自填类别或“只是检查”获得权限。模型调用仍须经过完整 Schema、当前授权、绑定和首次派发守卫。

文件工具沿用限根、防路径穿越、整文件 SHA、原子写入和原捕获字节；可读文本优先返回文本。`/input` 只读接入、体积配置及环境卡实际检查是 G4-N3/N4 的目标，由相应阶段验证，不以本规格声称已经完成。

| 档位 | 选择与目标边界 |
| --- | --- |
| `strict` | 仍为默认档；保留逐文件封存、资源上限、身份检查和缺前提即拒绝 |
| `standard` | 显式选用；受控系统运行目录只读、`/work` 可写、`/input` 只读、独立临时目录；隔离和后代退出按真实证据报告 |

两档均默认断网、不继承宿主凭据或环境、不挂载宿主 home 或控制库、不静默降级。Standard 不自动等同 Strict 的强隔离声明。无可委派 cgroup 的启动与回收只在 G4-N5 的入口条件满足后推进；rlimit 或进程组不能冒充全部后代退出证据。

`doctor` 的只读前提观察与实际执行验收分开。环境卡目标是在沙箱内执行有界版本检查，记录实际工具、版本、缺失项和用法，参与稳定配置身份；卡片不是安装或执行授权。托管原生验收、每夜作业与 owner 本机能力分别记录；不因文档目标修改 owner 主机。

## 8. 生态互通

G7 实现 MCP 的 stdio、Streamable HTTP、发现与 `tools/list`、`tools/call`，以及 Agent Skills 目录加载。开工前核对当时的规范原文和版本，不把提案中的旧日期当作当前协议事实。验收使用一个现成 stdio MCP 服务器和一个符合规范的现成 Skill。

MCP 工具仍注册为有作用域的 Worker 工具；默认只允许服务器声明为只读的工具，有副作用的工具必须在功能模板逐项授权，走持久意图、唯一派发、结算和 UNKNOWN 路径。外来声明不免除宿主授权。Skill 名称和说明可稳定索引，正文按需读取，脚本经获准沙箱执行。

MCP 服务端的 submit、status、amend、answer、get_delivery、ack、cancel 和功能互调经同一 RootGateway，按 G9 落地。A2A 按 G10-A 与现成实现互通，不由当前 G2 文档提前开放。

## 9. 记忆 v1

模块边界、四类内容、四态、版本/CAS、加载绑定、可见范围与撤销传播沿用 v0.4.1 记忆规格。第一步完成 Markdown/Git 内容、SQLite 元数据和全文索引、受治理的 draft→active 写入、规则加载、卡片、`recall`/`load_memory`、使用声明及按版本统计。

## 10. 状态、存储与恢复

v0.4.1 §5.8、§5.9、§14.2 的事务、持久意图、幂等、CAS、写者和恢复围栏继续生效。每请求独立库、登记库及团队并发按 G6 推进，不能据目录分离宣称当前已没有共享写锁。

Store 拆分以已采纳的五子域范围为止；D-44 规定除非实际改动的增量构建超过 3 分钟，不继续拆分。预编译语句缓存属于等价优化，不改变事务和公开语义。本文不要求改变 Store 410；后续功能确需新表时按 D-16 提交新迁移与回归，不改已发布 SQL。

UNKNOWN 核对追加可验证事实，不覆盖原操作、原用量或历史失败，不恢复旧发送权。恢复只作用于获准范围，不围栏兄弟请求，也不将模型输出当作核对授权。

## 11. 交付、原名导出与清理（A5）

交付验收、不可变包、原始字节、技术回执和恢复沿用 v0.4.1 §10.1–§10.3。`wls run` 除交付包外，另导出 `output/<节点>/<原相对路径>`；名称、大小和哈希须与原交付清单一致。发布意图先落盘，根身份固定，原文件不覆盖，冲突和不明残留明确拒绝。

请求已经 DELIVERED 且满足唯一 CONFIRMED 交付等原门禁时，同命令重放可走核验原包和补齐导出的零模型路径；不能由重放推断此前失败或 UNKNOWN 从未发生。原请求处置按 D-31 及实际报告，新请求各自保留原授权和证据。

交付确认、经验完成、所有待核副作用解决后默认清理运行态是 G9 的目标；在该阶段落地前不提前启用。清理仅限登记所有权的工作区、输入副本和请求私有记录，保留获准交付、经验、回执及必要登记，可配置全部保留。目标默认保留期为 30 天，具体保留范围和受控清理须符合批准政策；目录步骤完成不等于全局清理完成，删除也不声称安全擦除或已删除备份。

## 12. 接口

| 入口 | 目标与边界 |
| --- | --- |
| `wls run` | 按冻结配置准入并推进到交付或明确阻塞；显示实际模型、额度、进度、分角色用量及原名成果位置 |

## 13. 配置与实际运行边界

提供不超过 40 行的入门配置，只展示已生效的模型/角色覆盖、有限额度、沙箱和保留选择；完整配置另有参考。每字段说明来源、默认值、冻结时点及“已生效/仅校验”的区别。旧请求不读取后来配置替换原快照。

当前 G2 采用 owner 指定 Responses 中转与 `gpt-6.1-sol`；不换供应方兜底。R2 三角色仍为 `max`；R3 使用探针确认后的三个不同等级，优先 high/medium/low。此为阶段验收配置，不固化为产品型号默认。

真实额度与调高权限按 D-34：单请求默认有限调用、token 和墙钟，上调范围及阶段/机动总量分别核对；每次报告实际用量、未知项和保守占用。没有价格表无需为获准 observe-only 请求重新索取密钥或金额批准，但不能取消其他额度与网络边界。

## 14. 安全不变量

1. 只有 Worker 执行业务工具；每次派发检查 Schema、身份、权限、当前版本与唯一执行权。
2. 请求要求、计划、任务、说明、应用版本及代次分别维护；迟到结果不覆盖新状态。
3. AMEND 按任务显式处置，遗漏保持暂停；控制恢复不被普通业务门禁锁死。
4. 副作用先持久意图；不能证明的结果保持 UNKNOWN；核清前不自动重做。
5. 原请求、原响应、原反馈和原用量不可改写；未知保持 null，保守占用不冒充实际量。
6. 发送前预留适用额度、领取唯一发送权；observe-only 只按明确授权解除金额门禁，每次尝试仍记账。
7. 凭据不进入仓库、数据库、日志或提示词；外部输入不能扩充工具和宿主权限。
8. 文件工具限根，进程默认断网；控制库在业务工作区之外；隔离不静默降级。
9. 交付先意图后发布、逐字节核验并绑定回执；只清理登记所有权及批准范围。
10. 自动测试使用自造 fixture，不调用真实模型；历史、已发布 SQL 和原失败记录保留原义。

## 15. 阶段与验收安排（A3）

[11-16 `04-plan.md`](../../reviews/claude-2026-11-16/04-plan.md)是唯一前向计划，顺序为 G2 → G4 → G3 → G5 → G6 → G7 → G8 → G9 → v1.0 → G10。允许真实运行线与代码线并行，在制 PR 不超过 3 个；G4-N1/N2 可与 G2 并行，其他工作按实际入口条件推进。

每个接真实模型的阶段先通过合成端点上的[朴素模型剧本 P7 八场景](../../reviews/claude-2026-11-13/03-fix-list.md#p7-g2-预演门禁朴素模型剧本)。八场景仍为预演依据，包括参数/路径纠正、TeamLead 拒绝 partial 后完整返工、带用量的 incomplete，以及断流后的同命令恢复；本节仅概述，不缩减原验收范围。脚本按冻结的策略运行；独立测试重试能力不改变当前真实运行自动重试 0。合成通过不替代真实调用、成果核对或用户价值验收。

G2 R6 在 U1/U2 达成，或同一报告明确记载未达原因后，由 root 依计划确认出口处置；同时完成六格式冻结、蓝图迁移、旧 ROADMAP 原字节归档后压缩摘要、相关入口更新和版本 0.13.0 的出口记录。真实提交、回归范围、R2/R3/R5 结果和审核结论只记录在 STATUS、阶段报告及最新交接中。

阶段版本和 main 上带注释标签按 D-43；不创建 GitHub Release。v1.0 还须 main 完整矩阵、每夜原生沙箱与 TSan 通过、上手说明不超过 100 行，owner 审阅验收报告；是否对外发布另由 owner 决定。G10 默认按独立审核/DAG、向量检索、A2A、Windows 顺序，Windows 原生覆盖构建与文件流程，命令执行先经 WSL。

## 16. 度量与优化

每个真实请求按角色记录调用、纠错、重试、输入/缓存读/缓存写/输出 token、推理 token（有值时）、耗时、返工、未知项和适用的费用估算；保留实际型号、思考等级及配置来源。请求体按工具、系统、契约、历史、本次状态及外层封装分别计量，避免把截取样本当作完整序列。

D-37 要求先从原捕获请求形成 A-1 调用表和 A-2 历史字节表，再为 R5 选最多三个小优化。每项有同一组原输入的离线前后字节对比，合入后复跑 R2 取得真实 token 对比；无改善的项目回退。请求未完成或 usage 缺失时，真实改善结论保持未知，保留或回退决定及理由写入同一报告；不得以部分用量或离线字节代替完整比较，也不得据此断言优化无效。E-9 多工具应答留到 G3，冻结后使用新取值。真实缓存、总 token 与墙钟目标是优化方向，不篡改为已达到的门禁。
