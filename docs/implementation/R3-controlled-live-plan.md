# R3.3 受控真实闭环与 R1.4 管理视图实施计划

本文是各节点的开发计划与验收契约，不是测试通过记录。R3.3a 的实现契约已另列于
[HTTPS 组件](R3-https-transport.md)，实际执行证据见[传输报告](../reports/r3-https-transport-validation.md)；
R3.3b/c 与下文长任务前置继续待实现/验收。当前能力见
[STATUS](../STATUS.md)，现有离线边界见 [R3.1/R3.2](R3-offline-responses.md)；
原 Store 的[请求恢复](S1-request-recovery.md)、[容量窗口](S1-capacity-windows.md)
和[不可变交付](S1-acceptance-delivery.md)继续适用。

## 1. 拆分原因与依赖

现有协议组件能编码请求和回放响应，尚不能证明实际请求已发送、供应商已接收或用量已结清。
Store 目前只准入 FakeModel；已有结算记录只允许原完整指纹重放，未知用量继续保留预留并
阻止要求完整账目的收尾。开放真实网络前必须同时解决准入、发送事实和事后用量核对，
不能通过修改原响应、把 null 写成 0 或单独提供可绕过 Store 的 transport 入口解决。

| 节点 | 前置依赖 | 交付物 | 无付费参数时可推进 |
| --- | --- | --- | --- |
| R3.3a 传输组件 | R3.1/R3.2 的严格协议与原始字节契约；先定义 R3.3b 的发送/结算边界 | 可注入本地模拟服务的 HTTPS/TLS 组件、实时取消/deadline、分阶段观察及故障夹具 | 全部实现、普通用户集成测试、故障注入和 CI；生产调用入口仍关闭 |
| R3.3b Store 集成 | 原请求冻结/身份/CAS/预算机制；先评审附加用量核对契约，再消费 R3.3a | 冻结 profile、attempt 预约、唯一发送权、实际传输证据、原响应结算与附加对账 | 使用临时 SQLite、合成凭据和本地服务验证全部状态转换；真实开关默认关闭 |
| R3.3c 小任务与对照验收 | R3.3a/b 的对应提交门禁；选定端点能力/凭据/预算及明确调用授权 | 一组预先固定任务、多角色与单 Agent 同条件记录、实际交付及限制报告 | 先做任务集、评分规则、账本与报告框架；付费执行等待所需配置和授权 |
| R1.4 管理视图容量 | R1.1 原证据回读、R1.2 结构化输入、原管理目标捕获/CAS | Dispatcher/TeamLead 的有界管理视图、受控回读及预约前超限诊断 | 可与 R3.3a/b 并行，全程使用 FakeModel 和本地原记录 |
| 工作区容量后继 | R2a.2 原所有权/代次和不可变清理库存 | 新准入贯通容量或有界清理分片、明确的旧工作区超限出口 | 仅临时目录/SQLite 的边界与中断测试，不需要真实供应商 |

R1.4 是长任务验收的前置条件；完整当前契约已能容纳的小任务可先执行 R3.3c。
不能用小任务通过来宣称长任务容量已解除，也不能因等待 R1.4 而停止本地协议和账本开发。
CLI 可承载这些切片；wlsd、API 和并发服务化继续后置。

## 2. R3.3a：HTTPS/TLS 与实时中断组件

### 产出与边界

- 输入仅消费已验证的编码请求及明确的传输配置；组件不决定业务准入、模型重试或工具派发。
  本地测试通过后仍不能形成独立 live CLI；真实调用必须经过 R3.3b 的原 Store 路径。
- 使用受信 CA 和主机名验证；测试证书只放在自建夹具的显式 trust 配置中。默认拒绝重定向，
  如以后支持代理或重定向，须独立配置、测试目的地址和凭据作用域，不能靠环境默认值悄悄启用。
- 同一个单调 deadline 覆盖连接、TLS、请求写入、响应头和响应体；取消在每个等待边界生效。
  实际耗时来自执行器观察，回放提供的 elapsed 不得转写为真实传输时钟。
- 网络分块交给现有有界 HTTP/SSE 解码器；头、体、事件、输出与累计原始字节各自有硬限额。
  取消、deadline、超限和解码失败不能释放部分工具；有效终态之后收到的非法尾部仍使响应不可采用。
- 记录连接/握手/写入/读取/取消发生到哪一步、已观察到的字节范围及截断事实。
  “本地写调用完成”仅证明该观察，不能命名为供应商接收确认或计费凭证。
  凭据值不进入日志、报告、请求快照或完整记录的可分享字段；认证引用与安全的请求表示分开。

### 必须能拒绝或正确保留的反例

本地模拟服务覆盖证书不可信/主机名不匹配、响应头超限、HTTP 错误、半个 UTF-8 字符、
分块边界、响应体超限、连接后不返回、请求只写入一部分、取消与终态竞争、已发送后断流、
SSE 完整终态后的多余数据。任何不确定发送状态都不能被解释为“没有计费，可以免费重试”。
协议变更须核对所选官方默认事件字段并保存有来源的最小 fixture，扩展元数据与业务字段分开验证；
不能仅用自行简化过的 fixture 证明兼容性，也不能为接受未知字段而关闭原严格语义检查。

### 完成条件

普通用户下可重复运行本地 TLS 服务与故障夹具；每个中断阶段均有明确结果、字节范围和时间范围，
无未关闭连接或无限等待，原 HTTP/SSE 回归继续通过。报告区分本地传输观察与供应商实测；
没有实际端点或凭据仍可完成本节点，且 fake-only 的生产准入边界不因此解除。

## 3. R3.3b：原 Store 准入、发送事实与附加用量核对

### 先定义不可变记录与对账投影

在放开真实准入前，先确定以下持久化契约及兼容策略。若需要新结构，新增迁移，
保留所有已发布 SQL、旧快照、原调用、原响应与原结算字节；不得在旧结算行内覆盖未知数值。

| 记录 | 必须保留的身份或事实 | 可变性规则 |
| --- | --- | --- |
| 准入快照 | 外部 profile 的协议/映射版本、模型、端点/路径、能力依据、时限/容量、认证引用名称、预算与重试策略 | 请求冻结；以后配置更新只影响新请求。真实凭据值不入快照 |
| attempt 预约 | 原调用 ID、独立 attempt ID、原 request/plan/task/instruction tuple、代次、配置 hash、预留维度 | 网络发送前持久化；真实 profile 不能给旧 FakeModel attempt 改标 |
| 发送与接收观察 | 原 attempt、编码请求 hash、实际传输阶段、原响应字节及其范围/截断、观测来源 | 追加原事实；本地编码 hash、发送观察与供应商回执使用不同含义和字段 |
| 原始结算 | 原响应状态、原 usage/null、原 settlement hash、当时业务可采用性 | 原记录不可改写，精确重放仍返回原结果 |
| 附加用量核对 | 原 attempt/settlement hash、独立核对 ID、幂等键、预期核对版本、来源与证据 hash、逐维度已知/未知金额 | 追加事件或记录，以 CAS 更新独立账本投影；同键异证据冲突，证据不能由模型自称有效 |

核对必须同时记录原值、新的有依据值和账本差额。只对新确认的维度释放对应预留、调整已花费；
其他维度继续为未知。实际费用超过原预留时仍保留实际账目、告警并停止新付费准入，
不能为了满足预算上限截短真实支出。后续证据矛盾保持待核对，不覆盖前一份事实。
没有可验证来源则保持未知；估算值不得填进实际用量字段。

对账不会使旧模型结果重新取得业务资格，不会清除工具 UNKNOWN，不会再次派发工具，
也不修改已经发布的包或原用户回执。新增查询须同时显示原结算和当前核对状态；
未来清理消费的是已完整核对的账本，仍必须独立满足原退出证据、交付和所有权门禁。

### 事务与发送次序

先核冻结 profile、最新政策、完整版本和预算，再在短事务中保存 attempt 与预留。
发送前取得一次性发送权并再次核原绑定；网络等待不放入数据库事务。
崩溃后不能从“没有响应”推断“没有发送”，不能重新领取旧发送权重复请求。
收到迟到响应时仍按原 attempt 保存用量和原始字节；只有当前业务绑定全部成立才可采用工具。
已发送后解码/持久化失败须阻止新的相关业务并保留未决状态。
429、5xx、超时、断流均不自行增加重试次数；所有新尝试再次准入并独立预留。

### 失败反例与完成条件

用本地服务和临时 SQLite 验证：预约失败时零发送；唯一发送权重放时零重发；
预约后/发送中/原响应保存前/用量核对事务内崩溃；AMEND、取消、恢复或政策撤销后的迟到响应；
同键重复与异证据冲突、部分用量未知、超预留真实支出、终态后的原 attempt 对账，
以及 OneRequest 接管和对账不改变兄弟请求账本。

完成必须给出账本守恒检查、原证据字节不变检查、失败事务整体回滚和旧数据库兼容结果。
原事件/工具/历史/收尾回归继续通过；不得通过填 0、删除审计、放开 UNKNOWN、扩大清理权限或
弱化权限断言使测试通过。真实能力开关只能在该整条路径可用后由显式配置启用；
没有付费参数仍可完成实现和模拟集成，默认值保持关闭。

## 4. R3.3c：获准小任务与单 Agent 基线

执行前固定任务材料、验收规则、端点和精确模型标识、工具与环境、每条件尝试/费用/时限上限、
取消规则及是否允许重试。能力声明只用于选择待验证项；未知必需能力不能当已支持。
测试范围与预算获准后才解析真实凭据和发起调用。
profile 的 reasoning effort 配置不等于支持 reasoning 输出项；首个 live 配置须证实所选模型
能使用当前文本/function_call 子集，否则先单独版本化扩展并验收协议。若调整带历史工具消息的
tool_calling 能力检查，先明确该能力描述当前可调用工具还是历史表示，不据名称猜测并放宽门禁。

至少覆盖一组可明确验收的小任务：原生工具往返、两任务 AMEND 部分处置与继续、
否定验收后的有限返工、返工耗尽到用户问题、版本正确的成果交付/精确回执。
模型决策必须来自实际调用；固定 Fake 脚本和宿主 dispositions 文件仅作为对照或故障夹具。

单 Agent 条件使用同模型、同材料、同工具权限、同验收规则及等额预算上限；
保留各自协议开销和实际消耗，不靠删掉失败/未知样本制造优势。逐任务报告是否通过、
端到端耗时、各角色/条件尝试、token、费用已知/未知、返工、缓存定义与收尾状态。
样本不足时只报告观察，不能推导普遍的质量提升、成本降低或并行收益。

完成条件是每项均有实际结果与原 attempt/交付证据映射，所有失败和未执行项明确保留，
且能从账本重建统计。供应商验收只适用于该端点、模型和已验证子集，不能推广到所有兼容端点。
本地框架可先完成；没有凭据/预算/授权时将真实执行保持待办。

## 5. R1.4：管理角色的有界当前视图

现有 Worker window-v1 不改变 Dispatcher/TeamLead 的全量管理契约。管理视图应单列实施，
先用累计已回答问题、历史候选和多次 AMEND 构造可重复的超限案例，再定义下列选择规则：

- 当前原始要求与有效约束、当前计划/说明和绑定、未决问题/操作/用量、一次管理动作捕获的
  完整目标及其必要原证据保持完整。缺证据不得产生有权限的管理决定。
- 仅旧的已完结事实可投影为有范围、有数量、hash 固定的引用；不重读当前工作区冒充旧成果。
  回读绑定角色/请求/目标/原版本和当前政策，记录反馈并计入正常调用与控制查询限额。
- 管理调用前先计算各段字节、总容量和省略范围。若完整当前契约仍放不下，在预约前返回
  可操作的阻塞原因及超限部分，保持待办；不裁剪约束、不反复付费尝试同一超限输入。
- 新策略明确冻结，旧快照保持原解释；任何分批读取都不能从最新行补写旧模型的目标或 CAS。

反例必须覆盖跨请求/角色回读、旧 hash/目标代次、遗漏未答问题或 UNKNOWN、引用缺失、
回读期间政策变化、旧反馈缺失、超限前零新增预约，以及管理响应期间 AMEND 后提交被拒。
完成条件是有限窗口内长流程跨重启继续推进、原记录可完整回读、当前契约未丢失，
且原管理目标捕获和事务 CAS 回归通过。实际模型是否能有效使用引用另列质量验收。

## 6. owned 工作区贯通容量

当前 [WorkspaceLimits](../../include/wls/workspace.hpp) 默认允许 20000 条目，
[CleanupLimits](../../include/wls/cleanup.hpp) 的清单最多 4096 条目。合法业务树可能在收尾时
碰到更小的清理硬上限；保守拒绝会留下资源，不等于数据丢失，也不能通过跳过库存检查解决。

先用临时 owned 工作区复现合法树超过清理容量的场景，再评审两种实现选择：新请求冻结一套
从分配、业务写入、完整库存到删除都可承受的容量；或建立有界分片和不可扩展的原总清单。
选择必须说明旧请求/已有工作树如何保持原权限与证据，不能把新更小的默认值偷偷写回旧快照，
也不能把较大的 Workspace 上限直接用作新增删除许可。

产出为贯通限制的配置解释、效果前准入与运行器检查，或明确的分片格式/检查点/恢复 API。
反例覆盖恰到上限、合法超限、库存中断、删除中断、条目增加/身份替换、容量配置更新及旧库存重放。
完成条件是超限时明确可操作且无部分无记录删除，选定方案可跨重启完成，全部目标仍来自原所有权
与持久库存。此项是大工作树长任务的前置；小工作树可先验收，现有清理权限不随计划扩大。

## 7. 强环境、工程整理和完成定义

强 bwrap/cgroup 部署正向、退出/逃逸与残留恢复属于独立部署验收，doctor 的只读观察不能替代。
只用已支持文件工具的小任务可以与该部署工作并行；任何需要 `run` 的实际任务必须先具备相应
强隔离能力及正向证据，不能在 live 验收中启用弱回退。供应商协议通过也不增加工作区删除权限。

Store 整理按稳定接口与行为覆盖推进：先明确模型预约/发送/结算/对账的类型边界，
再按实际依赖提取账本、工作流或操作模块。每次提取保持事务范围、锁顺序、原事件字节和旧 API
兼容，并用原故障/恢复测试验收；不用文件行数作为大改理由。服务化前补迁移注册表与资源安装
契约，保留单写者行为，不能同时借重构放开并发租约或改写已发布 SQL。

每节点单独提交契约、源码、聚焦反例及实际报告。最终验证使用同一交付源码的普通用户、
宽松 umask、严格编译、ASan/LSan、UBSan 与 Clang 门禁；本地模拟、真实供应商、强沙箱部署和
单 Agent 对照分列证据。计划写出的反例、完成条件及框架存在均不等于已经执行通过。
