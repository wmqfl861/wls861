# 请求限定的写者恢复（R2.2）

依据 [ADR-071](../adr/071-request-scoped-recovery.md)，整合实现0.8.1-r2.2，目标蓝图v0.4.1。
当前进度见[STATUS](../STATUS.md)，实际验证见[报告](../reports/r2-integration-validation.md)。

## 接口与作用域

`Store` 最后一个可选参数为 `StoreRecoveryScope`，默认值保持既有行为。

| 选择 | 启动行为 | 写入权限 |
| --- | --- | --- |
| `AllRequests`（默认） | 原全库活动请求和终态待办恢复 | 原可信宿主API规则 |
| `StoreRecoveryScope::request(id)` | 仅恢复该请求及归属的操作、调用、事件领取、经验/清理租约 | 只允许目标请求；禁止新准入 |
| `StoreRecoveryScope::admission()` | 不恢复既有请求；空库可正常初始化 | 仅admit及其精确重放；禁止执行身份及所有其他写接口 |

所有写模式都持有**同一个数据库级独占writer-lock**，并保留WAL/FULL与事务CAS。
这不是按请求并行租约或网络认证边界。只读连接不接受写者恢复范围，继续使用原ReadOnly行为。
请求范围限制可信宿主的写操作；不宣称所有诊断/原记录读接口都变成新的读权限隔离层。

## 恢复与版本

选中活动请求仍执行原恢复事务：提升Dispatcher/team执行代次，取消未派发PREPARED，
将运行中/取消中不确定操作围栏为UNKNOWN，将PENDING模型调用按未知用量保留预留，释放旧事件claim。
同语义说明只由恢复事件授权投影到新代次，Worker必须重新ack；原说明和反馈不可变，工具额度和预算不清零。

未选请求的RUNNING/PENDING可能仍描述崩溃前事实；这不表示它可安全执行。当前限定连接
拒绝为它发行身份，亦拒绝无actor的结果保存、核对、结算和反馈。以后打开它时先恢复再发身份，
旧epoch结果只能保留为迟到原件，不能采用，也不自动核清UNKNOWN。
WAITING保留原generation，AMEND未处置任务仍暂停；恢复本身不产生新TeamLead模型调用。

终态请求不重启业务。只恢复其遗留事件领取、未完成experience_jobs/cleanup_jobs租约和待定调用用量；
有待完成经验时追加原控制事件。FAILED/CANCELLED/SUPERSEDED仍创建原保留收尾事实。
其他请求（包括终态）的任务、事件、call_attempts、原反馈和收尾作业均不因本次恢复改写。

## CLI与结构升级

所有带目标请求的写入口使用OneRequest：run-fake、pump-fake、amend、cancel、answer、wait/wake、
reconcile-op、容量检查点、交付发布/确认、工作区分配/清理。已有只读前置检查保留；事务内再次授权。
submit使用AdmissionOnly。查询保持ReadOnly。

`wls init --db ...` 是**明确的全库维护**，保持默认AllRequests，可能提升全部活动请求代次。
限定写者遇到带请求的旧结构版本时，在数据迁移前拒绝，要求先显式init；避免旧事件迁移引导
顺带为其他请求追加事件。已知SQL和哈希规则不变，不改407迁移或原冻结快照。
OneRequest要求数据库已存在且受支持：缺文件不创建，空文件不初始化，未知request拒绝。
锁文件权限规范化、SQLite连接/完整性检查仍可执行；“不变”指业务持久行，不保证WAL等文件的逐字节静止。

## 原子性与验收

恢复、租约推进、代次/操作/未知用量及事件追加在同一事务中完成；任一失败整体回滚并释放写者。
新测试先在19ea603实际CLI复现六项兄弟请求扰动，再验证修复；覆盖当前/兄弟进行中调用、
迟到响应、控制等待、未处置AMEND、终态作业、跨范围写/重放、恢复事件故障和迁移拒绝。
合成的进行中操作/经验租约仅验证恢复存储语义，不作为真实进程退出或验收通过的证明。

## 尚未改变

默认嵌入式Store不传scope仍恢复全库；使用方需显式选择范围。被选中的活动请求每次仍推进执行代次，
不声称“只有发现未决工作才恢复”。数据库仍只有一个写者；模型判断质量、强沙箱正向部署、
真实供应商及PREPARED分配恢复仍独立验收。拒绝后继已与本范围在 R2.2 联合测试。
