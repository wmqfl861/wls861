## 4. M0/M1 本批采用的工程边界

以下内容是本次工程契约，**是开发与验证目标，不是已通过声明，也不是生产政策定案**。

### 4.1 单机内核与持久化

本批选择 Linux、C++20 和无第三方库依赖的构建，验证入口为 `make test`。标准库、Linux 系统接口及开发工具链仍是运行和构建前提。平台文件操作独立于业务内核。Make 主验证路径不依赖 CMake；另提供 CMake/CTest 入口。历史材料中的 SQLite 等仍是实现建议，本批不据此引入运行库依赖。

持久化采用小型、版本化、带校验的 append-only Journal。一个完整帧表示一次逻辑事务，状态和事件一起保存，成功返回前同步。恢复只重放完整且校验正确的帧；不完整尾帧按契约恢复，完整损坏帧拒绝加载。操作系统独占文件锁防止两个运行时同时写同一 Journal。

Journal **不是 SQLite，也不是生产数据库的最终选型**。它用于有界、合成测试数据；当前契约不提供压缩、查询数据库、备份、加密、生产保留或介质擦除能力。测试历史保留在生成的临时目录中，不用于真实用户任务。

### 4.2 身份、并发与工具状态

`Actor` 是受信宿主传入的上下文。内核核对角色以及持久化的 Root、请求、团队和主体绑定，但这不等于已实现外部认证。恢复和资源核对接口是宿主接口，不能注册为 Agent 业务工具。

状态提交由内核互斥保护且保持短小；模拟执行回调在锁外并行。调度器有有限队列和槽位，为审核、交接类工作预留容量；相同资源键的回调串行，不同资源键可以推进。这不是分布式调度，也不代表已经验证真实模型并发或资源公平性指标。

业务操作只模拟准备、派发、结果和未知状态，不运行 Shell、MCP 或远程模型。派发时重新核对权限、要求、计划、应用版本和租约；准备记录不代表操作已经执行。恢复后的在途操作成为 `UNKNOWN`，需要运行时核对，不自动重做副作用。取消和替换会隔离旧代次，不声称已发生的操作被撤销。

### 4.3 验收、交付与资源生命周期

候选版本、摘要和当前要求绑定验收；候选变更使旧批准失效。本批用独立指定的审核团队与非空证据引用测试验收关口，这只是合成契约，不能代替 M3 的真实审核和工作流，也不把所有业务的生产审核政策提前写死。

业务完成须有匹配当前成果的、所属 Root 明确提交的合成交付回执。资源状态独立推进至 `DRAINING`、`STOPPED`、`CLEANING`、`CLOSED` 或 `CLEANUP_FAILED`；未知操作须先核对。M1 不终止真实工具进程，不删除用户目录，不提供真实外部收件或严格数据清除。

模型注册使用符号化测试配置；没有供应商端点和凭据。工具授权按角色、系统允许列表和请求允许列表求交集，模型继承不会授予工具权限。经验发布、长期保留、Wiki/RAG 和实际模型适配属于后续批次。
