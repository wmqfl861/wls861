## 1. 签名计费证据与连续工作流

新增版本化的受信中转账单适配契约。外部信任政策限定签发方、账户、公钥、执行类别和
原冻结 profile；每次发送采用显式冻结启用的唯一 billing challenge。签名证据只使用
中转可观察的 challenge、原 wire 请求/响应身份、响应 ID 和五维 nullable usage，
宿主验证后映射到原 attempt 与原不可变 settlement。

同步收据由原 TLS 响应保留的有界 HTTP 字节提供；晚到收据由独立 CLI 控制入口核账。
同一账单身份必须在原 Store 事务内检查归属，不能在另一 attempt 或请求重复认领。
原金额与未知值不改写；部分未知、争议、超预留和预算耗尽继续阻止新的调用。
对账不重新应用旧响应、不清除工具 UNKNOWN、不改变交付或回执。

`pump-live` 的新增信任输入由版本化宿主授权绑定其一次捕获的原字节 hash；旧授权与
未启用 billing 扩展的 profile 保持兼容。全部外部文件在写者接管前做有界普通文件
检查和完整预检，使用前再核请求绑定。凭据仍由原冻结引用解析。

该接口是本项目新增的中转适配契约。真实中转服务的签发实现、信任根与账单现场验收
仍需独立成立；本地测试密钥或有效合成签名不能被称为实际供应商费用证明。
详细协议与安全边界见 ADR-088 和 `R3-signed-billing.md`。

## 2. 一个逻辑 Agent 与原角色权限代理

新请求可显式冻结 `single-agent-role-broker-v1`。同一模型与 reasoning 的一个逻辑
执行者串行处理原角色目标，原 Dispatcher、TeamLead、Worker 身份继续授予不同权限。
每次实际输入包含该请求所有已闭合的前序原模型响应与原工具反馈；旧完整上下文不递归
嵌入，失败调用不被省略。只给调用贴共同 ID 不能形成这个模式。

逻辑 ID、全局序号、前链和历史内容身份随原请求信封持久化；预约事务重建并核对
实际历史与高水位，拒绝漏项、分叉、旧捕获及错反馈。未结算或缺原反馈的前序调用
阻止新预约。正常闭合历史可跨批次和重启继续；超限在预约前明确退出。

新增 v3 评测，逐项核对实际模型输入和原业务来源。固定五任务、两个条件的十个样本位
全部保留；共同条件只排除明确的逻辑拓扑变量，其余模型、材料、权限、预算和上下文
政策继续匹配。v1/v2 原身份解释和历史成绩不变。
详细契约见 ADR-089 和 `R3-single-agent-baseline.md`。

## 3. 实现与并行边界

| 工作 | 主要范围 |
| --- | --- |
| 计费模块 | profile/编码/HTTPS 的 opt-in challenge，签名核验，独占收据归属，核心回归 |
| 单 Agent 模块 | 冻结策略，共享原生历史，原预约事务连续性，显式运行器，v3 评测及回归 |
| 集成 | CLI 输入/授权/晚到核账，CMake/Make 注册，版本/状态/蓝图和验证报告 |
| 独立复核 | 真实 CLI + local TLS 双条件五任务，错绑、重放、缺证据与权限反例 |

原 SQL、原快照、原结算、vendor 与 handoff 保持发布时字节。Store 仍采用独占写者；
本批不借此放开并发租约、增加自动付费重试或实现 daemon/API、私有行 purge。

## 4. 完成条件与发布

实现源码、版本化契约和有意义的反例一起交付。验证使用普通用户、宽松 umask、
严格 C++20、ASan/LSan、UBSan 和 Clang；保留旧回归和原失败记录，输入清单固定本批
最终源码。新能力的专项与全树验证分开记录，不把方法数与套件数相加。

联合验收使用自建 loopback TLS、临时密钥、临时 SQLite 和业务文件，真实供应商调用、
付费调用和生产数据操作均不属于本批开发验收。合成双条件运行只验收工程链和实验
身份，不得推导真实模型质量、成本优势或强沙箱部署完成。

统一推送两模块的源码、测试、契约与实际报告，再核远端 SHA、tree、工作区和该最终 SHA 的
六路 CI 及源码快照。远端若已前进，先同步审查，禁止覆盖未见提交。
