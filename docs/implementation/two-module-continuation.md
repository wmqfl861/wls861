## 模块一：原 Store 的受控模型工作流

落实 R3.3c 的执行前置，把已有原预约、唯一发送权、传输观察、不可变结算与
Dispatcher / TeamLead / Worker 事件工作流接通。

- 将完整上下文与目标捕获和原预约分开，保留 Fake 入口及旧 API 行为。
- live 路径先核授权、冻结配置、当前绑定、事件 claim 范围及预算，再解析明确的认证引用。
  唯一发送权和原观察仍由 Store 保存；网络不在数据库事务内。
- 新观察由原响应接纳路径首次结算并应用；已结算且没有原反馈的调用仍保守阻塞，
  不把重放变成再次派发工具的许可。
- 沿用原业务守卫，提供受信宿主的独立用量核验 hook。未知、争议或超预留阻止下一次
  付费调用；缺少费用证据不补零、不用价格估算冒充实际支出。
- 提供显式 `pump-live` 宿主入口，授权文件绑定原 request / 配置 / 模型 profile 及批次上限。
  默认无网络授权；端点、模型、CA、认证引用均来自外部冻结配置。
- 批次调用数、每任务 Worker 调用数、总墙钟及取消有界；错误停止批次，不隐式重试。
  输出只含安全运行摘要，原响应和私有证据留在原 Store。
- 评测新增版本化的模型决定来源契约：原响应、捕获目标、原反馈和业务结果必须能关联。
  保留旧 v1 的结构判据解释，不把合法宿主控制动作当成实际模型决定。

验收使用临时 SQLite、合成凭据和自行创建的 loopback TLS。覆盖模型工具往返、
管理工作流、原反馈、原账本守恒、账目未知出口、当前版本失效、错误零重试、
授权和预算拒绝前零发送，以及跨重启不重复应用。实际供应商验收独立进行。

## 模块二：迁移注册表与运行资源安装

落实蓝图 14.3 和 R3 计划第 7 节的工程前置，使运行程序不再依赖当前源码目录。

- 用编译认可的版本、顺序、路径、大小和 hash 注册已发布 SQL；原 SQL 字节保持。
- 新资源对象捕获并校验 SQL、Schema、公共提示词及版本化 manifest；Schema 从已捕获
  原字节构造，避免验证路径后再读取另一份文件。
- 新 Store 注册表入口委托原迁移流程，保留逐步事务、单写者、旧构造接口和显式全库维护。
- 支持 CMake 安装和 DESTDIR staging，布局为 `bin` 与 `share/wls861`。
  运行资源不包含凭据、供应商端点或用户请求数据；安装后显式选择用户配置。
- 明确 `--resource-root`、兼容 `--source-root` 和相对可执行文件的默认发现；
  不根据当前工作目录或环境变量偷偷选择另一套运行资源。
- 默认公共提示词在冻结后与捕获资源核对；显式外部提示词仍属于独立用户配置。

验收包括普通用户真实 staging 安装、移走源码后从其他工作目录执行、资源缺失／
篡改／符号链接／特殊文件拒绝、清单版本和哈希错误、旧构造和迁移兼容。

## 单 Agent 完整对照的后续契约

现 v1 要求同一 Worker principal/team 的全部模型调用，而双任务 AMEND 的两个任务
在原 Store 中各自拥有团队及 Worker。完整对照需要区分逻辑模型 Agent 连续上下文
和 Store 权限 actor，并以新契约保存连续性和业务决定来源。

本轮不放宽 v1 身份规则、不重命名多个 Worker、不删除原调用，也不由宿主预造
第二个成果来填满样本位。后续独立设计该身份／上下文契约，真实质量对照仍等待
端点能力、认证引用、预算和明确调用授权。
