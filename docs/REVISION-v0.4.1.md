## 3. 当前实现与目标契约的分界

本批 C++ 仍采用现有 `TaskEngine` 与 Journal。它是受信宿主 API，没有新的
外部身份认证、模型网络请求、业务文件／进程工具或实际用户数据清理。
保留 Journal 格式，不把 SQLite 建表脚本当作已经完成存储迁移。

新增 Schema 和 SQLite/Python 参考以可执行方式检查模块间约定。它们可验证
字段、约束、事务 CAS、幂等与版本证据，但不代表已经实现 C++ Store、
RoleRunner、MemoryEngine、守护进程、MCP 或真实业务验收。

S1 继续从现有内核出发，先接配置、确定性模型替身、角色循环及工具接口。
首次真实调用需要明确的网关 profile、认证引用、模型能力和预算；本次示例
保持 FakeModel、记忆关闭、空真实预算，不进行自动付费重试。
