# WLS861 实施路线

更新日期：2026-10-17（Asia/Taipei）。当前状态：**M0 首批契约已落实，M1 合成内核通过本地严格构建与 UBSan 验证**。本路线描述当前边界、验收目标和后续依赖，不预报未经验证的工期、并发规模或缓存命中率。

当前实现依据 [M1-contract.md](implementation/M1-contract.md)；需求演变与历史覆盖关系见 [交接审阅](implementation/handoff-review.md)。原始设计包位于 `docs/handoff/v0.3/`，保持不改。执行结果另记入 `docs/reports/`，不能用原包 51 项拟定场景代替实际成绩。

## 1. 当前批次

M0/M1 的目标是先建立 Linux C++20 单机内核，以合成请求和模拟操作验证身份、版本、事件、恢复、调度和交付关口。首批实现已完成并经过实际验证，具体范围见 [M1 验证报告](reports/M1-validation.md)。

本批不引入第三方库依赖，采用 append-only Journal 保存原型状态和事件。Journal 不是 SQLite，也不决定生产存储方案。它面向有限测试数据，无压缩、生产保留、备份、加密或介质擦除承诺。Linux 文件接口独立封装，构建与测试入口为 `make test`。

有界调度器在状态锁外执行模拟回调，并区分审核/交接容量及共享资源键。工具操作只维护准备、派发、结果、未知和核对状态。没有真实模型调用、Shell 工具、MCP/A2A、记忆检索、生产交付回执或用户目录删除。

### M1 的验收目标

- 独立请求有独立且唯一有效的 Dispatcher；相同幂等键和内容不重复创建，同键内容冲突明确报错。
- AMEND 路由原请求，REPLACE 建立替代关系，NEW 不默认取消旧请求；目标与已应用要求分别可见。
- 状态和事件形成持久化事务；重启可重放；旧版本、旧租约和旧团队绑定不能继续派单或提交。
- Root、Dispatcher、TeamLead、Worker 的管理和执行权限受内核约束；模型和思考直接继承请求冻结的 Root 默认快照。
- 调度队列和槽位有限；不同请求和不同资源键可以独立推进；未知操作先核对，不盲目重试。
- 旧候选批准不能放行新候选；业务、合成交付和资源状态独立；清理失败不篡改业务结果。

这些目标验证的是内核及模拟边界。真实工具隔离、进程树回收、生产交付和数据清除必须在后续实现中单独验证。

## 2. 分阶段路线

阶段沿用 [v0.3 综合设计 §12](handoff/v0.3/01_最新设计/无量山_项目现状与综合设计_v0.3.md)，详细批次依据 [交接文档 §5—6](handoff/v0.3/02_交接与执行计划/项目交接文档_v0.3.md)。同一阶段中的未来选型须记录具体理由和约束，不能把建议当作历史已批准配置。

| 阶段 | 当前状态 | 主要目标 | 进入下一阶段所需证据 |
| --- | --- | --- | --- |
| M0 契约与政策边界 | 首批契约已落实，生产 Q 项保留未决 | 明确四角色、版本、身份、事件、状态和首批测试契约；列明生产未决项 | 文档、接口与实际实现能对应；测试配置与生产授权分开 |
| M1 无模型内核 | 合成内核已实现并通过本地验证 | 单机持久化 Journal、请求去重、唯一代次、显式变更、有界调度、模拟工具、版本化验收和资源状态 | 可重复 Linux 构建；并发、越权、陈旧结果、恢复、损坏、取消和交付关口的真实测试报告 |
| M2 基础执行闭环 | 后续批次 | 目标 Linux 的基础环境、Worker 文件/进程工具、隔离、异步输出、超时；一个明确选定模型链 | 同一授权边界覆盖文件、Shell 和后代进程；真实方向修改、成果转存、交接和安全回收；模型兼容证据 |
| M3 互调与工作流 | 后续批次 | AgentRegistry、InvocationService、固定流程与有限动态计划、候选触发审核、返工和并行汇合 | 跨功能经对方 Root；无越级控制和等待闭环；审核绑定当前版本；循环有界；用第三种功能模板验证通用性 |
| M4 记忆最小闭环 | 后续批次 | 记忆登记、明确 ID/基础搜索、工作记忆绑定、候选证据、验证发布、撤销和清除 | 可追溯用了什么及发布依据；跨域不泄露；撤销阻止后续相关操作；清理与获准知识交接一致 |
| M5 检索与演化 | 后续批次 | 根据评测选择混合检索、Wiki、条件化权重、冲突对照、合并归档和缓存优化 | 对照无记忆、固定 Skill、一次检索、分阶段检索；比较质量、总成本和耗时；实际缓存用量可核验 |
| M6 兼容与扩展 | 后续批次 | 按需求扩展端点、MCP/插件、Windows、记忆服务化或其他部署形态 | 每项声明有版本、部署范围和实测证据；不以一个“兼容模式”概括全部能力 |

M2 的工具契约和测试替身可先开发；真实执行必须具备相应环境与权限。M3/M4 的接口可在依赖阶段内预留，但不得因此提前宣布完整工作流或记忆引擎可用。

## 4. 每批次的完成定义

每批次必须提供源代码与版本、配置和契约、可重复构建方法、实际测试报告、已知缺陷、未实现能力和下一批接口。报告记录环境、命令、输入、观察和结果；需要关联原拟定矩阵时，注明覆盖的是整项还是某个模拟子集。

源码未实现、测试未执行、供应商不支持、缺授权无法测试和已知失败应分别说明。包 SHA 检查不能替代产品测试；通过 M1 不代表 M2 工具隔离、M3 工作流、M4 记忆、真实交付或严格删除已经通过。当前原始交接包中的 51 项“未执行”保持原样，新证据独立记录。

后续增加真实能力时，应先明确对应 Q 项和测试范围，再按已有任务、权限、版本和交付关口接入。不能为了完成某条演示路径而移除陈旧结果检查、独立审核或回执要求。
