## S1-01 仓库骨架、依赖与 CI

- **目标：** 可构建、可测试的空骨架。
- **规格：** 主规格第 16 节。
- **做：**
  - `CMakeLists.txt`（C++20）、`CMakePresets.json`（dev、release、asan 三个预设）、`vcpkg.json`（boost-asio、boost-beast、openssl、sqlite3（启用 FTS5）、nlohmann-json、yaml-cpp、spdlog、gtest，以及 S1-02 选定的 JSON Schema 校验库）。
  - 按第 16 节建好 `src/` 与 `tests/` 目录，各模块先放一个能编译的空文件。
  - `.clang-format`、`.gitignore`（忽略构建目录、*.db、secrets.env）。
  - `scripts/ci.sh`：configure → build → ctest；如果用 GitHub，再加一个跑这个脚本的 Actions 工作流。
  - `wlsd --version`、`wls --version` 输出版本号。
- **不做：** 任何业务逻辑。
- **验收：** Ubuntu 24.04 上 `scripts/ci.sh` 通过；asan 预设能构建；两个可执行文件输出版本号。

## S1-02 基础类型与存储层

- **目标：** ID、时间、Result、JSON 工具、Schema 校验、SQLite 封装与迁移、各表仓储。
- **规格：** 主规格 5.1、5.8、14.2；`db/schema.sql`；`schemas/README.md`。
- **做：**
  - ULID 生成（单调、线程安全）和带前缀的 ID 类型（req_、tsk_ 等）；UTC 时间工具。
  - `Result<T>`：预期内的失败（校验失败、版本冲突、工具失败）用返回值，程序错误用异常。
  - JSON Schema 校验封装：选定并接入一个支持 draft-07 的 C++ 库；能加载 `schemas/`；能从完整 Schema 去掉"运行时填写"字段，得到给模型的工具参数 Schema。
  - SQLite：一个写连接（串行）+ 只读连接池，打开时设置 WAL 等 PRAGMA；迁移（把 db/schema.sql 拆成迁移 1、2，S1 只执行 1）；事务封装；条件更新（CAS）辅助函数。
  - 各表仓储：requests、request_texts、plans、tasks、task_deps、change_orders、teams、events、artifacts、ops、questions、notes、llm_calls、receipts。
- **验收：**
  - 单元测试：CAS 冲突时返回"版本冲突"；events 的 command_id 重复被拒；删除请求时级联删除；迁移可重复执行。
  - `schemas/examples/` 全部通过校验；`schemas/README.md` 提到的反例全部被拒（把 Python 校验脚本里的反例移植成 C++ 测试）。

## S1-03 状态机、事件与消息路由

- **目标：** 请求、任务、团队三套状态机；事件总线；Root 接单与后续消息路由；额度与排队。
- **规格：** 主规格 5.2–5.8、5.10；02 第 2 节。
- **做：**
  - 三张状态转换表，非法转换返回错误。每次转换 = 同一事务里 CAS 更新 + 写事件；提交后按请求 strand 分发到内存事件总线。
  - Root 接单：格式与大小检查、idempotency_key 去重（内容哈希不同返回 409）、持久化原文、返回 RECEIVED。
  - 后续消息路由：AMEND（写原文、版本 +1、暂停该请求所有活动团队）、REPLACE、ANSWER、CANCEL、QUERY。
  - 额度：Dispatcher 与 Worker 名额、先进先出队列、为审核保留名额的开关（S2 才用到）。
  - 预算计数接口：供模型层登记用量，达到 80% 发 BUDGET_WARNING，用尽发 BUDGET_EXHAUSTED 并把请求置为 WAITING_INPUT。
- **验收：** V3-002、V3-003、V3-005、V3-006；非法状态转换测试；BUD-01 的计数部分。

## S1-04 配置、校验与继承解析

- **目标：** 加载 system.yaml 和功能模板目录，校验，解析每个角色的有效模型配置。
- **规格：** 主规格 8.2–8.4、13；`config/examples/`。
- **做：**
  - 读取 YAML（注意 `"off"` 要加引号的问题，读到布尔 false 时给出明确错误提示）。
  - 配置校验：引用存在、每个角色都能解析出模型、思考档位被模型支持、`dispatch: template` 的能力配置完整。
  - 继承解析（8.3），结果附带每个字段的来源。
  - 请求创建时冻结 config_snapshot；Agent 实例创建时冻结 EffectiveModelConfig。
  - `wls config check`、`wls config explain` 的后端函数。
- **验收：** V3-016、V3-017；缺少模型时报错；`config/examples/` 通过检查。

## S1-05 模型适配接口、HTTP/SSE 与 FakeModel

- **目标：** 统一的模型调用接口、可脚本化的 FakeModel、HTTPS + SSE 客户端。
- **规格：** 主规格 7.5、8.1、8.5。
- **做：**
  - ModelAdapter 接口和内部的消息、工具调用、用量结构。
  - Beast HTTPS 客户端：超时、TLS 校验、支持 `HTTPS_PROXY` 环境变量；SSE 解析器。
  - 重试策略：429、5xx、网络错误指数退避加抖动，最多 5 次；400 类不重试。
  - FakeModel：按 JSON 脚本（按角色和调用序号）返回文本或工具调用，可模拟延迟、错误和 usage。后续所有不连真实模型的测试都靠它。
  - 计量：写 llm_calls，供应商没给的用量记 NULL。
- **验收：** SSE 解析测试（分块到达、多行 data、带 id）；重试测试（429 后成功、400 不重试）；FakeModel 脚本测试；V3-026 的 NULL 语义测试。

## S1-06 沙箱与进程管理

- **目标：** 在 bwrap 沙箱里安全执行命令，按团队管理进程和资源。
- **规格：** 主规格 9.5–9.7、14.1。
- **做：**
  - 按 9.6 构造 bwrap 参数；用显式 envp 启动，不继承 wlsd 环境。
  - cgroup v2：检测委派是否可用；可用时为每个团队建子组、设 memory.max 和 pids.max、fork 后 exec 前写入 cgroup.procs、用 cgroup.kill 结束；不可用时退化为进程组 + 超时。
  - 操作生命周期：启动、输出落盘、前台等待与超时、后台运行、分页读取、取消（SIGTERM → 5 秒 → SIGKILL）。
  - 工作区目录的创建与删除（只按团队资源清单，不按路径前缀）。
  - error_signature 归一化函数。
  - `wls doctor` 的检查项：bwrap 是否安装、AppArmor 是否限制 user namespace、cgroup 委派、ripgrep。
  - 写 `docs/安装_Ubuntu24.04.md`：需要安装的软件包、bwrap 的 AppArmor 配置、systemd 用户服务的安装命令。
- **验收：** SBX-01、SEC-01、V3-020、V3-021、V3-022、V3-023；超时测试；network 为 none 时无法联网。

## S1-07 工具注册表与 Worker 工具

- **目标：** 所有角色工具的注册与权限检查；Worker 工具的实现。
- **规格：** 主规格 9.1–9.5；02 第 3.3、4.3、5.3 节。
- **做：**
  - ToolRegistry：按角色生成工具定义，按名称排序，参数 Schema 去掉运行时字段。
  - 统一检查链（9.3）：角色权限 → 代次 → 暂停与 applied_rev → 路径 → 网络 → 预算。
  - fs_list / fs_read / fs_write / fs_patch：openat2 约束、分页、expected_sha256、唯一匹配替换。fs_search：在沙箱里调用 `rg --json`。
  - run / op_status / op_output / op_cancel：调用 S1-06。
  - ask / progress / ack_change / submit / note：写库并发事件；submit 校验 Submission Schema；ack_change 更新 applied_rev。
  - Dispatcher 和 TeamLead 的管理工具：只定义参数 Schema，执行逻辑在 S1-10。
  - recall / load_memory：返回"记忆系统未启用"。
- **验收：** V3-001、V3-019；暂停期间工具调用被拒；applied_rev 落后时被拒；路径穿越和符号链接逃逸被拒。

## S1-08 上下文编排器

- **目标：** 按固定布局拼装上下文，支持两种模式、压缩、前缀指纹和环境卡片。
- **规格：** 主规格 7.1–7.5、9.8；02 第 8 节。
- **做：**
  - ContextCompiler：①–⑤ 的拼装；② 的各段顺序固定。
  - Worker 追加式：对话持久化到 transcripts/，可以从文件恢复。
  - Dispatcher / TeamLead 快照式：按 02 第 8 节的模板生成快照；决策日志取自 rationale。
  - 压缩：用到窗口 60% 时触发；摘要必须包含规定的字段，所有生效 ChangeOrder 的原文保留不压缩。
  - prefix_sha256 计算。
  - 环境卡片：读 env.yaml，在沙箱里执行检查命令，渲染成 Markdown 并缓存。
  - 在中间表示中标注缓存断点（7.4），由适配器编码。
- **验收：** V3-025、CTX-01、SNAP-01；缺失的 optional 工具在卡片中标注"未安装"。

## S1-09 Worker 运行器

- **目标：** 实现 Worker 的工作循环。
- **规格：** 02 第 5 节；主规格 4.2（停滞判定）、5.9（恢复）。
- **做：** 循环本体；暂停与等待回答时阻塞；工具调用按顺序执行；只有文字时提醒，连续 2 次触发停滞告警；submit 后等待结论；工具调用上限；压缩触发；崩溃后从 transcripts 恢复，并通知未知结果的操作。
- **验收（FakeModel 脚本）：** 正常完成并提交；收到 ChangeOrder 后先 ack 再继续，旧方向不再产生新操作（CHG-01 的 Worker 部分）；ask 阻塞直到收到回答；同一错误 3 次触发停滞；达到工具调用上限触发停滞。

## S1-10 TeamLead、Dispatcher 运行器与 Root

- **目标：** 两种管理角色的唤醒与工具执行，打通完整链路。
- **规格：** 02 第 2–4、6–8 节；主规格 4.2–4.4、5.7、6.1–6.2。
- **做：**
  - 唤醒表与事件合并；快照生成。
  - Dispatcher 工具的执行逻辑：submit_plan（校验无环、模板、逐字摘录、额度）、change_task、accept_task、cancel_task、answer_team、ask_user、read_artifact、deliver（调用 S1-11）、fail_request。
  - TeamLead 工具的执行逻辑：issue_work_order（约束覆盖检查）、issue_change（parent_change_id 与覆盖检查）、answer_worker、escalate、read_workspace、forward_submission、return_for_rework（团队内 3 轮上限）、write_experience_report（S1 只存进交付包）。
  - AMEND 后本轮结束时自动恢复未处理的暂停任务；事件未处理时再唤醒一次。
  - 问题上报协议（02 第 6 节），答案原文直达提问者。
  - 验收时把成果复制到成果区，成为不可变成果。
- **验收：** E2E-S1 的 FakeModel 版本；CHG-01；Q-01；HOP-01 的程序部分（丢约束的消息被拒）；V3-004。

## S1-12 守护进程、本地 API 与 CLI

- **目标：** 可以日常使用的 wlsd 和 wls。
- **规格：** 主规格 12.1、12.2、5.9；`packaging/systemd/wlsd.service`。
- **做：**
  - wlsd 启动流程：配置检查 → 数据库迁移 → 崩溃恢复 → 监听套接字（权限 0600）。

- **验收：** FakeModel 下的 CLI 端到端脚本：submit → watch → amend → answer → deliveries open → ls 显示已清理；SSE 断线续传；套接字权限为 0600。

## S1-13 真实模型适配器（需先定 P-01）

- **目标：** 接入你选定的供应商。
- **规格：** 主规格 7.4、8。
