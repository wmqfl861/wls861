# 统一记忆引擎规格｜v0.3 草案

**WLS-MEM-SPEC-001 · 2026-10-17 · 设计提案，未实现**

本规格基于 T13—T20。用户已确认统一记忆与演化方向；模块内置/服务化、字段名、阈值和具体存储仍为建议。与原 Agent 内核共同工作，不新增指挥层，不替代 TaskEngine、ToolRegistry 和 PolicyEngine。

## 1. 设计目标与不变量

知识从候选到正式可追踪，从检索到实际使用有证据，从错误到撤销能传播，从任务交付到清理不越界。事实、经历、规则、程序性 Skill 与成果引用统一登记，但分类型处理。

强制规则不依赖检索偶然命中；搜索排名不等于可信度；加载不等于使用；使用不等于导致成功；归档不等于删除；自动提炼不等于授权发布；新方法不是天然优于旧方法。

一条结论应能在自己的适用范围内验证、修订和撤销。完整 Skill 主说明、脚本与资源形成版本包，不把搜索片段直接当完整程序。

## 2. 正式对象与关系

| 对象 | 职责 |
| --- | --- |
| MemoryRecord | 稳定身份、类型、内容版本、标签、范围、来源、状态 |
| Applicability | 输入/输出、项目、环境、工具版本、前置条件与不适用条件 |
| EvidenceRecord | 可去重的观察或验证，关联准确方法版本和任务步骤 |
| MemoryProposal | 新内容、修订、合并、范围提升或归档的候选申请 |
| ApprovalRecord | 授权主体、策略版本、内容校验值、范围、有效期与证据 |
| Relation | 支持、矛盾、依赖、替代、源自、警示、合并自等有向关系 |
| WorkingMemoryBinding | 哪个请求/角色在什么阶段绑定了哪些版本与限制 |
| DerivedArtifact | Wiki、摘要、向量与缓存的来源依赖和重建状态 |

建议标识 memory_id 不变，revision 不可变，content_hash 校验内容。修改生成新 revision；统计与正文分表管理。并发补丁携带 expected_revision，冲突时保留两份提案而不覆盖。

## 3. 标签、条件与作用范围

可生成的内容标签只用于检索与展示。工具版本范围、OS、输入格式、权限、发布状态、项目范围等必须有可校验结构，不让自由标签承担授权。

来源字段由运行时补充：自行观察、第三方导入、用户规则、已发布修订、模型归纳等分别记录。观察时间、记录时间、验证时间、有效期间和工具环境不同；易变知识按失效条件重新核对，稳定知识不按年龄盲目降权。

权限范围覆盖名称、摘要、片段、Wiki 和证据，查询前即过滤；不能先泄露内容再在执行时拒绝。项目资料不能因“通用”标签被提升到全局。

## 4. 导入与生成

下载 Skill：保存原包和来源→解析元数据→内容/脚本/依赖检查→标记未知条件→登记候选→按政策验证发布。不能直接执行未审查脚本；工具安装与依赖审批不是导入操作的隐含授权。

自产经验：Worker 留真实观察→TeamLead 交接报告→候选记忆或 Skill 补丁→Dispatcher 查重归类→必要验证→发布申请。可报告无新增经验；一段失败记录不能被模型洗成通用原因。

优先更新正确的位置：工具入口/契约问题修 ToolRegistry/Adapter；环境问题修配置；稳定方法进入 Skill；仅有局部参考价值的保留在对应经验范围。完全确定性步骤可以封装工具或工作流。

## 5. 生命周期与发布

建议状态：CANDIDATE → UNDER_REVIEW → VALIDATING → PUBLISHED。需要补充时 NEEDS_EVIDENCE；拒绝为 REJECTED；正式内容可 SUPERSEDED/ARCHIVED；危险内容 SUSPENDED/REVOKED；最终删除 PURGE_PENDING→PURGED。

这些不是一条线性必经链：简单事实核对可少走步骤，风险项目要求更强验证。发布前必须同时满足：所需验证足够、允许保留、发布范围批准、内容与批准绑定一致、依赖可用、无阻断冲突。任何关键修订不能借用旧内容批准。

团队能提交提案，不直接改公共正式库。PolicyEngine 或受托审批者提供授权，发布模块执行有版本检查的变更。审批记录必须与身份绑定，不能来自模型自报“管理员已批准”。

## 6. 检索与激活

建议先走明确 ID/任务绑定，再在可见正式域中进行关键词＋语义＋标签/关系检索，返回少量候选卡片。分类树是导航与排序依据，不强制每层一次模型判断；大类不无界加载全部 description。

卡片包括名称、简介、场景、负例、版本、工具依赖、验证范围、风险和不可用原因。实际加载准确 revision，再展开必需规则/依赖/严重警示。无法满足前置条件先询问或核对，禁止截掉条件继续执行。

复杂选型调用模型，但模型仅推荐 ID/版本/条件/理由，不自动成为执行器。无适用记忆可返回缺口。显式安全撤销、权限变化和来源删除优先于缓存。

动作接口分离：search 找候选，resolve 读准确内容，prepare_activation 查依赖与许可，bind 将授权结果登记到工作记忆。命名与签名为草案。发生不可用时不伪造“已激活”。

## 7. 分阶段工作记忆

阶段进入时注入必要规则、选中方法、约束和少量经验；执行中只对新问题追加检索。控制阶段、预算、已用版本、未决问题和结果引用，避免每轮重写全库摘要。

工作记忆的当前事实与任务状态链接，不能用旧案例覆盖现在。压缩和恢复后保留有效方法及负面条件；运行中的任务默认绑定版本。普通升级由新任务采用或显式迁移，安全撤销触发暂停/重选。

Root 只读取外部沟通所需信息；Dispatcher 做请求级选择；TeamLead 明确团队方法；Worker 读取执行所需内容。跨角色只传必要引用，不复制全部私有历史。

## 8. 证据与使用归因

EvidenceRecord 建议包含 evidence_id、source_run_id、task_id、operation_id、memory_id/revision、role/model/config、输入/环境摘要、观察事实、推断、结果、验收主体、artifact_refs、独立性分组与时间。

事件链：RETRIEVED、LOADED、SELECTED、LINKED_TO_OPERATION、OBSERVED、VERIFIED。系统不得按全部加载内容批量加分，也不把一份日志经多个团队总结视作独立验证。

失败分类至少有 METHOD_FAILURE、WRONG_SELECTION、EXECUTION_DEVIATION、ENVIRONMENT_FAILURE、UNKNOWN。自述成功不等于验收；无法归因时保留不确定性。记录方法实际使用并不自动证明因果效果。

对照测试覆盖代表性与边界任务，隔离上下文与工作区，避免泄露测试答案。不同模型、思考和工具配置的结果必要时分桶，不盲目跨条件累加。

## 9. 权重与多方案竞争

不采用单一“使用次数分”。建议区分执行推荐、证据可靠、风险警示和时效适配。先做权限/状态/适用性硬门槛，再按任务质量标准、证据、成本和资源比较。

热门不等于正确；未选择不计失败；同一证据不重复加权。失败方法可降低执行推荐但增加警示权重。归档前考察覆盖、重复独立证据、反例和风险，不预设连续 N 次适用于所有知识。

探索只在预算和风险允许的测试环境安排；不能为收集数据拿生产副作用随机试验。阈值、置信表达、统计模型或 bandit 是否采用均待评测，不在本稿定死公式。

## 10. 冲突、合并与归档

条件不同的方法并存并补标签/条件；目标取舍用任务目标选择；同条件相反结论登记冲突等待验证。新内容不自动获胜，旧内容不因旧就无效。

合并生成新 revision 或新的选型记忆，保留来源关系和有效分支；矛盾部分不直接同时执行。脚本和资源也要检查。旧版本成绩作为源证据，不变成新版本已通过的验证。

归档退出默认候选，保留获准追溯资料；提炼仍有效的失败警示。REVOKED 内容默认不得复活，恢复要重新经过授权和验证。未授权长期保留的原任务材料不能借归档留存。

## 11. 撤销、派生依赖与清除

正式状态变化生成有编号的事件，跟踪依赖于此内容的 Skill、Wiki、索引、缓存和活动绑定。查询结果可以暂时旧，但激活和关键执行前再次查正式状态。普通升级与安全撤销分开。

记忆或证据删除可能使派生结论失去依据；需重新核验、缩小范围或撤销。不能保留一段脱离已删唯一依据的“已验证”结论而没有声明。

清除计划覆盖正文、Skill 包、向量、索引、Wiki、缓存、日志、快照、备份和恢复路径。删除回执本身是否保留也须配置。远端不可保证删除的副本必须在策略中说明。未批准沉淀的候选交付后导出或清除，不自动进入长期库。

## 12. 安全与故障

候选提炼不能提升来源信任；第三方指令不升级成宿主规则。秘密、私人资料、提示注入、可疑网络访问和依赖链必须检查，审查通过不声称绝对安全。读取文件名/元数据同样可能泄露，权限覆盖全部输出。

索引故障可在授权内退回精确/关键词；没有可选经验允许受控探索；必需方法/权限/撤销状态无法确认时阻止相关动作。提炼失败记录状态不谎报发布。队列、回调和证据提交均有幂等与版本约束。

## 13. 引擎与宿主接口（建议）

MemoryEngine 可提供 capabilities、search、resolve、propose、record_evidence、publish、supersede、archive、revoke、changes、export、purge。每个写操作带身份上下文、幂等键和预期版本；命令返回结果/待处理编号，而不是任意开放数据库写入。

MemoryBridge 负责从宿主获取授权身份和任务阶段、登记激活/使用、接收撤销、提交候选、确认知识交接后再释放原材料。接口可以先同进程，后改 IPC/HTTP，业务语义不变。

工作流与验收的真实状态仍属宿主。记忆引擎只能提出验证需求；实际团队、工具权限和预算由宿主决定。模型提炼复用 ModelAdapter；EmbeddingAdapter 独立记录模型/维度/索引版本，变更需重建或迁移。

## 14. 部署、指标与未决选择

建议首版可独立构建测试的 memory_core＋MemoryBridge，同一 Linux 部署包内运行；独立进程/服务作为后续能力。此路线尚待用户确认，非强制插件，也不要求现在使用分布式向量库。

指标：候选召回/适用性、错误激活、无匹配处理、重复查找、实际使用归因覆盖、验证通过/反例、合格任务总费用/时间、撤销传播、删除残留、跨域泄露。测试分别比较无记忆、固定 Skill、单次检索、阶段检索等基线。

待定：记忆后端、向量模型、中文检索、评分规则、发布授权、跨项目范围、保留与归档期限、验证预算/覆盖阈值、管理界面、服务化时点和性能目标。任何数值例子不构成生产默认。

## 15. 最小可验收闭环

一个团队提炼候选→登记来源与范围→验证发布→另一个任务找到准确版本并使用→结果登记到真实操作→发现反例→修订/暂停→已有绑定收到变化→不再执行旧方法→请求与记忆按明确授权分别交付、归档或清除。

该闭环及附件中的用例均为拟定，当前未执行。
