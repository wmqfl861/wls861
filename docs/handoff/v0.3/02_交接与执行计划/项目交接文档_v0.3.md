## 1. 不可退回的设计方向

四角色为 Root → Dispatcher → TeamLead → Worker。Root 是功能级稳定入口，只处理外部沟通；每独立请求有自己的 Dispatcher，承担规划、协调、变更、验收，可并行管理多个 TeamLead＋Worker 团队。只有 Worker 执行业务操作，管理与资源回收由运行时受控完成。

独立请求与后续消息区分；任务、计划、执行应用和状态版本区分；旧结果不能覆盖新要求。不同请求并行、同一对象状态提交有序。不能因为逻辑主身份固定就让所有规划共用一个串行模型会话。

模型与思考等级独立设置，未设字段直接继承所属 Root。工具权限按角色和任务决定，不套用模型继承。端点、工具与协议兼容按能力登记，不能声称支持所有供应商全部特性。

工作流和互调用同一任务内核。跨 Agent 通过对方 Root，不能指挥对方 Worker。固定外层审核与交付，内部允许有限动态计划。候选成果触发审核；审核不通过报告仍可完成审核任务。

通用基础包一次准备、版本固定、团队私有空间、统一接口和执行边界。不要把主机 Shell 默认开放给所有角色，也不要每个团队重复安装相同基础环境。

知识统一为类型化记忆，所有自产或下载内容带标签/来源/条件；Wiki＋RAG 随阶段激活；强制规则确定性生效。经验和 Skill 的生成借鉴 Hermes，交接报告可附候选补丁，正式发布要有验证与授权。

方法冲突先并存比较，按实际证据和场景调整推荐；多次验证再整合、归档。不得按热度当正确，合并新方法须重新验证。更新证据不必重写正文，方法版本不可无声改写。

## 2. 哪些仍是建议，而不是已批准配置

MemoryEngine 独立开发、MemoryBridge 深度接入、首版同进程内置而后服务化，是最后一轮的推荐路线，尚待确认部署取舍。浅分类/常用入口/混合检索也是建议组合，数据库、向量模型、分类深度和排序参数未确定。

运行时基本准入、两类清除政策、回执窗口、权限审批边界、经验预授权、独立验证等级与团队提前回收都要形成明确政策。用户要求低延迟和删除记录，不等于授权无限进程、不鉴权、永久保存或自动全局发布。

**不得把打包请求当成“所有建议已批准”，也不得因为本文是交接稿就声称已经实现。**

## 5. 推荐接续实施批次

**第一批：状态与契约，不先造庞大记忆库。** 建立源码仓库、C++ 构建、核心数据模型、事件信封、请求去重、调度唯一代次与状态条件更新。以不调用模型的模拟执行验证并发请求、变更路由、恢复与取消。源码和构建命令从这一批开始产生，本包没有预先生成假仓库。

**第二批：基础工具闭环。** 在目标 Linux 验证环境包、Worker 文件/进程工具、目录与身份隔离、异步输出、超时和清理。用一个明确选定端点跑接单—规划—团队执行—候选—验收—交付。未配置真实授权前只用测试文件和受控对象。

**第三批：互调与工作流。** 实现 AgentRegistry、InvocationService 和有界流程，验证开发/Review 只是通用性样例；再以不同功能模板证明不写死业务。并行、返工、失败、过期结果、审核证据和资源汇合须有测试。

**第四批：记忆最小闭环。** 实现登记、明确 ID/基础搜索、工作记忆绑定、证据、验证发布、撤销与清除。先证明“用了什么、凭什么发布、错了能停用”，再引入复杂 Wiki 和向量排序。

**第五批：演化与性能。** 加入分类/向量/关系融合、复杂选型、冲突对照、条件化权重、合并归档；与无记忆和固定 Skill 对照。供应商缓存以实际用量核验，不能只凭文本前缀相同宣称命中。

## 6. 开发完成定义

每批次交付应包含源代码/版本、配置说明、变更记录、可重复构建方式、实际运行的测试报告、已知缺陷和验收证据。未执行测试写“未执行”，不能把本文拟定用例编号当作通过记录。

高风险操作遵循审批和测试环境；版本状态提交和工具执行两处都检查权限。文档、配置、Schema 与实现有对应版本，不用说明文档掩盖接口差异。接手开发者不得从其他项目复制测试成绩作为本项目结果。

## 7. 最大风险与处理原则

任务并发风险靠唯一代次、版本和去重；副作用风险靠核对与幂等；知识污染风险靠来源/候选隔离/受控发布；旧知识风险靠撤销传播和最终激活检查；清理风险靠明确交付回执、正式知识交接和派生删除；性能风险靠预算、阶段检索与基线测试。

不能兼得的承诺须说明：零记录之后没有无限历史去重；有限验证不证明所有场景正确；本地删除不保证远端副本消失；高语义相似不表示方法适用；更多 Agent 不保证线性加速。



## 8. 接手后不要重复犯的理解错误

不要恢复旧三层并让 Root 包办所有内部工作。不要限制系统只有两个 Agent。不要让所有模型配置沿父层继承。不要把普通外挂搜索当成深度记忆接入。不要把 Skill 安装当成已授权可执行。不要把经验写入、业务验收和知识发布三个动作混为一谈。不要把归档当删除，也不要把所有未采纳方法算失败。

首版不需要为了“通用”安装全部软件，不需要为了“智能记忆”先建设分布式集群，更不需要为了提高缓存把失效指令永远留在上下文。
